# 第 8 章　模型後訓練

> 《深入理解 AI Agent》— 李博杰，第八章

## 1. 本章定位

核心公式 **Agent = LLM + 上下文 + 工具**；本章聚焦 LLM 這個「大腦」：先用 **Mid-training** 補領域知識與基礎能力，再用 **SFT、RL** 塑造模型使用上下文與工具的方式。第七章結尾的兩塊基石：**評估環境提供練習場，評估指標定義訓練目標**。

本章面向沒有 RL 或訓練背景的讀者——從「一個模型是怎麼被訓練出來的」講起。

### 1.1 能力開發的四個部分

| 階段 | 類比 | 資料 | 最佳化目標 | 學到什麼 | 典型代價 |
|---|---|---|---|---|---|
| **預訓練** | 通識教育（讀完圖書館所有書） | 海量原始網路文字 | 預測下一個詞 | 語言規律、世界知識、基本推理 | 極高（數百萬～數千萬美元） |
| **Mid-training**（CPT/DAPT/TAPT） | 集中研讀專業教材 | 目標語言／領域／能力語料 + 保留資料 | 繼續預測下一個詞（通常全 token 算損失） | 補領域知識、語言與基礎能力缺口 | 中到高 |
| **SFT** | 老師示範解題與表達規範 | 幾千～幾萬條「輸入—輸出」示範 | 預測下一個詞（**只在回答上算損失**） | 指令遵循、格式、風格、流程協定 | 低（幾小時～幾天） |
| **RL** | 自己做題、依結果反覆改進 | 任務、環境 + 獎勵訊號 | **最大化期望獎勵** | 可遷移的決策策略、探索出的新解法 | 高（常是 SFT 的幾十～上百倍） |

### 1.2 兩條貫穿主線

1. **在本章的對照實驗中，SFT 更容易記住示範，RL 表現出更好的泛化。**（GeneralPoints、V-IRL 在相同任務、模型、預算下的結果——**特定條件下的結論，不是普遍屬性**。）
2. **資料和環境比演算法更重要。** 工業界最反直覺、最值錢的經驗：PPO、GRPO 會用就夠了，決定成敗的是**模擬環境**的真實度與**訓練資料**的品質；很多場景 SFT 資料到位就根本不需要 RL。

> 閱讀路徑：Agent 應用開發者讀四階段全景 → 跳過兩節 `[可選閱讀]` → 從 Mid-training 繼續；模型訓練工程師全部順讀。

## 2. 四階段的機制 ⭐⭐⭐

### 2.1 預訓練：預測下一個詞（NTP）

- 輸入「中國的首都是」，模型給「北京」高機率；預測與真實 token 的差距（**損失**）越大，參數調整越用力。在幾兆 token 上反覆做——**沒有捷徑，只能真正消化文字裡的規律**。
- ⭐ **模型的輸出本質上是一個機率分布**；訓練 = 調整分布。四個部分的差別在於「想要什麼」以及用什麼訊號定義它。
- 預訓練後博學卻不好用：問它問題，它可能續寫更多問題（網路上一個問題後面常跟著另一個問題）——還沒學會「被提問時應該回答」的協定。

### 2.2 Mid-training：在目標分布上繼續學習

- 通用預訓練不可能覆蓋所有語言、領域、能力。模型讀不懂某語言、不懂企業內部協定、沒形成目標任務需要的程式碼與長上下文表徵 → **直接教「怎麼回答」或只按成敗給獎懲，補不上這些基礎能力**。
- 保留下一 token 目標，但把資料收窄到目標領域 + 混入通用保留資料控制遺忘。回答的是「**是否具備完成任務所需的知識與基礎能力**」，而不是「回答長什麼樣」或「哪種策略獎勵最高」。
- **Mid-training vs. SFT 的知識注入**：Mid-training 把完整文件、程式碼、推導都當學習目標、在大量 token 上算損失；SFT 只在回答 token 上算損失。小型問答 SFT 能記住少量事實，但**只強化幾條存取路徑**。龐大、互相關聯、相對穩定的領域知識 → Mid-training；需要持續更新、可追溯的知識 → **RAG**。

### 2.3 SFT：換了資料的「預測下一個詞」

> ⭐ **SFT 在數學上和預訓練是同一個任務**——預測下一個詞、最小化同一個損失函式。差別只有兩點：

1. **資料不同**：人工精心準備的「使用者提問 → 理想回答」。
2. **損失只算在回答上（loss masking）**：把問題部分的 token 遮蔽，只對回答回傳梯度——工程上唯一實質性的區別。

- 為什麼 SFT 有記憶傾向？目標是**讓標註回答裡每一個 token 的機率盡可能高** = 盡量復現示範。目標明確、格式固定時極高效（幾千條見效）；覆蓋與多樣性不足時會對表面模式或捷徑過擬合。
- **一句話**：用極高的樣本效率，把一套穩定的「輸入 → 輸出」對映與協定固化進參數——固化的是**協定性知識**（該怎麼說、怎麼做），而非大量**事實性知識**（知道什麼）。

**LoRA（Low-Rank Adaptation）——貫穿全章的工程預設**：
- 不動原大權重矩陣，只在旁掛一個低秩「補丁」，參數量約原始的 **1%–5%**，接近全參效果；原權重凍結 → 災難性遺忘風險更低。
- 經驗（Schulman & Thinking Machines Lab「LoRA Without Regret」）：
  - **必須**應用到所有主要權重矩陣（尤其參數佔比最大的 **MLP 層**），只加在注意力層會掉點；
  - **最佳學習率約為全參微調的 10 倍**（SFT、RL 都成立）；
  - SFT 用中高 rank（**64–256**）；RL 每輪資訊量很小，小 rank（**8–32**）甚至 **rank = 1** 就夠；
  - 一臺推理伺服器可同時載入多個 adapter 做多租戶服務。

### 2.4 什麼時候需要先補底座，再做 SFT／RL

RL 用獎勵評估模型**自己生成**的回答。兩個前提：

| 前提 | 內容 | 不滿足時 |
|---|---|---|
| **格式支援** | 輸出能被驗證（JSON、工具呼叫能解析） | 獎勵函式連成敗都判斷不了 → 先用 SFT「把話說利索」 = 常見的「**先 SFT、後 RL**」 |
| **能力支援** | 當前策略**偶爾能探索到有價值的行為** | 見下 |

**用 pass@k 診斷能力支援**（在留出任務上，以與訓練相近的溫度取樣）：

```
pass@k ≈ 1 − (1 − p)^k

pass@1 低，但 pass@k 隨 k 明顯上升 → 正確策略已在模型分布裡，只是機率質量小
                                      → RL、拒絕取樣、蒸餾都有東西可放大
合理 k、溫度、覆蓋下 pass@k 仍近 0  → 基礎模型幾乎生成不出成功軌跡
                                      → GRPO 一組 rollout 全為 0，組內優勢消失；
                                        PPO 看不到正向樣本；放大取樣只能以 ~1/p 速度等偶然成功
```

**先問缺的是什麼**：
- 缺領域語言、事實、程式碼模式、長上下文基礎 → **Mid-training**；
- 有能力但不會按介面表達 → **SFT**；
- 能局部前進但到不了終點 → **可驗證的部分獎勵或課程學習**。

> **RL 擅長把「已有但機率較低」的成功行為推高，不擅長從全零獎勵中憑空創造模型從未學過的知識和能力。**

**邊界**：「必須先 SFT」只在格式或基本行為未建立時成立。Llama-3.2-Vision-11B 在嚴格結構化輸出下不經 SFT 直接 RL 會失敗（實驗 8-11）；但**足夠強、已有非零成功率的基模可以跳過 SFT**——**DeepSeek-R1-Zero**；它後來加的冷啟動 SFT 主要是改善**可讀性與語言一致性**，不是注入任務知識。

### 2.5 SFT 與 RL 的本質區別

| 維度 | SFT | RL |
|---|---|---|
| 最佳化目標 | 最大化標註答案機率（極大似然） | 最大化期望獎勵 |
| 訓練訊號 | 標註回答的逐 token 監督 | 策略生成的回答/軌跡 + 結果或步驟級純量獎勵 |
| 資料形態 | 「輸入—輸出」示範對 | 任務、環境 + 獎勵（參考答案可選） |
| 直接最佳化壓力 | 模仿示範中的對映與協定 | 強化能獲得獎勵的行為與策略 |
| 分佈漂移下 | 取決於示範覆蓋與正則化；本章有限示範實驗出現過擬合 | 取決於獎勵、環境、探索；本章實驗遷移更好 |
| 樣本效率 | 高 | 低（SFT 的幾十～上百倍） |
| 穩定性 | 高、收斂快 | 低、易震盪 |
| 最適合 | 固化格式/風格/流程、有高品質示範、環境穩定 | 泛化到新場景、探索最佳策略、標註成本過高 |

- GeneralPoints 例：有限示範把 J/Q/K 都當 10 → 測試值變化時崩；RL 學到「重新計算直到正確」→ OOD 更好。反之，**獎勵或環境有偏時 RL 同樣可能對捷徑過擬合**。
- **機率分佈視角**：一個問題常有多類合理回答（多個「峰」）。
  - 極大似然 SFT → **mass-covering（覆蓋式）**：盡量覆蓋訓練資料中出現過的多個模式；
  - RL + 常見的反向 KL 約束 → **mode-seeking（尋峰）**：把機率集中到少數高獎勵峰。
  - 最終多樣性還取決於示範分佈、獎勵、KL 方向與係數、熵正則、取樣溫度。

**後訓練還會塑造「何時行動」**（呼應第五章 §4.2、第七章實驗 7-9）：GPT 系列與 Claude 系列常有不同的預設行動閾值——這不是擬人化的「謹慎」或「直覺」，而是參數中的策略在估計「**多讀一個檔案的預期價值，是否高於提交當前補丁並驗證的預期價值**」。SFT 示範若反覆是廣泛調查後才編輯 → 模仿較高閾值；RL 獎勵若持續認可快速定位、儘早進入可驗證迴圈 → 機率質量向較早行動集中。（廠商不公開配方，實驗只能證明模型側差異，不能斷言是哪種私有演算法造成。）

**線上回饋提供的三個機會**：
1. **可以評估固定示範之外的候選**：SimpleVLA-RL 的「**推切**」動作從未出現在人類示範中。但獎勵識別不了的品質學不到，探索不到的策略也發現不了。
2. **可以利用「驗證比生成容易」**：SFT 要先寫出正確答案；RL 只要可靠地判斷品質（數學對照、程式碼測試、定理驗證器）——RLVR 的優勢；驗證器不完整則導致獎勵駭客。
3. **可以在當前策略實際訪問的狀態上訓練**：離線模仿有**協變數漂移**——偏離示範後進入沒見過的狀態、缺乏恢復訊號；在特定序列模仿學習設定中誤差最壞可隨軌跡長度 T 按約 **T²** 累積，線上資料聚合可降到約 **T**。

> **SFT 細緻學習已有地圖；RL 拿著獎勵這枚指南針探索地圖外的候選路線。地圖或指南針不準都會迷路。**

## 3. 從經典 RL Agent 到現代 Agent `[可選閱讀]` ⭐

### 3.1 RL 基本概念

- 目標：最大化**累積獎勵**；互動產生**軌跡**（狀態 → 動作 → 獎勵 → 新狀態 …）。
- **價值函式**：「按當前策略一直行動下去，總共能拿多少獎勵？」——像棋手憑直覺估勝率。
- Agent 與環境的邊界：**凡是 Agent 無法任意改變的，都屬於環境。**
- 兩個獨特特徵：**試錯搜尋**、**延遲獎勵** → **探索與利用權衡**。
- 五要素：動作空間（離散/連續）、策略、獎勵訊號（長期而非即時）、價值函式（過去六十年 RL 最重要的認識之一）、環境模型（可選；有 → 基於模型，無 → 無模型）。

**表 8-3　不同 Agent 系統**

| Agent | 環境 | 動作空間 | 獎勵 |
|---|---|---|---|
| 新生小羚羊 | 地形、重力、身體姿態 | 連續高維（各肌肉群收縮） | 平衡 +、跌倒 − |
| 掃地機器人 | 房間佈局、電量 | 離散（方向、吸塵、充電） | 清潔面積 +、電量耗盡 − |
| 西洋棋大師 | 棋盤、時間限制 | 離散有限（合法走法） | 贏 +1、輸 −1 |
| 客服 Agent | 對話歷史、知識庫 | **變長組合式**（思考、說話、API） | 解決 +、處理時間 − |
| 程式碼助手 | 需求、程式碼庫 | **變長組合式**（思考、搜尋、編輯、執行） | 測試通過 +、引入 bug − |

### 3.2 MDP 與 Q-learning

- **MDP**：馬可夫性質——未來只取決於當前狀態，而**當前狀態必須包含決策所需的全部歷史**（西洋棋的狀態不只棋子位置，還有輪到誰、王車易位權、吃過路兵權、五十步規則與重複局面資訊）。
- **貝爾曼方程**：一個動作的真實價值 = 這一步的即時獎勵 + 到達下一狀態後的最大未來價值：

```
Q*(s, a) = r + γ · max_{a'} Q*(s', a')      （隨機環境下對 s' 取期望）
γ ∈ [0, 1)：折扣因子，越接近 1 越重視長期；累積獎勵 = Σ_t γ^t · r_t
```

- **時序差分學習（TD）**：每次行動後把舊估計往實際結果方向微調一點。
- Q-learning 是 **off-policy**：可用不同於目標策略的探索資料學最佳策略，但仍要求充分覆蓋相關狀態—動作對並滿足學習率條件。

> **實驗 8-1 ★ Q-learning 尋寶遊戲**（隱藏機制：鑰匙—門、武器效果、物品合成；最佳解 11 步；稀疏獎勵；ε-貪婪）
>
> | episodes | 表現 |
> |---|---|
> | 前 1000 | 0% 勝率，Q 表 124 個狀態，盲目探索 |
> | 前 5000 | 仍無穩定勝利，133 個狀態 |
> | 7000–8000 | 勝率 34% → 96% |
> | 10000 | 100%，145 個狀態，找到 11 步最佳解 |
>
> 不到 10 秒，但需近 **10000 次完整嘗試**。真實世界（打電話有成本、瀏覽器有延遲、錯誤可能不可逆）不可接受 → 用預訓練 LLM 策略的原因之一：**用已有知識在更少互動中做出有效決策**。侷限（無先驗表格 Q-learning）：樣本效率低、難遷移、每個新任務重新探索——不是 MDP 框架本身的限制。

### 3.3 LLM 策略：思考 token 是特殊動作

- 經典 RL 也能把內部計算建模為動作；LLM 的實用變化是**預訓練語言策略能用變長 token 序列表示內部計算，並與外部行動由同一策略生成**。思考 token 不直接改變世界，卻能提高最終行動品質 → 動作表示包括「做什麼」與「**想多久、想什麼**」。
- 變長組合式動作搜尋空間巨大，從零學像「蒙眼在沙漠找寶藏」；**預訓練給結構化路徑更高先驗機率**（「識別條件 → 回憶公式 → 逐步計算」），即使沒有 RL 也能生成基本 CoT。
- 語言結構不是單獨的「內部獎勵」，而是預訓練策略的**先驗分佈**：「要換算貨幣，所以先查匯率」機率高，「所以先查天氣」機率低；RL 在這個初始分佈上用任務獎勵重新調整。
- OpenVLA 本身是在近百萬條機器人示範上**模仿學習**（SFT 性質）；真正把 RL 引入 VLA 的是 SimpleVLA-RL（實驗 8-13）。

**姚順雨《The Second Half》的三階段**：
1. **2015–2016 演算法中心主義**：Atari 有進展，換環境就從頭訓練；
2. **2016–2018 環境的重要性**：Gym、Universe、World of Bits、Dota 2；通用電腦使用與網頁導航始終無法突破；
3. **2018 至今先驗的覺醒**：GPT-2/3、WebGPT、ChatGPT。**先驗知識可以透過與 RL 完全無關的方式獲得**。

> **不是「演算法 > 環境 > 先驗」，而是「先驗 > 環境 > 演算法」。**

> **實驗 8-2 ★★ 傳統 RL vs. LLM Agent**（同一尋寶遊戲；Kimi K3，最多 50 條經驗緩衝）
> - **LLM Agent 第一局 18 步通關**：拿生鏽的劍（「武器總比空手好」）→ 發現北門鎖了推理「需要找鑰匙」→ 取得紅鑰匙與魔法水晶 → 預判生鏽的劍對付不了守衛，**第 8 步主動合成銀劍** → 第 13 步擊敗強守衛 → 第 18 步取得巨龍寶藏。
> - LLM 理解遊戲的**概念結構**；對 Q-learning，「門」「鑰匙」「劍」只是無意義的符號組合。
> - **計算成本悖論**：Q-learning 10000 局 10 秒，LLM 一局 1–2 分鐘；但現實互動的時間、金錢、風險成本遠超純計算。LLM 的成功**不是因為更好的學習演算法，而是攜帶了海量先驗**；規則變了，Q-learning 要重訓，LLM 可直接推理適應。
> - 原則：模擬成本低、可大量重複 → 傳統 RL 仍有價值；互動成本高、需快速適應 → LLM 的樣本效率更實際。

## 4. 模型預訓練基礎 `[可選閱讀]` ⭐

流程：**詞元化 → 預訓練 → 後訓練**。後訓練是在預訓練建立的表徵空間內最佳化——**預訓練奠定的知識結構決定後訓練的天花板**。

> **實驗 8-3 ★★ 從頭訓練 MiniMind 2**（一億參數，消費級 GPU）：引入 **QK Norm + Muon 最佳化器** → 收斂速度 **3 倍**；總計約 14 小時、約 34 美元。預訓練後能答「世界最高峰」但格式不規範；SFT 後指令遵循改善；偏好最佳化減少事實錯誤。**固定小預算下，演算法改進比堆規模更具性價比。**
>
> **實驗 8-4 ★★ 自己訓練 VLM**：視覺編碼器（CLIP，凍結）+ **投影層**（唯一從頭訓練的部分，視覺特徵與語言模型間的「翻譯官」）+ LLM。先「凍結 LLM + 只訓投影層」對齊（避免災難性遺忘），再解凍 LLM 用高品質圖文對 SFT。投影層表達能力有限，可能成為跨模態深層理解的瓶頸；同骨架再輸出動作就是 VLA。

## 5. Mid-training：補知識與基礎能力 ⭐⭐

DAPT/TAPT 研究（Gururangan et al., *Don't Stop Pretraining*）已證明：在領域或任務相關的未標註語料上做第二階段預訓練能改善下游。

| 缺口 | 例子 |
|---|---|
| **知識缺口** | 目標語言、金融/醫療/法律、企業文件、特定程式碼庫 |
| **基礎能力缺口** | 長上下文、程式碼模式、數學推導、跨模態表徵；大量取樣也幾乎找不到正解 |

- **不應把 SFT 當主要知識注入工具**：少量 QA 只涵蓋有限問法，擅長訓練「如何存取與表達」。反過來，Mid-training 降低了領域文字的 LM 損失，**也不保證模型會自動按使用者問題取出知識**——繼續預訓練與指令訓練的順序、資料組織顯著影響知識能否被問答形式存取。
- **穩健配方**：Mid-training 吸收知識與能力 → 小規模 SFT 建立輸出格式 → 有非零成功率後 RL 提升成功率與泛化。

### 5.1 Mid-training 資料怎麼構造

1. **從失敗分布反推資料**：按主題、語言、文件型別、程式碼模式、上下文長度切分評估，確認低 pass@k 來自哪類底座缺口；**別把輸出格式錯誤誤診成知識不足**。
2. **構造高密度目標語料**：原始文件建立術語與事實關聯；程式碼倉庫學結構與依賴；教材式推導、合成釋義、跨文件關聯樣本把隱含關係寫明。去重、品質過濾、**評估集汙染檢查**。
3. **按能力配比**：自然長文本（書、長文件、程式碼倉庫）+ 體現長文本原子能力的思維鏈資料（檢索、多跳、指令遵循、聚合統計）+ **Agent 執行軌跡**（規劃、工具選擇與呼叫、長程狀態追蹤、錯誤恢復）；後兩者可從較強開源模型蒸餾或用現有資料集。
4. **每階段「雙重回放」**：① 原始短文本與通用資料（保留語言、知識、短上下文能力；最好來自基模原始預訓練集，否則用 FineWeb-2 等）；② **「長度提升後的舊任務」**——把模型已會的短任務放進當前長度的上下文，在不同位置加相關資訊與干擾項，檢驗同一能力在更長視窗中是否仍成立。
5. **多維門禁決定何時停**：除 loss 外，追蹤留出領域任務、通用能力、原有指令遵循、目標任務 pass@1/pass@k。領域升、通用降 → 混合或學習率過激；**loss 降而 pass@k 不動** → 資料沒覆蓋所需能力，或缺存取知識的 SFT。

**長上下文能力檢查**（LongBench v2、IFEval、第七章端到端 Agent 評估）——長上下文是長思維鏈與指令遵循的基礎，後兩者又是工具呼叫等高階能力的基礎：

| 類別 | 內容 |
|---|---|
| 位置與檢索 | 單針、多針、不同位置的關鍵資訊 |
| 關係與推理 | 跨段落、多文件、多跳；矛盾消解、證據組合 |
| 聚合與統計 | 長表格、長日誌中的計數、分組、排序、比較、趨勢 |
| 指令遵循 | 多指令、矛盾消解、思考流程遵循、輸出格式遵循 |
| 長鏈思考 | 複雜數學、邏輯、程式碼 |
| Agent 原子能力 | 任務分解、計劃、工具選擇、參數構造、狀態記憶、失敗恢復 |

- 頻繁更新或需給出處的事實 → RAG 優於寫進權重；全參 Mid-training 計算與遺忘風險都明顯高於小規模 SFT → **先用小規模實驗驗證資料配比**。

> **實驗 8-5 ★★ 繼續預訓練學新語言**：Mistral 7B v0.3（幾乎不懂韓語）+ 韓語維基百科繼續預訓練（約 **80% 韓語 + 20% 英語**——該實驗的選擇，不是通用預設）→ 韓語指令 SFT。職責分明：**Mid-training 補韓語知識與語言能力，SFT 教模型如何用韓語接受指令和組織回答**。代價：韓語盲評改善，**英語能力下降**——繼續預訓練不能免除保留集、事實評估與資料品質稽核。

## 6. SFT（監督微調） ⭐⭐

> SFT 的核心價值不在注入新知識，而在**固化輸出格式**：把對映、互動格式、風格規範寫入參數，推理時無需冗長提示。代價是可能依賴訓練分佈。

**SFT 資料從哪來**：

| 來源 | 特點 |
|---|---|
| **人工專家示範** | 品質天花板最高，貴且慢；適合定義格式與風格的**種子資料** |
| **教師模型生成** | 合成資料；強模型批次產出「輸入—輸出」對，過濾後蒸餾 |
| **拒絕取樣** | 模型自己對同題取樣多條，驗證器篩出正確者再訓練自己 |

- 三者常組合：**少量人工種子立格式 → 教師模型放大規模 → 拒絕取樣拉齊品質**。
- 流程：定義任務分佈與輸出 schema → 批次生成候選 → 規則校驗、格式檢查 + 人工抽檢 → 去重、平衡配比、保證多樣性。
- **與其堆十萬條髒資料，不如精修一萬條乾淨資料**——資料裡的每一處噪聲，SFT 都可能忠實地寫進參數。

| 實驗 | 固化了什麼 | 要點 |
|---|---|---|
| **8-6 ★★★ 語音 SFT** | 風格控制協定 | **Orpheus**：波形壓成 token、拼接同說話者參考音訊 → 跨句音色一致；**Sesame**：笑聲、嘆氣抽象為 `<laugh>`、`<sigh>` 標記。失敗模式：說話者過少 → 所有人一個腔調；標記過擬合 → 「**機械笑**」 |
| **8-7 ★★★ 多語言思考** | 思考組織範本 | gpt-oss-20b，系統指令加 `reasoning language: German`，用英、西、法等思考樣例訓練；**訓練資料完全沒有中文**，設為 Chinese 卻能用中文完整思考。⚠️ 這**不是 SFT 本身的泛化**——多語言預訓練已建立跨語言共享表徵，SFT 只是啟用了它 |
| **8-8 ★★ Prompt 蒸餾** | 輸入到輸出的直接對映 | 「長提示 + 思考型教師」→「短提示/無提示 + 非思考學生」；訓練資料只留使用者輸入與最終結論。兩個維度：**大到小**、**思考到非思考**（同規模下把顯式 CoT 摺疊為隱式參數化知識，**20–30 倍**響應速度提升）。會繼承教師邊界：長尾系統性錯誤被硬編碼；**教師依賴工具保證正確性時，單純輸出蒸餾會失去工具帶來的魯棒性**。產品穩定、輸入可預期、成本約束明顯時用；探索期保留顯式思考與可編輯提示 |
| **8-9 ★★★ CoT 蒸餾** | 完整思考軌跡 | 同參數量下可恢復教師 **70%–80%** 能力；DeepSeek-R1 的開源蒸餾小模型是代表——不追求前沿、尋求自主可控團隊最務實的**跟隨者策略** |

**CoT 蒸餾的補充要點**：
- **「思維圍牆」**：閉源思考模型（OpenAI o 系列、Gemini）對 CoT 改寫或摘要，原始思考藏在 API 後 → 選**開源思考模型**當教師（DeepSeek V4、Kimi K3、GLM 5.2 公開完整思維鏈；仍需確認許可證對蒸餾產物的條款）。
- **實驗現場**：作者用 GPT-5.6-Sol 驅動的 Codex 寫蒸餾實驗程式碼被拒，換 Claude Opus 5 驅動的 Claude Code 也被拒，最後用 Kimi K3 完成——蒸餾在廠商策略中可能與**模型提取、能力複製、智財保護**相關聯，是敏感類別。
- **多數人根本不需要蒸餾閉源模型**：教師只需「明顯高於學生」，不需要「全球第一」；後訓練 200B 及以下規模時，開源 SOTA 當教師已完全夠用。
- **三步流程**：① 採集軌跡 + 規則驗證器過濾答案錯誤的軌跡（否則錯誤思考也被模仿）= **拒絕取樣**，用它做 SFT = **RFT（Rejection Sampling Fine-Tuning）**，介於 SFT 與 RL 之間、不訓獎勵模型、不做策略梯度，可驗證任務上 CP 值極高；② 以「問題 → `<think>` 思考 `</think>` + 最終答案」對 7B 量級學生做 SFT；③ 對比蒸餾前後與教師。
- 代價：學生繼承教師的**系統性錯誤與冗長思考習慣**（可用 AdaptThink 二次最佳化）。

## 7. SFT 資料合成：從示範到可訓練軌跡 ⭐⭐

- 組合：**少量人工種子 + 教師模型生成 + 驗證器篩選**；模型自舉時同題多取樣只留驗證通過者 = RFT。
- 合成資料的目標不是複述線上日誌，而是提煉可複用的**任務結構**：使用者意圖、初始狀態、可用工具、業務約束、常見失敗方式、成功條件。去除身份資訊後重新生成**虛構**人物、訂單、檔案、狀態，放進可重置的隔離環境——保留真實難點，又避免記住客戶資料或內部憑據。

```
線上資料 → 任務藍圖 → 合成任務 → 多次候選軌跡 → 任務驗證 + 軌跡驗證 → SFT 資料
```

- **任務驗證**：題目可完成？難度合適？參考結果正確？**軌跡驗證**：最終狀態、工具呼叫、業務約束。能寫成單元測試、資料庫斷言、狀態差異檢查的優先確定性程式碼；開放式溝通品質再由模型評價器補充並人工校準。
- 同一套任務與驗證設施可轉成 RL 環境，但用法不同：**SFT 只保留驗證通過的成功軌跡；RL 讓當前策略重新 rollout 探索示範之外的路徑**。失敗軌跡不當正確示範——可構造偏好對、發現覆蓋缺口，或補上診斷修復後再加入。
- **關鍵不是數量，而是覆蓋面、多樣性、準確性**。訓練集按範本、客戶、時間段去重劃分；評估集來自不重疊的任務型別；參考解法、隱藏測試、驗證器回饋不能洩露。
- **bad case 轉訓練資料**：「過早結束」→ 截出「準備宣稱完成」的前綴，過早宣稱作 **rejected**、「先執行測試、逐條核對驗收條件，再下結論」作 **chosen** → 適合 **DPO 或決策邊界示範**，而不是直接當正確 SFT 軌跡；失敗原因、適用條件、驗證器隨樣本保存。

## 8. 何時選 Mid-training、SFT、RL ⭐⭐⭐

> **先判斷缺的是底座、協定，還是策略；不要把「模型做不好」統一歸因成需要 RL。**

**表 8-4　選擇準則**

| 觀察到的現象 | 主要缺口 | 優先方法 | 進入下一階段的門檻 |
|---|---|---|---|
| 不懂領域概念、語言或基礎操作；合理取樣下 pass@k 仍近 0 | 知識與能力不在基模的有效支持中 | **Mid-training**；動態事實用 RAG | 領域留出集改善、通用保留集可接受、開始出現可驗證的（部分）正確軌跡 |
| 偶爾能做對，但格式、工具 schema、語氣或固定流程不穩 | 行為協定未固化 | **SFT** 或約束解碼 | 解析成功率穩定，驗證器能可靠評分關鍵動作與輸出 |
| 已有非零成功率與可靠獎勵，但好策略機率低、長程決策或 OOD 不足 | 機率質量分配與策略最佳化 | **RL** | 獎勵符合真實目標、rollout 組內有足夠差異、獨立測試隨訓練改善 |
| 只有少量穩定示範，尚無互動環境 | 有可模仿資料，沒有線上回饋 | **SFT／RFT／離線偏好最佳化** | 先建基線與評估，再判斷是否值得建 RL 環境 |

**決策順序**：
1. **先排除不必改權重的方案**——Prompt、工具、程式約束、上下文管理能解決就別訓練；事實要常更新、引用或刪除 → RAG。
2. **在目標留出集測能力支持**——不只看貪心 pass@1，還要固定取樣設定下的 pass@k、部分進展率、解析率，並審計失敗原因。
3. **用 SFT 建立協定，不拿它硬塞知識庫。**
4. **只在有探索空間時用 RL**；pass@k 近零時，在全零 rollout 上套 PPO/GRPO 通常只是浪費取樣預算。

> 不是每個專案都要依次做完三種：強基模可能直接 RL、格式型任務可能只需 SFT、穩定領域知識可能只做 Mid-training。**關鍵是每一步都有可測的進入條件。**

> 對照第一、九章的「更新載體」：先問能不能用上下文、Skill、程式解決，再問要不要改參數——這是同一套「最小、可回滾的修改」思想在模型層的版本。

## 9. 單輪強化學習：記憶與泛化的對照 ⭐⭐⭐

**最小直覺**：對同一問題多生成幾條回答，「**獎勵高的方向多走，獎勵低的方向少走**」。

```python
# GRPO：同一 prompt 的組內比較
for prompt in batch:
    group = [rollout(policy, env.reset(prompt)) for _ in range(G)]
    rewards = [verify(trajectory) for trajectory in group]
    advantages = normalize_within_group(rewards)       # GRPO baseline
    update(policy, group, advantages)

# PPO：價值網路 + 裁剪目標
for trajectory in rollouts:
    returns = discounted_returns(trajectory.rewards)
    values = value_model(trajectory.states)
    advantages = returns - stop_gradient(values)
    ratio = exp(policy.log_prob(trajectory.actions) - old_policy.log_prob(trajectory.actions))
    policy_loss = -mean(min(ratio * advantages,
                            clip(ratio, 1 - epsilon, 1 + epsilon) * advantages))
    value_loss = mean((value_model(trajectory.states) - returns) ** 2)
update(policy, value_model, policy_loss + value_coef * value_loss)
```

- **PPO**：機率比超出區間時裁掉代理目標的額外收益——抑制大幅更新，**但不是對策略變化的硬約束**；`old_policy` 是生成這批 rollout 時凍結的快照。
- **GRPO**：不訓價值網路，「相對」來自同一 prompt 的組內比較。

> **實驗 8-10 ★★ AdaptThink——學會「何時不思考」**
> - 先驗證：**NoThinking**（`<think></think>` 跳過思考）在簡單題上相當甚至更好，只有難題 Thinking 才有優勢。
> - 兩個核心元件：**約束最佳化目標**（鼓勵 NoThinking 但整體效能不降）+ **重要性取樣**（平衡兩類樣本，解決初始模型幾乎總選 Thinking 的**冷啟動**問題——與 R1「冷啟動 SFT」不同語境）。
> - 實測（8×H100，W&B `wubbn5tj`，step 0 → 300）：
>
> | 資料集 | 準確率 | 回應長度 | NoThinking 比例 |
> |---|---|---|---|
> | MATH500 | 0.8100 → 0.8180（+0.80 pp） | 4911 → 1577（−67.90%） | 83.80% |
> | GSM8K | 0.7968 → 0.8188（+2.20 pp） | 1025 → 477（−53.44%） | 84.15% |
> | AIME mean@16 | 0.3146 → 0.3104（−0.42 pp） | 12120 → 6402（−47.17%） | 56.25% |
>
> - 資料集層面存在**與難度一致的路由訊號**（難題 NoThinking 比例低），但**不能稱為逐題「完美難度感知」，也不能聲稱準確率普遍提升**。
> - 誠實記錄：繼續到 step 410（36.92 小時）後 `crashed`，配置的 3,140 steps 未完成；checkpoint 不隨書分發；訓練/評估腳本路徑不相容需手工修正。
> - 與 Prompt 蒸餾互補成「**快—慢雙系統**」。

> **實驗 8-11 ★★ GeneralPoints（Chu et al., *SFT Memorizes, RL Generalizes*）**
> - 類 24 點：四張牌加減乘除湊 24；**GP-L**（純文字）與 **GP-VL**（影像）。
> - **規則變體**：訓練 J/Q/K = 10，測試 = 11/12/13；**視覺變體**：訓練黑色花色（♠♣），測試紅色（♥♦）。
> - Llama-3.2-Vision-11B，先 SFT 初始化，再同預算分別擴展 SFT 與 RL（帶價值網路的 PPO）。
>
> | OOD 測試 | RL | SFT |
> |---|---|---|
> | 規則 GP-L | **+3.5%**（11.5% → 15.0%） | **−8.1%**（11.5% → 3.4%） |
> | 規則 GP-VL | +3.0% | −5.6% |
> | 視覺 GP-VL | **+17.6%**（23.6% → 41.2%） | −9.9%（23.6% → 13.7%） |
>
> - **RL 透過結果導向最佳化改善了底層視覺編碼器**（識別準確率提升且與整體效能高度相關）；SFT 過度擬合思考中的 token 模式、忽視視覺 token → 識別準確率反而下降。
> - **未經 SFT 直接 RL 完全失敗**（無法產生結構化輸出、獎勵無法計算）——特定設定下的結論。
> - **驗證迭代越多泛化越好**：10 次 +5.99% vs. 1 次 +0.48% → 增加測試時計算量是泛化提升的重要因素。
> - 解釋：有限 SFT 強化「遇到 J/Q/K 就當 10」；RL 更可能強化「**重新計算直到正確**」。**不是說 SFT 必然只能記憶、RL 必然學會通用演算法。**

## 10. RL 演算法：從 16 次 rollout 到一次參數更新 ⭐⭐⭐

**以 SWE-bench 任務為例**（`parser.py` 空輸入觸發 `IndexError`，不能改測試）：

```
① 重複嘗試    同一初始程式碼 + 問題 → 16 個隔離沙箱，各跑一次完整 rollout
               （讀碼 → 改檔 → 跑測試 → 提交）；有的補邊界檢查，有的只捕獲異常掩蓋問題，
               有的改錯檔，有的試圖改測試
② 計算獎勵    驗證器在乾淨環境套用補丁跑測試：4 條通過且未改測試 → 1；12 條 → 0
③ 相對優勢    組內平均 4/16：通過者正優勢、失敗者負優勢
               ⚠ 16 條全敗或全勝 → 獎勵全同 → 相對優勢消失（RLVP、過程獎勵、部分進展要解決的正是這個）
④ 梯度更新    提高正優勢軌跡中選擇的機率、降低負優勢的；
               不是背下某個補丁，而是讓「先復現、查邊界、改實作、跑測試」更容易出現，
               「掩蓋異常、改測試、沒驗證就提交」更少出現
```

- 四步 = 一個 **step**；訓練 100 steps ≈ 重複 100 輪（框架內部的 minibatch 計數要另確認）。
- **時間估算**：rollout 階段牆鐘由**最慢的那條**決定。最慢約 2,000 秒 + 梯度與最佳化器約 600 秒 → 一 step ≈ 2,600 秒 ≈ 43 分鐘 → 100 steps ≈ **72 小時**。
- **PPO vs. GRPO vs. DPO**：GRPO 比同題多條 rollout、不需價值模型；PPO 訓價值模型估「每一步通常能做多好」，更適合需細粒度信用分配的長軌跡；**DPO** 直接學事先收集的「較好—較差」偏好對，不線上生成 rollout。
- 本章用法：AdaptThink 自定義約束目標；GeneralPoints、V-IRL 帶價值模型的 PPO；SimpleVLA-RL、RLVP 用 GRPO；ReTool 用 PPO。

> **演算法決定如何比較軌跡和更新參數；獎勵決定什麼算成功；環境和資料決定模型能經歷哪些問題。**

### 10.1 為什麼 LLM RL 通常優先 On-Policy

- **Online**：資料在訓練中持續與環境互動產生；**On-policy**：生成 rollout 的行為策略 μ 與要最佳化的 π_θ 相同或足夠接近。非同步叢集即使一直在線生成，worker 落後數個 checkpoint 就含 off-policy 成分；PPO 在同批資料上多輪 minibatch 更新，後幾輪也逐漸偏離 `old_policy`（這正是它需要機率比與 clipping 的原因）。
- 資料由 μ 取樣時需重要性比率修正：

```
ρ_t = π_θ(a_t | s_t) / μ(a_t | s_t) = exp( log π_θ(a_t | s_t) − log μ(a_t | s_t) )
新鮮 on-policy rollout 在參數更新前應有 π_θ = μ，因此 ρ_t = 1
```

- Off-policy 能重用舊資料、非同步提高吞吐，但策略越陳舊 ρ 越重尾；長序列連乘許多 token 比率 → 小偏差累積成極端權重；clipping 能限制離群更新，**卻不能無損補回缺失的分布覆蓋**。「on-policy 較好」不是普遍定理，而是在當前 LLM 策略梯度中通常代表**較小分布偏差與較穩定最佳化**。

### 10.2 看似 On-Policy，為何仍會被數值誤差拖垮 ⭐⭐

- 常見架構：**vLLM/SGLang 生成 rollout，FSDP/Megatron 重算 log prob 與梯度**。即使權重相同，浮點精度、歸約順序、張量平行、batch size、KV cache、fused kernel 差異都會讓同一 token 的 log prob 略有不同 → 本應為 1 的 ρ 已偏離 1：**名義上同步權重，數值上把 on-policy 變成 off-policy**；微小的 token 級訓練—推理差異本身就可能導致訓練崩潰。
- **放大鏈條**：log prob 小誤差 → 指數化的比率偏差 → 長前綴累積 → clipping/優勢加權改變 → 梯度方向與有效樣本數改變。

```
若 4,000 個 token 的 log ratio 都有同方向 1e-3 偏差：
軌跡級比率 = e^(4000 × 0.001) = e^4 ≈ 54.6
```

  早期 token 的機率差還可能改變實際取樣的 token → 整條狀態軌跡分叉 → 重要性比率尖峰、大量 token 被裁、梯度或回應長度突變 → **獎勵和熵一起坍塌**。批次大小改變歸約方式、破壞 **batch invariance**，也被直接觀察到會把 RL 變成隱式 off-policy。

**工程守則**（當作核心問題，而不是普通浮點雜訊）：
- **任何參數更新之前**，用同一批軌跡比較 sampler 與 trainer 的 token log prob，監控 ρ 的均值、分位數、最大值、近似 KL、被裁剪比例——**最直接的 on-policy 單元測試**。
- 同步的不只是權重：LoRA adapter、tokenizer、chat template、模型 revision、位置編碼設定；rollout 要**保存生成時的 behavior log prob**，不能事後拿當前模型冒充。
- 盡可能對齊精度、平行佈局、關鍵核心；做不到就**明確當作 off-policy**，用重要性修正並監控有效樣本數，而不是假設 clipping 會兜底。
- 保持 rollout 新鮮，限制每批更新輪數與非同步 staleness——重用舊資料是**經過測量的偏差—效率取捨**，不是免費加速。

> 對照第五章「跨廠商接管」與第七章 `old_string` 逐層定位：**同一份「資料」在不同系統裡的表示不同**——這次是 log prob 在推理引擎與訓練引擎之間不一致。

## 11. RL 環境：從評估到模擬 ⭐⭐⭐

> RL 的瓶頸往往不在演算法，而在**環境是否足夠真實、可重置、可並行**。環境工程是 RL 的前置條件，不是訓練完的附屬品。

- **環境失真，策略必廢**：模擬客服總按固定套路回話、錯誤資訊與生產對不上 → 學到只在模擬裡管用的「應試策略」——**練習場跟考場不是一回事**，是 RL 專案最常見的翻車方式。
- **建高保真環境常比訓練本身更貴更難**：真實 API 有速率限制、會封號、有副作用 → 必須先造一個穩定、可控、可重放的「**影子世界**」（AWorld 的 MCP 沙盒、ReTool 的直譯器沙盒）。
- **環境的另一半是獎勵函式**。

> 在動手調演算法之前，先問：**我的模擬環境，真的像真實世界嗎？** 這比選 PPO 還是 GRPO 重要得多。

### 11.1 造不出環境：讓模型扮演環境

| 層次 | 代表 | 做法 |
|---|---|---|
| **模型合成工具返回值** | **ZeroSearch** | LLM 扮演搜尋引擎；**課程式**：初期回高品質強相關文件，逐步摻入噪聲、降低品質 → 逼學生在不完美返回中提取資訊；全程沒見過真實搜尋引擎，對接真實搜尋依然表現良好 |
| **模型模擬整個環境動態** | **DreamGym** | 把環境動態蒸餾進推理式「經驗模型」：給狀態 + 動作，逐步推理狀態轉移與回饋 → 批次合成 rollout 做線上 RL；客服/銷售用 LLM 扮演使用者（τ-bench 系列——同一個模擬器既是考場也是練習場） |

> ⚠️ **模擬器的世界知識是訓練的天花板，模擬器的系統性偏差會被策略照單全收**——更有耐心的模擬使用者、從不回垃圾的模擬搜尋；RL 還會主動尋找並利用模擬器漏洞。穩妥做法：**混合**——模型模擬承擔大部分互動量，輔以真實互動，並**定期用真實互動校準模擬器**。

### 11.2 環境、任務分佈與評估隔離

- 環境必須可重置、可並行、可復現，狀態轉移後給可信驗證結果。任務來源同 SFT 資料合成（業務日誌 → 任務藍圖 → 虛構人物/訂單/檔案/狀態）。
- **訓練與評估環境可共享任務生成器與驗證程式碼，但不能共享同一批任務**（SWE-Gym、τ²-bench、AndroidWorld）；測試案例、隱藏狀態、參考解法留在驗證器一側。
- 先用少量 rollout 檢查「**任務是否可完成、驗證器能否區分對錯**」再擴大取樣——驗證器有系統性偏差，RL 只會更快地利用它。

```
任務藍圖 → 可重置模擬器 → 確定性驗證器 → 訓練/評估隔離 → 少量真實互動校準
```

- 確定性驗證器「便宜」≠「沒有成本」：Lean kernel、測試執行器、容器執行可能讓 CPU 驗證遠慢於 GPU 生成 → 吞吐取決於**並行的驗證器 worker**，而不是繼續堆 GPU。

## 12. 從單輪到多輪：信用分配 ⭐⭐

- 多輪：策略要考慮未來狀態價值、在延遲獎勵下做**信用分配**——客服 10 輪對話獲好評，是第 2 輪的精準提問還是第 7 輪的耐心解釋？
- 多輪互動就是第一、四章的 **ReAct 迴圈**（思考 → 行動 → 觀察）；獎勵延遲來自「最終結果要多輪後才能判斷」。

| 實驗 | 設定 | 結論 |
|---|---|---|
| **8-12 ★★★ V-IRL-VL** | 真實城市街景導航；訓練紐約、測試其他城市，同時改方向表達與視覺外觀；帶價值網路的 PPO | RL 在規則與視覺 OOD 都明顯優於 SFT；策略要學會依當前觀測重新規劃，而非復現訓練軌跡；**逐步回饋緩解長時序信用分配** |
| **8-13 ★★★ SimpleVLA-RL** | LIBERO 機器人任務，**只有成功/失敗結果獎勵**；每任務**僅一條**示範做 SFT 冷啟動 | 成功率 **17.3% → 91.7%**；發現示範中沒有的「**推切**」動作。對照 V-IRL：**過程訊號容易定義時能加速學習；最佳路徑未知時，稀疏結果獎勵保留更大探索空間** |

### 12.1 工具呼叫：把環境帶進 Agent

- 動作變成搜尋、執行程式碼、改檔、查資料庫、組合 API → 信用分配、環境工程、安全約束同時推到前台。
- **Search-R1**：模型自主決定何時搜、搜什麼；**ReTool**：直譯器嵌入思考迴圈，學會何時執行、讀回饋、依報錯修正；**AWorld-train**：MCP 多工具沙盒，引入工具選擇、依賴管理、狀態重置、可重放性。

> ⭐ **環境返回的 token 不是策略生成的**——算策略梯度時**遮蔽這些回饋 token**，只對模型自己的思考與工具參數回傳梯度。否則模型會被訓練去「預測沙盒輸出」，而不是學會使用工具。（SFT 的 loss masking 在 RL 中的對應。）

> **實驗 8-14 ★★★ ReTool**：SFT 預熱後，交織文字思考、程式碼執行、直譯器回饋做 PPO；資料 DAPO-Math-17k（演算法仍是標準 PPO）。**AIME 2024：約 25% → 67.0%**；比純文字 RL 更快學會精確計算與糾錯。
>
> **實驗 8-15 ★★★ AWorld-train**：MCP 沙盒（Web、文件、多媒體、程式碼、知識檢索）；重點不是刷 GAIA，而是跑通**可重置、可重放的多工具訓練鏈路**，觀察工具呼叫成功率與組合策略是否改善。

> 多輪 Agent 的訓練難點不是「有沒有更複雜的最佳化器」，而是**環境回饋是否可靠、動作鏈是否可驗證、最終獎勵如何歸因到中間決策**。

## 13. 獎勵設計 ⭐⭐⭐

三個維度：**來自哪裡、什麼時候給、表達多少資訊**；再加一個：**結果正確時路徑是否合規**。

### 13.1 獎勵來自哪裡

| 來源 | 說明 |
|---|---|
| **RLVR**（可驗證獎勵） | 測試、資料庫斷言、狀態差異、格式檢查；最可靠、便宜、可復現、不易被鑽漏洞 |
| **RLHF**（背景） | InstructGPT：人工比較 → 訓獎勵模型 → PPO；獎勵模型是偏好的代理，**過度最佳化導致 reward hacking** → 用 KL 正則錨定在 SFT 參考模型附近。**DPO** 跳過顯式獎勵模型，直接從偏好對離線最佳化 |
| **生成式獎勵模型（GRM）** | 不只給分數，還生成「哪裡好、哪裡要改」的診斷；**DeepSeek-GRM**：先歸納評價原則 → 按原則評價 → 用可驗證事實檢查評價。更透明，但仍需抽樣人工校準 |

> ⭐ **Reward hacking vs. reward seeking**：前者是鑽規則或實作漏洞拿高分；後者是模型先在心裡建一個「評判器會看什麼」的模型、再按猜測調整行為——不一定篡改測試，卻可能**自設一個很淺的檢查、剛好通過就提前結束**，交付物只滿足代理指標。**「通過了 grader」不能自動等價於「任務完成了」**：訓練越強，模型越可能把代理當成目標本身。

### 13.2 獎勵什麼時候給：結果還是過程

| | 結果獎勵（ORM） | 過程獎勵（PRM） |
|---|---|---|
| 時機 | episode 結束 | 中間步驟（身份驗證、工具參數、測試通過數、導航動作） |
| 優點 | 最簡單；**最大探索自由度**；最佳解未知時合適（SimpleVLA-RL） | 緩解長時序信用分配（V-IRL）；《Let's Verify Step by Step》展示逐步驗證的價值 |
| 缺點 | 稀疏，難判斷多步軌跡中的具體錯誤（RL 樣本效率受限的原因之一） | 可能把模型限制在設計者預設的路徑上；標註與驗證成本高 |
| 一句話 | **稀疏回饋換探索空間** | **密集回饋換收斂速度** |

- 長程 coding/cowork 任務：「是否完成」要交給**模型寫不了的隱藏測試、狀態斷言或外部終止鉤子**，不能只信模型自稱完成。
- **「過早結束」的獎勵**：模型宣稱完成時，Harness 在隔離工作區執行**模型看不到的驗收測試**；通過 +、未通過 −。測試必須讀真實檔案或狀態，不能只檢查是否說了「已完成」（否則學會口頭承諾驗證而不真驗證）。評估把**未完成的邊界集**與**確實已完成的保留集**分開，避免把模型訓練成永遠不敢結束。
- 工程：先用結果獎勵建可靠基線，再只為真正可驗證的中間事件加過程訊號。多輪 LLM RL 通常令 **γ = 1**；PPO 的價值網路或 turn-level 優勢把終點回饋歸因到較早動作；GRPO 把軌跡級優勢均攤到 token，長軌跡要注意**訊號稀釋**。

### 13.3 獎勵要表達多少資訊

| 形式 | 回答 | 適用 |
|---|---|---|
| 純量 | 整體多好 | 有確定答案或測試 → **優先二元純量** |
| 半純量 | 先給簡短理由再給分 | — |
| 向量 | 準確性、完整性、成本、安全分別打分 | 多個相互獨立的品質目標（或加權成純量） |
| 生成式診斷 | 自然語言診斷，可多取樣彙總 | 開放式、難以窮舉規則；配事實校驗與人工抽檢 |

> **不要為了「獎勵更豐富」堆疊不可驗證的維度**——每加一個維度就多一種被鑽漏洞的可能；先確認它能在少量 rollout 中產生有意義的組內差異。

### 13.4 結果正確還不夠：RLVP（獎勵結果、懲罰路徑） ⭐⭐⭐

- 表面成功可能來自改測試檔、跳過身份驗證、執行破壞性命令。**RLVP**（Reinforcement Learning with Verified Penalty，作者論文 arXiv:2607.07435）針對**可機器判定、與最終成敗無關的結果中性約束**；不能替代對語義意圖、交付完整性、早停行為的獨立檢查。
- ⭐ 真實環境通常是**非對稱驗證器**：偵測「做了一個壞動作」便宜可靠；證明「這一步確實取得有意義進展」很難。

```
R = O + β · Φ
O：任務結果；Φ：由確定性規則逐動作計算的路徑訊號
  （違規扣分；可驗證的合規動作或可達子目標給少量部分獎勵；兩路正規化後再合併）
不改變 PPO/GRPO，只改變每一步看到的獎勵
```

```python
outcome = verify_final_state(trajectory)              # result, not self-report
path_signal = 0
for step in trajectory:
    path_signal += deterministic_path_signal(step)    # penalty or reachable progress
reward = normalize(outcome) + beta * normalize(path_signal)
```

- **關鍵不是獎勵越密越好，而是能否補回組內差異**：純結果獎勵在全敗組、全勝組零方差、沒梯度；**違規動作通常容易偵測，懲罰幾乎總能補回差異**；進展獎勵只在部分進展可達時有效。
- **四條設計原則**：① 只懲罰具體動作，不懲罰「不夠努力」；② **結果獎勵始終保留**，避免學會什麼都不做；③ 每個懲罰最好配一條**可達的合規路徑**；④ 規則確定、難以鑽漏洞。基礎策略根本不會取樣合規動作 → 先用少量示範「種」出這條路徑，穩定後逐步減弱塑形。
- **懲罰是通常可達的那一半，進展獎勵是受可達性門控的那一半。**

> **實驗 8-16 ★★★ RLVP**（GRPO + O + Φ vs. 純結果獎勵）
> - **TerminalBench**：違規次數 **3.71 → 0.66**，成功率基本持平；
> - **miniF2F**：可達的部分獎勵把達到 0.9 成功率所需迭代 **7.0 → 4.4**；
> - **軟體修復**中所有 rollout 都過不了任何測試 → 進展訊號不可達 → 加了也沒收益。
> - → **先測訊號可達性，再決定是否增加獎勵維度**。數字來自可控代理環境，結論是機制性的；真實部署還要把隱藏驗證、軌跡監控、外部終止條件一起納入 harness。

> 呼應第五章「約束的另一層目的：防止過程性錯誤」——Harness 護欄是對現有模型的**外部約束**，RLVP 是對可訓練模型的**內部內化**。

## 14. 蒸餾：提升樣本效率 ⭐⭐⭐

- **樣本效率**：每次昂貴的環境互動能帶來多少有效參數更新。ReTool 的 RL 訓練時間是 SFT 的 **200 倍以上**（9 天 vs. 1 小時）。
- RL 樣本效率低的根本原因是**回饋太稀疏**：一條 rollout 只有一個成敗純量。客服說「需要信用卡後四位」，模型卻只能從最終 0/1 反覆試錯，可能數百次才偶然學會；**人類聽一次就記住**。
- **蒸餾把一次 rollout 變成密集監督訊號。**

### 14.1 On-Policy Distillation（在軌蒸餾，Thinking Machines Lab 2025）

> 這裡的 policy 指「**由誰生成學生學習時所在的狀態前綴**」，不是由誰提供監督。

| 方法 | 誰取樣軌跡／狀態 | 每條軌跡的主要監督 |
|---|---|---|
| SFT／off-policy 蒸餾 | 人類或教師 | 標註答案的稠密 token 監督 |
| On-policy RL | 當前學生 | 通常是稀疏的結果或過程獎勵 |
| **On-Policy Distillation** | **當前學生** | **教師在學生前綴上的稠密 token 分布** |

> **學生決定走到哪裡，教師在學生真正到達的狀態提供完整的下一 token 分布。** 長度 T 的 rollout 不再只有一個 0/1，而有約 T 組逐 token 監督。

```python
student_trajectory = rollout(student, task)
loss = 0
for state in student_trajectory:
    teacher_logits = teacher(state)
    loss += KL(student_logits(state), teacher_logits)
update_student(loss)
```

- 例：學生生成「先查詢 API，再解析返回值……」時，教師在當前位置給「查詢」80%、「呼叫」15%、其餘 5%。逐 token 對齊比二元獎勵**密集得多、方差更低**；代價是教師推理成本 → 環境互動昂貴時尤其划算。
- 數學等任務上，達到同等效能所需步數約為純 RL 的 **1/10**。
- 前提：學生至少要進入教師可糾正的有效狀態；模擬環境要夠真，讓學生探索到的狀態接近部署分佈。基模連目標語言、概念都不會 → 先 Mid-training 或 off-policy 示範冷啟動。仍要**驗證 sampler/trainer 的 log prob 一致性**。
- **作者的「時間感」任務**：比較 DPO、四種 RL 與 On-Policy Distillation——前者分別受**稀疏獎勵、目標錯位、rollout 形狀不匹配、策略崩潰**限制；換成凍結的 Qwen3-32B 教師在學生自己的多輪軌跡上逐 token 對齊 → 平滑收斂，四種條件下通過率比同源 SFT 基線高 **23 到 47 個百分點**。**瓶頸往往不是獎勵函式不夠複雜，而是每次互動提供的訊號不夠密。**

### 14.2 沒有更強的教師：On-Policy Self-Distillation（OPSD）

> **同一個模型分飾教師和學生，但看到的上下文不同**：教師版看到**特權資訊**（標準答案、已驗證解答），學生版只看到問題，在自己取樣的軌跡上向教師版的逐 token 分佈對齊。**對著答案解釋學生剛走過的路徑，通常比獨立探索更容易。**

```python
student_trajectory = rollout(model, task_without_answer)
loss = 0
for state in student_trajectory:
    privileged_state = add_verified_answer(state)
    teacher_logits = stop_gradient(model(privileged_state))
    loss += KL(model(state), teacher_logits)
update(model, loss + retention_regularizer)
```

- `privileged_state` 只能在訓練側構造，**不能洩露給部署時的 Agent**；`retention_regularizer` 代表保留集/風格約束。
- 相比 RLVR，**不要求獎勵能被自動驗證**（特權資訊可以是答案、人工示範、領域文件）。
- 不會憑空創造新知識——拿著答案也講不清過程就沒有額外訊號；樸素 OPSD 可能**丟失原有思考風格**，需要額外正則（Purified OPSD）。

> 對照 Ferguson《Cryptography Engineering》：特權資訊只能在訓練側出現、絕不能在部署時可見——和「金鑰只能在受信任的一側」是同一種邊界紀律。

## 15. 從 bad case 到後訓練 ⭐⭐⭐

**表 8-5　第七章評估資產 → 第八章訓練用法**

| 第七章的評估資料集 | 第八章的訓練用法 |
|---|---|
| 端到端迴歸任務（含驗證器） | RL rollout 任務與可驗證獎勵（RLVR）；拒絕取樣（RFT）的取樣池 |
| 軌跡前綴迴歸任務 | DPO 偏好對、決策邊界 SFT 示範、On-Policy Distillation 的教師狀態 |
| 失敗歸因記錄（首錯步驟與類別） | 過程監督的負標籤（PRM）、RLVP 路徑懲罰的規則來源 |
| Rubric 多維評分與人工金標集 | 向量獎勵各維度、生成式獎勵模型（GRM）的訓練與校準資料 |

### 15.1 案例 1：Coding Agent 過早結束

- **歸因**：測試沒跑就宣稱完成、改三個功能改完兩個就收尾、失敗兩次就宣布「不可能」——第七章「任務完成度與邏輯判斷」；三類訊號（使用者糾正、點踩、事後審計：宣稱完成的軌跡中沒有任何測試工具呼叫）都能捕獲。**首錯在「準備宣稱完成」的決策邊界**——之前讀碼改碼可能都沒錯，錯的是「**在缺乏證據時下結論**」（正是 reward seeking）。
- **構造資料**：
  - 端到端：「宣稱完成前必須跑通驗收測試」寫成可驗證獎勵——測試對模型不可見、宣稱完成時才執行，通過 +1、不通過 −1（可選 RL 分支）；
  - 前綴：在決策邊界構造偏好對——rejected = 過早結束；chosen = 「先執行測試、逐條核對驗收條件，再下結論」（教師生成 + 規則驗證器過濾 = 拒絕取樣）→ DPO 訓練對；bad case 太少就擴充（換任務型別、缺失的驗證項、完成措辭）到數百條；**小配比混入通用資料**做 LoRA，避免把「逢收尾必驗證」學成新的過擬合。
- **評估：邊界集與保留集缺一不可**——邊界集查「未完成時是否繼續驗證」；**保留集查「確實完成時能否正常宣稱完成」**。只盯前者 → **過度矯正**：永遠不敢收尾，延遲與成本崩潰。還要抽查通用能力。

> **實驗 8-17 ★★ 從「過早結束」bad case 到 DPO**：24 條寫實 bad case，四類（未跑測試就宣稱、多目標只完成一部分、驗收未滿足、遇錯放棄宣稱不可能——含**刪除失敗測試**的惡劣 reward hacking 變體）；held-out：boundary 12 + retention 8；鏈路：歸因 → 前綴迴歸 → DPO 偏好對 → 7B LoRA → 雙集驗證。生產中要警惕新形態：模型可能學會「**口頭聲稱去驗證**」而不真驗證——所以獎勵必須依賴模型寫不了的隱藏測試。

### 15.2 案例 2：中文引號

- 回饋「中文文章中的直引號應統一為彎引號」描述了期望，卻沒給可訓練的規則。正確修復是**作用域敏感的最小編輯**：中文自然語言中的引用轉成 `「」`（巢狀按中文標點規則）；英文原文、可執行程式碼、JSON/schema、路徑、識別符、Markdown 反引號內容原樣保留；**無法判斷作用域時保留原文**。
- 把引號規則寫成 **Skill**；正例覆蓋中文段落、巢狀引用、程式碼註解中的中文；反例覆蓋英文原文、字串字面量、JSON、路徑、行內程式碼、整段程式碼 → 教「**先判斷作用域，再做最小編輯**」，而不是「看到直引號就替換」。

> **實驗 8-18 ★★ 作用域敏感彎引號 SFT**：Qwen3-8B，bf16 LoRA 2 epoch（256 次更新）；`SKILL.md` 同時是**生成標籤、品質門禁、迴歸規範**；模型只負責選擇作用域與生成最小編輯，**生產側的解析器與語法檢查不被移除**。資料：16 類片段 × 10 種體裁 × 9 種程式語言 → 1024 訓練 + 256 留出 + 256 邊界。

### 15.3 案例 3：編輯檔案經常失敗

- `edit_file(path, old_string, new_string)` 精確匹配，差一個空格、換行、反斜線、Unicode 組合字元或低頻 token 都會失敗。
- **歸因鏈路**：原始位元組 → 工具返回 → Harness 序列化 → 模型上下文 → 模型 token 輸出 → 解碼字串 → JSON/tool-call 解析 → 工具匹配。讀取或工具返回改了位元組 → 工具；序列化、跳脫、提示詞拼裝改了 → Harness；tokenizer encode 再 decode 變了 → tokenizer；**只有模型收到的上下文與原字串完全一致、而模型輸出是首個差異位置，才算模型的精確複製能力問題**。
- **三個可驗證任務**：直接逐字複述；在相似且等長的多個字串中選完全相同的目標；把指定字串完整抄進 `old_string` 的工具 JSON 參數。特意包含空格、真實換行、反斜線、Unicode。

> **實驗 8-19 ★★ 特殊字串精確複製 SFT**：Qwen3-8B，bf16 LoRA 2 epoch；**只對目標字串或 `old_string` JSON 欄位提供逐 token 監督**。結果：byte-exact accuracy **37.5% → 78.9%**（留出），獨立邊界集 **80.1%**；平均首次位元組分歧位置 54.0 / 54.2。另用 512 條探針比較三個開源 tokenizer：Qwen3 與 Qwen2.5 無損 round-trip 均為 **80.1%** → **80.1% 同時反映了模型複製能力與 tokenizer 上限**。

> 兩個新 bad case 的監督目標不同：彎引號測「**該改才改、該留則留**」；精確複製測「**必須逐字複製**」——共享歸因與訓練/評估隔離協定，但不共享總分。

## 16. 後訓練實踐要點：十一個常見陷阱 ⭐⭐

| # | 陷阱 | 對策 |
|---|---|---|
| 1 | 把知識庫硬塞進 SFT，或把所有知識都交給參數 | 穩定大規模知識用 Mid-training 寫入，再由 SFT 教存取與表達；需更新、引用、權限控制、刪除的交給 RAG |
| 2 | 格式未穩定就引入 RL | 先用小規模評估設格式穩定性門檻（**不應把固定閾值當普遍標準**），必要時 SFT 或約束解碼 |
| 3 | **把標稱視窗當成有效視窗** | 位置編碼接受 128K ≠ 能在 128K 檢索、推理、規劃；擴窗前完成當前長度的能力門檻，保留短資料與 replay，以「**能力 × 長度」矩陣**檢查退化 |
| 4 | pass@k 近零仍直接 RL | 全失敗 rollout 沒有正軌跡；先 Mid-training/SFT/蒸餾擴大有效支持，或設計可達課程與部分獎勵 |
| 5 | 獎勵設計不當 → reward hacking | 評估最終目標，不是中間代理指標 |
| 6 | 忽視模擬保真度 | 高保真模擬的成本可能高於訓練本身 |
| 7 | 過度訓練導致泛化下降 | Mid-training 遺忘通用能力、SFT 過擬合示範、RL 過擬合當前獎勵與任務 → 都需要獨立保留集與早停 |
| 8 | 價值函式崩潰與探索不足 | PPO 價值偏差 → 曲線劇烈震盪；溫度過低 → 困在局部最佳 |
| 9 | **把訓練—推理數值差異當成無害雜訊** | 監控 log prob 差、近似 KL、裁剪比例、策略陳舊度 |
| 10 | 低估 RL 算力成本 | 適合 SFT 的任務轉 RL 可能 10–100 倍時間；測試與訓練分布相近時 SFT 可能已足夠 |
| 11 | 訓練資料品質低 | Mid-training 吸收錯誤關聯、SFT 直接學示範雜訊、有偏 RL 獎勵把策略推向錯誤方向 |

> **核心原則：投入大規模資源前，先用小實驗驗證關鍵假設**——小型 Mid-training 語料看知識、能力與遺忘曲線；少量 SFT 測格式穩定性；小批 rollout 檢查 pass@k、獎勵差異、sampler/trainer 數值一致性。

### 16.1 與 RAG/ICL 的協同

| 機制 | 作用位置 | 適合 |
|---|---|---|
| **ICL**（上下文學習） | 示例、規則、當前狀態 | 零參數即時適應；上下文增長時延遲與費用上升 |
| **RAG** | 可動態更新、可追溯的外部知識 | 事實與證據 |
| **程式** | 確定性流程 | 硬約束（長期穩定的轉賬審批規則也該由程式碼保證，**不能只靠模型記憶**） |
| **Mid-training** | 參數 | 穩定領域知識與基礎能力 |
| **SFT / RL** | 參數 | **外部規則難以完整表達的行為**：高維感知、生成風格、隱式決策策略（醫療影像識別、自然語氣即使領域持續變化也往往需要參數更新） |
| **蒸餾** | 參數 | 把大模型行為轉移到便宜的小模型 |

> 選擇依據不只是任務是否長期穩定，更重要的是**能力能否被外部符號充分表達**。

## 17. 設計觀念整理

| 觀念 | 本章體現 |
|---|---|
| **底座、協定、策略三分** | Mid-training 補底座、SFT 立協定、RL 調策略；不是同一種微調的不同強度 |
| **先測能力支持再選方法** | pass@1 vs. pass@k、解析率、部分進展率、失敗歸因 |
| **RL 放大已有，不憑空創造** | pass@k 近零時 GRPO 組內優勢消失 |
| **SFT 本質是換了資料的 NTP** | loss masking 是唯一實質區別；固化協定而非事實 |
| **先驗 > 環境 > 演算法** | LLM 一局通關 vs. Q-learning 10000 局 |
| **資料品質勝過數量** | 精修一萬條乾淨資料；示範雜訊會被忠實寫入 |
| **環境是 RL 的前置條件** | 影子世界、混合模擬、真實互動校準、訓練/評估隔離 |
| **on-policy 要在數值上成立** | 更新前比對 sampler/trainer log prob；保存 behavior log prob |
| **遮蔽不是自己生成的 token** | SFT 遮問題；RL 遮環境回饋 |
| **「通過 grader」≠「任務完成」** | reward seeking；隱藏測試、外部終止鉤子 |
| **非對稱驗證器** | 壞動作好偵測 → RLVP 懲罰路徑補回組內差異 |
| **先測訊號可達性** | 進展獎勵不可達就別加 |
| **稠密訊號勝過複雜獎勵** | On-Policy Distillation、OPSD |
| **邊界集 + 保留集** | 防過度矯正 |
| **逐層歸因再決定訓練** | 只有首差異在模型輸出才轉成訓練資料 |
| **小實驗先行** | 配比、格式、pass@k、數值一致性都先小規模驗證 |

| 13 ★★★ | 用 LLM 模擬環境訓練，可能出現哪些 reward hacking？如何防範？ | 行為：對模擬使用者**過度承諾、堆砌道歉與討好**（模擬使用者易被安撫、不追究兌現）；**編造模擬器不會核實的事實**；對模擬搜尋構造**誘導性 query** 走捷徑；冗長、模板化、「看起來專業」刷分；更隱蔽的是**策略縮進模擬器熟悉的分佈、迴避其盲區**。防範：**把獎勵錨定在可程式驗證的真實狀態**（任務完成、資料庫寫入、API 真實回傳），模擬器/評判者打分只作輔助並定期審計與真實結果的相關性，配合路徑約束；**有真實對應物的模擬器**（搜尋）走混合路線、用真實呼叫校準（ZeroSearch 課程式降質）；**模擬使用者**無法在訓練中引入真實使用者 → 用**線上 trace** 對比真實與模擬行為的系統性差異（真實使用者會追問、不耐煩、突然結束），持續校準；**線上真實指標是唯一的發布門檻**——模擬器裡分數再高都不算數 |

## 21. 本章重點整理

1. **四個部分**：預訓練（地基）→ Mid-training（專業課）→ SFT（示範與規範）→ RL（自己做題依結果改進）；分別處理**底座、協定、策略**。
2. 兩條主線：**本章對照實驗中 SFT 記憶、RL 泛化**（特定條件，非普遍）；**資料和環境比演算法更重要**。
3. **SFT 是換了資料、只在回答上算損失的 NTP**；固化協定而非事實。**LoRA**：全部主要矩陣（尤其 MLP）、學習率約 10 倍、SFT rank 64–256、RL 8–32 甚至 1。
4. **pass@k 診斷能力支持**：pass@1 低但 pass@k 隨 k 上升 → 可放大；pass@k 近零 → 先補底座。**RL 放大已有、不憑空創造**；強基模可跳過 SFT（R1-Zero）。
5. SFT vs. RL：極大似然 vs. 期望獎勵；**mass-covering vs. mode-seeking**；線上回饋的三個機會（示範外候選、驗證比生成容易、當前策略訪問的狀態——T² vs. T）；行動閾值是後訓練塑造的策略。
6. **先驗 > 環境 > 演算法**（Q-learning 10000 局 vs. LLM 一局 18 步）。
7. **Mid-training**：從失敗分布反推資料、高密度語料、能力配比（含 Agent 軌跡）、**雙重回放**、多維門禁；長上下文能力六類檢查；先小規模驗證配比。
8. **SFT 資料**：人工種子 → 教師放大 → 拒絕取樣拉齊；精修勝過堆量；**RFT**；開源教師就夠；Prompt 蒸餾與 CoT 蒸餾的取捨與代價。
9. **資料合成**：線上日誌 → 任務藍圖 → 虛構實例 → 任務驗證 + 軌跡驗證；失敗軌跡做偏好對而不當正確示範；訓練/評估按範本隔離。
10. **選擇準則表**：先排除不必改權重的方案 → 測能力支持 → SFT 立協定 → 有探索空間才 RL。
11. **單輪 RL**：AdaptThink（回應長度大降、難度一致路由、誠實記錄未完成的訓練）、**GeneralPoints**（RL 視覺 OOD +17.6% vs. SFT −9.9%；RL 改善了視覺編碼器）。
12. **GRPO 四步**（16 rollout → 驗證 → 組內相對優勢 → 梯度）；全敗/全勝時優勢消失；step 牆鐘由最慢 rollout 決定。
13. **On-policy 要在數值上成立**：推理引擎與訓練引擎的 log prob 不一致會把 on-policy 悄悄變成 off-policy；e^4 ≈ 54.6 的放大；更新前比對、保存 behavior log prob、對齊精度與佈局。
14. **環境**：影子世界、模型扮演環境（ZeroSearch、DreamGym）但模擬器偏差是天花板 → 混合與校準；訓練與評估共享生成器不共享題目；驗證器 worker 也是吞吐瓶頸。
15. **多輪與工具**：V-IRL（過程訊號加速）vs. SimpleVLA-RL（結果獎勵保留探索，發現「推切」）；**遮蔽環境返回的 token**；ReTool AIME 約 25% → 67%。
16. **獎勵設計**：RLVR 優先、RLHF/DPO 背景、GRM 診斷；**reward hacking vs. reward seeking**；ORM 換探索、PRM 換收斂；隱藏測試與邊界/保留集；別堆不可驗證的維度；**RLVP**：非對稱驗證器、懲罰路徑補回組內差異、先測訊號可達性。
17. **蒸餾**：**On-Policy Distillation**（學生決定走到哪、教師給逐 token 分布；約 1/10 步數；時間感任務 +23~47 pp）；**OPSD**（同一模型、特權資訊只在訓練側）。
18. **bad case → 後訓練**：評估資產對映到 RLVR/RFT/DPO/PRM/RLVP/GRM；過早結束（DPO + 邊界/保留雙集）、彎引號（Skill + 作用域 SFT）、精確複製（逐層歸因後 SFT；80.1% 也是 tokenizer 上限）。
19. **十一個陷阱**與「**小實驗先行**」；RAG、ICL、程式、Mid-training、SFT/RL、蒸餾各司其職，依據是**能力能否被外部符號充分表達**。

> **一句話**：後訓練不是「把模型再調一調」，而是先診斷缺的是底座、協定還是策略，再用對的資料與夠真的環境去改參數——RL 只能放大模型已經偶爾做得到的事，而讓它真正學會的，是稠密可信的訊號、在數值上真正成立的 on-policy、以及模型寫不了的驗證器。
