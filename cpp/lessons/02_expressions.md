# 第一部分：運算式是什麼

## 1.1 運算式 (Expression)

**白話**：由 **運算元 (operand)**（變數、字面值、函式呼叫）和 **運算子 (operator)**（`+`、`*`、`=`、`<<`……）組成，**算出一個值** 的東西。

```cpp
3 + 4            // 值是 7
x * 2            // 值是 x 的兩倍
f(a, b)          // 值是 f 的回傳值
x = 5            // 值是 x（賦值本身也是運算式！）
cout << "hi"     // 值是 cout 本身（所以才能一直串接 <<）
```

運算式加上分號 `;` 就變成 **運算式敘述**（第 03 課）。

## 1.2 副作用 (Side Effect)

**白話**：運算式除了算出一個值以外，**還改變了外面的東西**：修改變數、輸出、讀檔……

```cpp
x + 1        // 沒有副作用：只算出值，x 沒變
x++          // 有副作用：x 被改了
cout << x    // 有副作用：螢幕上多了東西
```

**比喻**：問路是「沒有副作用」的（對方告訴你答案，什麼都沒變）；請人幫你搬家是「有副作用」的（東西的位置真的變了）。

## 1.3 左值與右值 (Lvalue / Rvalue)

**白話**：
- **左值 (lvalue)**：有 **名字 / 有固定位置** 的東西，可以取位址 `&`，可以放在 `=` 左邊（除非是 const）。
- **右值 (rvalue)**：**暫時的值**，用完就消失，不能取位址。

```cpp
int x = 5;
x = 10;          // x 是左值 ✅
10 = x;          // ❌ 10 是右值，不能被賦值
(x + 1) = 3;     // ❌ x + 1 是暫時的值
int* p = &x;     // ✅ 左值可以取位址
int* q = &(x + 1);  // ❌
```

**比喻**：左值是「有地址的房子」，可以去那裡放東西；右值是「計算紙上的中間結果」，算完就丟掉了。

| 運算式 | 左值還是右值 |
|---|---|
| 變數名稱 `x` | 左值 |
| `++x`（前置） | **左值**（回傳 x 本身） |
| `x++`（後置） | **右值**（回傳舊值的複製品） |
| `*p` | 左值 |
| `a[i]` | 左值 |
| `x = 5` | 左值（回傳 x 本身） |
| `x + 1`、`42`、`f()`（回傳非參考） | 右值 |

🔍 C++11 之後更細分成 lvalue、xvalue、prvalue 三類，這是 **移動語意** 的基礎（第 06 課）。目前記住「有名字、能取位址的是左值」就夠了。

## 1.4 前置 vs 後置遞增 (Prefix vs Postfix)

```cpp
int i = 5;
int a = ++i;   // 先加再用：i = 6, a = 6
int b = i++;   // 先用再加：b = 6, i = 7
```

**比喻**：`++i` 是「先吃藥再上班」；`i++` 是「先上班，下班後再吃藥」——上班時的狀態是吃藥前的。

🔍 `i++` 要先 **複製一份舊值** 才能回傳，對 `int` 沒差別，但對迭代器、大型物件，`++i` 比較有效率。習慣寫 `++i`。

# 第二部分：優先順序與結合性

## 2.1 優先順序 (Precedence)

**白話**：一個運算式有好幾個運算子時，**誰比較「黏」**，誰就先跟旁邊的運算元綁在一起。

```cpp
1 + 2 * 3      // * 比 + 優先 → 1 + (2 * 3) = 7
```

**比喻**：數學的「先乘除後加減」。

## 2.2 結合性 (Associativity)

**白話**：**同樣優先順序** 的運算子連在一起時，從哪邊開始綁。

- **左結合**：從左邊開始。`10 - 4 - 3` = `(10 - 4) - 3` = 3。大部分運算子都是。
- **右結合**：從右邊開始。`a = b = c` = `a = (b = c)`。賦值、一元運算子、`?:` 是右結合。

```cpp
2 * 3 % 4      // 同優先順序，左結合：(2 * 3) % 4 = 2
a = b = 0;     // 右結合：先 b = 0，結果再給 a
-  -x          // 一元負號右結合：-(-x)
```

## 2.3 優先順序表（由高到低，常用的）

| 等級 | 運算子 | 結合性 |
|---|---|---|
| 1 | `a++` `a--` `f()` `a[i]` `.` `->` | 左 |
| 2 | `++a` `--a` `+a` `-a` `!` `~` `*p` `&x` `(type)` `sizeof` `new` `delete` | **右** |
| 3 | `*` `/` `%` | 左 |
| 4 | `+` `-` | 左 |
| 5 | `<<` `>>` | 左 |
| 6 | `<` `<=` `>` `>=` | 左 |
| 7 | `==` `!=` | 左 |
| 8 | `&`（位元 AND） | 左 |
| 9 | `^` | 左 |
| 10 | `|` | 左 |
| 11 | `&&` | 左 |
| 12 | `||` | 左 |
| 13 | `?:` `=` `+=` `-=` …… `throw` | **右** |
| 14 | `,`（逗號） | 左 |

**記法**：一元 > 乘除 > 加減 > 移位 > 比較 > 相等 > 位元 > 邏輯 > 賦值 > 逗號。

## 2.4 經典的優先順序陷阱

| 寫法 | 你以為 | 實際上 | 正確寫法 |
|---|---|---|---|
| `x & 1 == 0` | `(x & 1) == 0` | `x & (1 == 0)` → 永遠是 0 | `(x & 1) == 0` |
| `1 << 2 + 3` | `(1 << 2) + 3` = 7 | `1 << (2 + 3)` = 32 | 加括號 |
| `*p++` | `(*p)++`：值加 1 | `*(p++)`：指標往後移 | `(*p)++` |
| `!a == b` | `!(a == b)` | `(!a) == b` | `a != b` |
| `cout << a & b` | 印出 `a & b` | `(cout << a) & b` → 編譯錯誤 | `cout << (a & b)` |
| `cout << x > 0 ? "+" : "-"` | 印出符號 | `(cout << x) > 0 ? ...` → 編譯錯誤 | `cout << (x > 0 ? "+" : "-")` |
| `a < b < c` | `a < b` 且 `b < c` | `(a < b) < c`，`(a < b)` 是 0 或 1 | `a < b && b < c` |

**黃金規則**：**不確定就加括號**。括號不會讓程式變慢，只會讓程式更清楚。

### 🔍 C01 題的遞迴下降法

`C01` 要你自己寫一個運算式計算器。遞迴下降法的結構，剛好 **對應優先順序表**：

```
expr   = term   { ('+' | '-') term }           ← 優先順序低
term   = unary  { ('*' | '/' | '%') unary }
unary  = '-' unary | primary                   ← 右結合：自己呼叫自己
primary = 數字 | '(' expr ')'                   ← 優先順序最高
```

- 優先順序低的函式呼叫優先順序高的函式 → 高的先綁定。
- `while` 迴圈一直往右吃同等級的運算子，算完一個馬上合併 → 左結合。
- `unary` 呼叫自己 → 右結合。

# 第三部分：求值順序

## 3.1 優先順序 ≠ 求值順序 (Evaluation Order)

**白話**：優先順序只決定 **怎麼加括號**，**不決定哪個運算元先被計算**。

```cpp
int r = f() + g() * h();
// 優先順序：f() + (g() * h())
// 但 f()、g()、h() 哪個先被呼叫？C++ 沒有規定！
```

如果 `f`、`g`、`h` 都會印東西，不同的編譯器可能印出不同的順序。這叫 **未指定行為 (unspecified behavior)**：結果是幾種可能之一，但不知道是哪一種。

**比喻**：「蛋糕 = 麵粉 + 蛋 × 2」規定了配方的結構，但沒有規定你要先去拿麵粉還是先去拿蛋。

## 3.2 未定義行為：同一個變數在同一個運算式裡被改兩次

```cpp
int i = 1;
int a = i++ + i++;      // ❌ 未定義行為
int b = i + i++;        // ❌ 未定義行為（一邊讀、一邊改，沒有先後規定）
f(i++, i++);            // ⚠️ C++17 前是未定義行為；C++17 後是未指定順序
```

**未定義行為 (Undefined Behavior, UB)** 比「未指定」更嚴重：編譯器可以假設它 **永遠不會發生**，於是產生的程式可能做出任何事。

**規則**：**在一個運算式裡，不要修改同一個變數超過一次，也不要一邊修改、一邊在別的地方讀它。**

## 3.3 C++17 新增的順序保證

C++17 規定了一些常見寫法的順序，讓它們變成安全的：

| 寫法 | 保證 |
|---|---|
| `cout << a << b << c` | 由左到右 |
| `a = b`（含 `+=` 等） | **右邊** 先算完，再處理左邊 |
| `a[b]`、`a.b`、`a->b` | `a` 先算 |
| `a && b`、`a || b`、`a , b` | `a` 先算（這個一直都有保證） |

但 `f() + g()`、函式的多個參數之間，**仍然沒有規定順序**。

## 3.4 序列點的實用版：什麼時候「一定已經完成」

- 分號 `;` 結束時，所有副作用都完成了。
- `&&`、`||`、`?:`、逗號運算子：左邊算完（含副作用）才算右邊。
- 呼叫函式前，所有參數都算好了。

# 第四部分：算術的細節

## 4.1 整數除法與取餘數

```cpp
7 / 2     // 3（截掉小數）
-7 / 2    // -3（向 0 取整，不是 -4）
-7 % 2    // -1（正負號跟被除數一樣）
7 % -2    // 1
```

永遠成立：`(a / b) * b + a % b == a`。

| 語言 | `-7 / 2` | `-7 % 2` |
|---|---|---|
| C++、Java、C# | -3 | -1 |
| Python | -4（向下取整） | 1 |

想要「數學上的」非負餘數：`((a % m) + m) % m`。

**除以 0**：整數除以 0 或 `% 0` 是 **未定義行為**（通常程式直接當掉，SIGFPE）。

## 4.2 整數溢位 (Integer Overflow)

| | 有號 (`int`, `long long`) | 無號 (`unsigned`) |
|---|---|---|
| 超出範圍時 | **未定義行為** | **定義好的**：自動繞回（對 `2ⁿ` 取模） |

```cpp
unsigned int u = 0;
u - 1;                 // 4294967295，定義好的
int x = INT_MAX;
x + 1;                 // ❌ 未定義行為！不一定會變成 INT_MIN
```

🔍 **為什麼有號溢位是 UB 這麼重要？** 編譯器會假設它不會發生，然後做最佳化：

```cpp
bool check(int x) { return x + 1 > x; }   // 編譯器可能直接最佳化成 return true;
```

所以「先算，再檢查有沒有溢位」的寫法是錯的（`C13` 題的陷阱）。要在算之前檢查：

```cpp
if (b > 0 && a > LLONG_MAX - b) → 會溢位
// 或用 GCC 內建函式
long long r;
if (__builtin_add_overflow(a, b, &r)) → 會溢位
```

特殊情況：`LLONG_MIN / -1` 和 `LLONG_MIN % -1` 都會溢位（後者在數學上是 0，但 CPU 會當掉）。

## 4.3 浮點數誤差 (Floating-point Error)

**白話**：`double` 用 **二進位** 存小數，很多十進位小數（例如 0.1）**無法精確表示**，只能存近似值。

**比喻**：用十進位寫 1/3 = 0.3333...，永遠寫不完；二進位寫 0.1 也是同樣的情況。

```cpp
cout << (0.1 + 0.2 == 0.3);          // 0（false）！
cout << setprecision(17) << 0.1 + 0.2;  // 0.30000000000000004

// 比較浮點數要用誤差範圍 (epsilon)
bool eq = fabs(a - b) < 1e-9;
```

其他規則：
- `double` 大約有 **15~16 位有效數字**；`float` 只有 7 位左右，**盡量用 `double`**。
- `1.0 / 0` 是 `inf`（無限大），`0.0 / 0` 是 `NaN`（不是數字）。`NaN` 跟任何值比較都是 `false`，連 `NaN == NaN` 也是。
- 大整數轉成 `double` 會失去精度：`(double)(1LL << 53) + 1 == (double)(1LL << 53)`。

# 第五部分：邏輯運算與短路

## 5.1 短路求值 (Short-circuit Evaluation)

**白話**：
- `a && b`：如果 `a` 是 `false`，結果一定是 `false`，**`b` 根本不會被計算**。
- `a || b`：如果 `a` 是 `true`，結果一定是 `true`，**`b` 不會被計算**。

**比喻**：「有駕照 **而且** 有車才能開車出門」—— 沒駕照就不用去車庫看有沒有車了。

這不只是效率問題，**更是安全問題**：

```cpp
if (p != nullptr && p->val > 0)           // p 是空的話，不會去存取 p->val
if (i < n && a[i] == x)                   // i 越界的話，不會去讀 a[i]
if (!st.empty() && st.top() == '(')       // 空的話，不會呼叫 top()
```

**順序很重要**：把「保護條件」放在 **左邊**。寫成 `a[i] == x && i < n` 就沒有保護效果了。

> ⚠️ 位元運算子 `&`、`|` **沒有短路**，兩邊都會算。`if (p != nullptr & p->val > 0)` 一樣會當掉。

## 5.2 轉成 bool

在需要 `bool` 的地方（`if`、`while`、`&&`……），**0、空指標是 `false`，其他都是 `true`**。

```cpp
if (n) ...          // n != 0
if (p) ...          // p != nullptr
if (cin >> x) ...   // 讀取成功
```

## 5.3 條件運算子 (Conditional / Ternary Operator)

```cpp
int m = (a > b) ? a : b;
```

唯一的三元運算子。兩個結果的型別要能轉成同一種：`cond ? 1 : 2.5` 的型別是 `double`，所以就算選到 `1`，結果也是 `1.0`。

# 第六部分：位元運算 (Bitwise Operations)

## 6.1 六個位元運算子

| 運算子 | 名稱 | 規則（每一位分別算） | 例：`a = 1100₂`, `b = 1010₂` |
|---|---|---|---|
| `&` | AND | 兩個都是 1 才是 1 | `1000` |
| `|` | OR | 有一個是 1 就是 1 | `1110` |
| `^` | XOR | 不一樣才是 1 | `0110` |
| `~` | NOT | 0 變 1、1 變 0 | `~a` = `...11110011` |
| `<<` | 左移 | 全部往左移，右邊補 0 | `a << 1` = `11000` |
| `>>` | 右移 | 全部往右移 | `a >> 2` = `11` |

**比喻**：一整排電燈開關，每個運算子都是「一個一個開關分別處理」的規則。

- `x << k` 等於 `x × 2ᵏ`；`x >> k`（非負數）等於 `x / 2ᵏ`。

## 6.2 常用技巧

| 目的 | 寫法 |
|---|---|
| 判斷奇偶 | `x & 1` |
| 第 `k` 位是不是 1 | `(x >> k) & 1` |
| 把第 `k` 位設成 1 | `x | (1ULL << k)` |
| 把第 `k` 位設成 0 | `x & ~(1ULL << k)` |
| 反轉第 `k` 位 | `x ^ (1ULL << k)` |
| 清掉最低的 1 | `x & (x - 1)` |
| 只留最低的 1 | `x & -x` |
| 是不是 2 的次方 | `x != 0 && (x & (x - 1)) == 0` |
| 交換兩數（不用暫存） | `a ^= b; b ^= a; a ^= b;`（只是好玩，實務用 `swap`） |

## 6.3 移位的未定義行為

| 寫法 | 問題 |
|---|---|
| `1 << 31`（`int` 是 32 位元） | C++20 前是 UB（移進符號位） |
| `1 << 32`、`x >> 64` | **移位量 ≥ 型別位元數**：UB |
| `x << -1` | 移位量是負數：UB |
| 負數 `>> k` | C++20 前由編譯器決定；C++20 起是算術右移（補符號位） |

**規則**：做位元運算時 **一律用無號型別**，而且常數寫成 `1ULL << k`。`C02` 題的 `rotl x 0` 就是在測「`x >> 64`」這個陷阱。

```cpp
a) 2 + 3 * 4 % 5
b) 10 - 2 - 3 * 2
c) 1 << 1 + 1
d) 7 & 3 == 3
e) -7 / 2 * 2 + -7 % 2
```

### 題 2：哪些是未定義行為？

```cpp
a) i = i + 1;
b) i = i++ + 1;
c) a[i] = i++;
d) x = y++ + y++;
e) cout << i << i++;
f) f(i++, i);
```

### 題 3：預測輸出

```cpp
int x = 5;
int y = x++ * 2;
int z = ++x * 2;
cout << x << ' ' << y << ' ' << z;
```

### 題 4：找 bug

```cpp
bool is_even(int x) {
    return x & 1 == 0;
}
```

### 題 5：下面兩段程式，哪個安全？

```cpp
// A
if (v[i] > 0 && i < (int)v.size()) ...
// B
if (i < (int)v.size() && v[i] > 0) ...
```

### 題 6：預測輸出

double a = 0.1 * 3;
cout << (a == 0.3) << ' ' << (fabs(a - 0.3) < 1e-9);

### 題 8：`x = 0b10110100`（無號 8 位元），算出

```
a) x & (x - 1)
b) x & -x
c) x ^ (1 << 2)
d) (x >> 4) & 0xF
```

---

# 習題解答

**題 1**：
- a) `2 + ((3 * 4) % 5)` = `2 + 2` = **4**
- b) `(10 - 2) - (3 * 2)` = **2**
- c) `1 << (1 + 1)` = **4**
- d) `7 & (3 == 3)` = `7 & 1` = **1**
- e) `((-7 / 2) * 2) + (-7 % 2)` = `(-3 * 2) + (-1)` = **-7**（剛好驗證 `(a/b)*b + a%b == a`）

**題 2**：
- a) 安全。
- b) **C++17 起有定義**（右邊先完全算完，包括 `i++` 的副作用，再賦值），結果是舊的 `i + 1`；C++17 前是 UB。實務上 **不要這樣寫**。
- c) C++17 起有定義（右邊先算）；C++17 前是 UB。同樣不要寫。
- d) **UB**：`y` 在同一個運算式裡被改兩次。
- e) C++17 起有定義（`<<` 由左到右），印出 `i` 再印 `i`（舊值），之後 `i` 加 1。
- f) **未指定**：參數的計算順序不確定，`f` 拿到的第二個參數可能是加之前或加之後的值（C++17 起不是 UB，但結果不確定）。

**題 3**：`7 10 14`。`y = 5 * 2`（之後 x = 6）；`++x` 讓 x = 7，`z = 7 * 2`。

**題 4**：`==` 的優先順序比 `&` 高，變成 `x & (1 == 0)` = `x & 0` = 0，永遠回傳 `false`。改成 `(x & 1) == 0`。

**題 5**：**B** 安全。`&&` 由左到右短路，B 先確認 `i` 沒越界才讀 `v[i]`；A 先讀 `v[i]`，越界時已經出事了。

**題 6**：`0 1`。`0.1 * 3` 是 `0.30000000000000004`，不等於 `0.3`，但差距小於 `1e-9`。

**題 7**：有號整數溢位是 **未定義行為**，`a + b` 一旦溢位，`r < 0` 的檢查不一定有效（編譯器可能把它最佳化掉）；而且只檢查了正數，沒檢查兩個負數相加的情況。要在相加 **之前** 檢查：

```cpp
if ((b > 0 && a > LLONG_MAX - b) || (b < 0 && a < LLONG_MIN - b)) throw overflow_error("overflow");
```

或用 `__builtin_add_overflow(a, b, &r)`。

**題 8**：`x = 1011 0100₂`（180）
- a) 清掉最低的 1：`1011 0000₂` = **176**
- b) 只留最低的 1：`0000 0100₂` = **4**
- c) 反轉第 2 位（原本是 1）：`1011 0000₂` = **176**
- d) 取高 4 位：`1011₂` = **11**
