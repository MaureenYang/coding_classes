# 第一部分：核心想法

## 1.1 鍵 / 值 (Key / Value)

**白話**：
- **key（鍵）**：用來 **查詢** 的東西，不能重複。
- **value（值）**：key 對應到的 **資料**。

**比喻**：字典。「單字」是 key，「解釋」是 value。電話簿：「姓名」是 key，「電話號碼」是 value。

## 1.2 直接定址表 (Direct-Address Table)

如果 key 是 `0 ~ 999` 的整數，最簡單的做法是開一個大小 1000 的陣列：

```cpp
int table[1000];
table[key] = value;    // O(1)
```

但如果 key 可能是 `10¹⁸`，或是字串 `"apple"` —— 不可能開那麼大的陣列。

## 1.3 雜湊函數 (Hash Function)

**白話**：一個函數 `h(key)`，把 **任意的 key** 轉換成 **`0 ~ M-1` 之間的整數**（`M` 是陣列大小）。

**比喻**：圖書館的分類號。書名千奇百怪，但每本書都能被歸到「000 ~ 999」中的某一類，照分類號就能找到對應的書架。

```
key = 1234567       →  h(key) = 1234567 % 8 = 7
key = "apple"       →  h(key) = （把字元算成數字再運算）% 8 = 3
```

一個好的雜湊函數要：
1. **算得快**（`O(1)` 或 `O(key 的長度)`）。
2. **同一個 key 永遠算出同一個值**。
3. **把不同的 key 平均分散** 到 `0 ~ M-1`。

## 1.4 桶子 (Bucket) 與雜湊表 (Hash Table)

**白話**：雜湊表就是一個大小 `M` 的陣列，每一格叫做一個 **桶子**。key 經過雜湊函數算出要放在哪個桶子。

```
put("apple", 5)：h("apple") = 3 → 放到 bucket[3]
get("apple")：   h("apple") = 3 → 去 bucket[3] 找
```

查詢時不用一個一個比對所有資料，**直接算出位置** → 平均 `O(1)`。

# 第二部分：碰撞處理

## 2.1 碰撞 (Collision)

**白話**：兩個 **不同的** key 被雜湊函數算到 **同一個** 桶子。

**比喻**：兩個人被分配到同一個置物櫃。

碰撞一定會發生：key 的可能性遠比桶子多（**鴿籠原理 Pigeonhole Principle**：10 隻鴿子放進 9 個籠子，一定有一個籠子裝了 2 隻以上）。所以問題不是「怎麼避免碰撞」，而是「碰撞了怎麼辦」。

## 2.2 分離鏈結法 (Separate Chaining)

**白話**：每個桶子不是只放一筆資料，而是放 **一條串列**（或一個小 `vector`）。碰撞的資料就排在同一條串列裡。

**比喻**：每個置物櫃裡放一個小籃子，同一櫃的人把東西都放在籃子裡。

```
bucket[0]: → (16, "a") → (8, "b")
bucket[1]: → (9, "c")
bucket[2]:
bucket[3]: → (3, "d") → (11, "e") → (19, "f")
```

```cpp
vector<vector<pair<ll,ll>>> buckets(M);

void put(ll k, ll v) {
    auto& b = buckets[index(k)];
    for (auto& e : b)
        if (e.first == k) { e.second = v; return; }   // 已存在：更新
    b.push_back({k, v});                              // 不存在：新增
}

bool get(ll k, ll& out) {
    for (auto& e : buckets[index(k)])
        if (e.first == k) { out = e.second; return true; }
    return false;
}
```

查詢時間 = 算雜湊 `O(1)` + 掃那個桶子的長度。桶子越短越快。

## 2.3 開放定址法 (Open Addressing)

**白話**：每個桶子只放一筆資料。碰撞時就 **往後找下一個空的桶子**。

**線性探測 (Linear Probing)**：`h(k)` 被佔了就試 `h(k)+1`、`h(k)+2` ……

**比喻**：停車場。你的車位被佔了，就往旁邊找下一個空位。找車時也從原本的車位開始往旁邊找。

| | 分離鏈結法 | 開放定址法 |
|---|---|---|
| 實作 | 簡單 | 稍難 |
| 速度 | 稍慢（要跟著串列跳） | 快（記憶體連續，快取友善） |
| 刪除 | 簡單 | 麻煩：不能直接清空，要放 **墓碑 (tombstone)** 標記「這裡曾經有東西」，不然後面的資料會找不到 |

`std::unordered_map` 用的是分離鏈結法。

# 第三部分：負載因子與擴容

## 3.1 負載因子 (Load Factor)

**白話**：`α = 元素個數 n / 桶子數 M`，也就是「平均每個桶子裝幾筆資料」。

- `α` 小 → 桶子都很短 → 查詢快，但浪費空間。
- `α` 大 → 桶子很長 → 查詢變慢。

只要 `α` 保持在一個常數以下（例如 `≤ 1`），而且雜湊函數分散得好，每個操作就是 **平均 `O(1)`**。

**比喻**：餐廳的座位。客人太少，大部分桌子空著；客人太多，每桌都擠到要併桌，點餐上菜都變慢。

## 3.2 重新雜湊 (Rehashing)

**白話**：元素太多（`α` 超過門檻）時，把桶子數 **加倍**，然後把所有元素 **重新算雜湊、重新放一次**（因為 `M` 變了，`h(k) % M` 也變了）。

這跟 `vector` 的擴容一樣：偶爾一次 `O(n)`，但 **攤銷** 下來每次插入還是 `O(1)`。

```cpp
unordered_map<int,int> mp;
mp.reserve(1 << 20);   // 預先準備足夠的桶子，避免中途多次 rehash
```

# 第四部分：好的雜湊函數

## 4.1 陷阱 1：負數取餘數

C++ 的 `%` 對負數會得到 **負數**：

```cpp
ll k = -7;
k % 8;            // == -7，拿去當陣列索引 → 越界！
(ull)k % 8;       // 先轉成無號數再取餘數 → 一定在 0 ~ 7
((k % 8) + 8) % 8; // 另一種寫法 → 1
```

`10_hash_table` 題的 `corner_negative_keys` 就是在測這個。

## 4.2 陷阱 2：key 有規律 → 全部擠在同一桶

假設 `M = 1024`，雜湊函數是 `k % 1024`。如果所有 key 都是 1024 的倍數：

```
1024 % 1024 = 0
2048 % 1024 = 0
3072 % 1024 = 0
...           全部在 bucket[0]
```

所有資料擠在同一條串列裡，雜湊表 **退化成一條串列**，每次查詢 `O(n)`，`n` 次操作就是 `O(n²)`。

**比喻**：圖書館如果用「書名的第一個字」分類，結果某個系列的書全叫「哈利波特 ……」，全部擠在同一個書架上，其他書架都空著。

現實中的資料 **常常有規律**（ID 都是 1000 的倍數、記憶體位址都是 8 的倍數 ……）。
`10_hash_table` 的 `anti_power_of_two`、`anti_prime_buckets` 測資就是故意設計來卡這種寫法的。

## 4.3 雜湊攻擊 (Hash Collision Attack / Hash DoS)

**白話**：如果別人 **知道你的雜湊函數**，就能故意構造一大堆會碰撞的 key，讓你的程式變超慢。

這在真實世界發生過：2011 年許多網站伺服器被這樣攻擊，只送一個特製的請求就讓伺服器卡住好幾分鐘。在程式競賽中，也常有人故意出測資卡別人的雜湊表。

## 4.4 解法：把位元充分打亂

先把 key 的每個位元 **攪亂**，讓「有規律的 key」也能平均分散。常用的 **splitmix64**：

```cpp
static ull mix(ull x) {
    x += 0x9e3779b97f4a7c15ULL;
    x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9ULL;
    x = (x ^ (x >> 27)) * 0x94d049bb133111ebULL;
    return x ^ (x >> 31);
}
size_t index(ll key) { return mix((ull)key) & (M - 1); }
```

- `^` 是 **XOR（互斥或）**，`>>` 是 **右移**：把高位的資訊混到低位。
- 乘上大奇數：讓每個位元影響很多其他位元。
- `& (M - 1)`：當 `M` 是 2 的次方時，等於 `% M`，但比較快。

要防攻擊的話，再加上一個 **程式啟動時隨機決定** 的數（別人無法事先知道）：

```cpp
static const ull SEED = chrono::steady_clock::now().time_since_epoch().count();
size_t index(ll key) { return mix((ull)key + SEED) & (M - 1); }
```

**比喻**：洗牌。新的一副牌是照順序排的（有規律），洗過之後就分散開了。每次洗法都不一樣，別人就無法預測。

# 第五部分：STL 怎麼用

## 5.1 unordered_map / unordered_set

```cpp
unordered_map<string, int> cnt;
cnt["apple"]++;                   // 不存在會自動建立（值為 0）再 +1
if (cnt.count("pear")) ...        // 是否存在（0 或 1），不會建立
auto it = cnt.find("apple");
if (it != cnt.end()) cout << it->second;
cnt.erase("apple");

unordered_set<int> seen;          // 只有 key，沒有 value
seen.insert(5);
if (seen.count(5)) ...
```

> ⚠️ **`mp[key]` 在 key 不存在時會插入一筆**（值是預設的 0 或空字串）。
> 只想「查詢有沒有」時，用 `count` 或 `find`。不然雜湊表會越查越大，`size()` 也會不對。

## 5.2 unordered_map vs map

| | `unordered_map` | `map` |
|---|---|---|
| 底層 | 雜湊表 | 紅黑樹（一種平衡 BST，第 08 課） |
| 查詢 / 插入 / 刪除 | **平均** `O(1)`，最壞 `O(n)` | **保證** `O(log n)` |
| 有排序嗎？ | 沒有，走訪順序看起來是亂的 | 有，依 key 由小到大 |
| 能找「比 x 大的最小 key」？ | 不行 | 可以，`lower_bound` / `upper_bound` |
| key 的要求 | 要能雜湊（自訂型別要自己寫雜湊函數） | 要能比大小 |

**怎麼選？** 只需要「有沒有、是多少」→ `unordered_map`。需要 **順序**、**範圍**、**前一個 / 後一個** → `map`。

# 小測驗

1. `M = 10`，雜湊函數 `h(k) = k % 10`。依序插入 `13, 23, 7, 33`，用分離鏈結法，每個桶子的內容是什麼？
2. 雜湊表有 1000 個元素、500 個桶子，負載因子是多少？
3. 為什麼 `(-13) % 10` 不能直接當陣列索引？要怎麼改？
4. 所有 key 都是 1024 的倍數，`M = 1024`，雜湊函數 `k % M`。插入 `10⁵` 個 key 再查詢 `10⁵` 次，大約要比對幾次？
5. 下面的程式想印出 `cnt` 裡有幾個 key，結果是多少？

```cpp
unordered_map<int,int> cnt;
cnt[1] = 5;
if (cnt[2] > 0) cout << "yes\n";
cout << cnt.size() << '\n';
```

6. 要找「所有 key 中，第一個大於等於 50 的 key」，該用 `unordered_map` 還是 `map`？

### 答案

1. `bucket[3]: 13 → 23 → 33`，`bucket[7]: 7`，其他桶子都是空的。（`13`、`23`、`33` 除以 10 都餘 3，全部碰撞。）
2. `1000 / 500 = 2`，平均每個桶子 2 筆。
3. C++ 中 `(-13) % 10 == -3`，負數索引會越界。改成 `((k % M) + M) % M`，或先轉成無號數 `(unsigned long long)k % M`。
4. 全部擠在 `bucket[0]`。插入第 `i` 個要先掃過前面 `i` 個（檢查是否已存在），總共約 `10¹⁰ / 2`；每次查詢最壞掃 `10⁵` 個，又 `10¹⁰`。總共約 `1.5 × 10¹⁰` 次 → TLE。
5. 印出 **2**。`cnt[2]` 在 key 2 不存在時會 **自動插入** `{2, 0}`。應該寫 `cnt.count(2) && cnt[2] > 0`，或用 `find`。
6. `map`。`unordered_map` 沒有順序，只能全部掃一遍；`map` 可以用 `lower_bound(50)`，`O(log n)`。
