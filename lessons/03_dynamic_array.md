# 第一部分：陣列的特性

## 1.1 連續記憶體 (Contiguous Memory)

**白話**：陣列的元素在記憶體中 **一個緊接著一個** 排好，中間沒有空隙。

```
索引:    0    1    2    3    4
       +----+----+----+----+----+
data → | 12 |  7 | 33 | -4 |  9 |
       +----+----+----+----+----+
位址:  1000 1004 1008 1012 1016     （int 佔 4 bytes）
```

**比喻**：一排編好號的連棟透天厝，門牌是連續的。

## 1.2 隨機存取 (Random Access)

**白話**：**不管要第幾個，都一樣快**（`O(1)`）。「隨機」的意思是「任意指定一個位置」，不是「隨便亂選」。

因為記憶體連續，第 `i` 個元素的位址可以 **直接算出來**：

```
a[i] 的位址 = 起點位址 + i × 每個元素的大小
a[3] 的位址 = 1000 + 3 × 4 = 1012
```

**比喻**：連棟透天厝要找第 300 號，直接走到「起點 + 300 間」的位置就到了，不用一間一間數。
相反地，鏈結串列（第 04 課）就像尋寶遊戲：每一站只告訴你下一站在哪，要找第 300 站就得走過前面 299 站。

## 1.3 陣列的缺點

| 缺點 | 為什麼 |
|---|---|
| **大小固定** | `int a[100]` 宣告完就不能變大 |
| **中間插入 / 刪除很慢 `O(n)`** | 要把後面的元素全部往後（或往前）搬一格，才能保持連續 |

```
在索引 1 插入 99：
before: [12,  7, 33, -4,  9]
         後面 4 個都要往右搬一格 →
after:  [12, 99,  7, 33, -4,  9]
```

**比喻**：電影院一整排坐滿了人，要在第 2 個位置插進一個人，後面每個人都得往旁邊挪一格。

# 第二部分：動態陣列的原理

## 2.1 動態陣列 (Dynamic Array)

**白話**：會 **自動變大** 的陣列。C++ 的 `std::vector` 就是動態陣列。
它保留了陣列「`O(1)` 隨機存取」的優點，解決了「大小固定」的缺點。

做法很簡單：**空間不夠時，換一塊更大的連續記憶體，把舊資料搬過去。**

## 2.2 大小 vs 容量 (Size vs Capacity)

動態陣列內部記錄三個東西：

| 成員 | 意思 |
|---|---|
| `data` | 指向一塊用 `new[]` 配置的記憶體 |
| `size` | 目前 **實際放了** 幾個元素 |
| `capacity` | 這塊記憶體 **最多能放** 幾個元素 |

```
size = 3, capacity = 4
+----+----+----+----+
|  5 |  7 |  9 |  ? |    ← 第 4 格已經配置好了，只是還沒放東西
+----+----+----+----+
```

永遠滿足 `size ≤ capacity`。

**比喻**：一個書架有 4 格（capacity），目前放了 3 本書（size）。還有空位時直接放；放滿了就得換一個更大的書架。

```cpp
vector<int> v;
v.reserve(100);
cout << v.size();       // 0：還沒放任何東西
cout << v.capacity();   // 100：但已經預留了 100 格
```

## 2.3 擴容 / 重新配置 (Reallocation)

**白話**：容量滿了還要加東西時，做三件事：

1. 配置一塊 **更大** 的新記憶體。
2. 把舊資料 **全部複製** 過去。
3. **釋放** 舊記憶體。

```cpp
void push_back(int x) {
    if (size_ == cap_) {                    // 滿了
        int ncap = max(1, cap_ * 2);        // 新容量：加倍（0 要變 1）
        int* nd = new int[ncap];            // 1. 配置新空間
        for (int i = 0; i < size_; i++)     // 2. 複製舊資料
            nd[i] = data_[i];
        delete[] data_;                     // 3. 釋放舊空間
        data_ = nd;
        cap_ = ncap;
    }
    data_[size_++] = x;                     // 放進去
}
```

**比喻**：搬家。書架放滿了，買一個兩倍大的新書架，把書一本一本搬過去，舊書架丟掉。
搬家很累（`O(n)`），但搬完之後可以放很久。

> 注意 `max(1, cap_ * 2)`：一開始容量是 0，`0 × 2` 還是 0，永遠放不進東西。這是很常見的 bug。

## 2.4 pop_back 要不要縮小？

`pop_back` 只要 `size--` 就好，**不用真的清掉資料**，也 **不縮小容量**。

如果「`size` 降到 `capacity` 的一半就縮小一半」，會發生 **抖動 (thrashing)**：
剛好在邊界上反覆 push、pop，每一次都觸發搬家，每次都是 `O(n)`。

**比喻**：家裡東西剛好塞滿房子。丟一件就搬去小房子、買一件又搬回大房子 —— 整天都在搬家。

常見的做法：`size` 降到 `capacity` 的 **1/4** 才縮小一半，或乾脆不自動縮（`std::vector` 就不會自動縮，要手動呼叫 `shrink_to_fit()`）。

# 第三部分：為什麼要加倍？攤銷分析

## 3.1 兩種擴容策略比較

假設從空的開始 push `n` 個元素，數總共要 **複製** 幾次資料：

**策略 A：每次只多 1 格（或固定 k 格）**

每一次 push 都要搬家（或每 k 次搬一次），第 `i` 次搬 `i` 個元素：

```
總複製次數 = 1 + 2 + 3 + ... + n = n(n+1)/2  →  O(n²)
```

**策略 B：每次加倍**

只有在容量是 `1, 2, 4, 8, ...` 時才搬家：

```
總複製次數 = 1 + 2 + 4 + 8 + ... + n < 2n  →  O(n)
```

| `n` | 策略 A（+1） | 策略 B（×2） |
|---|---|---|
| 1,000 | 50 萬次 | 不到 2,000 次 |
| 1,000,000 | 5 × 10¹¹ 次（好幾小時） | 不到 200 萬次（瞬間） |

## 3.2 攤銷 O(1) (Amortized O(1))

**白話**：雖然 **偶爾** 有一次 push 很慢（`O(n)`，要搬家），但 `n` 次 push **加起來** 只有 `O(n)`，**平均每次** 是 `O(1)`。這叫「攤銷 `O(1)`」。

**比喻**：一年繳一次保險費 12,000 元，那一天很痛，但攤到每個月只有 1,000 元。

> 攤銷 vs 平均：「平均」通常是指 **隨機輸入** 的期望值；「攤銷」是指 **任何一串操作** 加起來的總成本除以次數，**不靠運氣**，最壞情況也成立。

## 3.3 存錢的想法（Accounting Method，記帳法）

另一種理解方式：每次 push **多付 3 塊錢**：

- 1 塊付給「把自己放進去」。
- 2 塊 **存起來**，留給以後搬家用。

容量從 `k` 變成 `2k` 時，要搬 `k` 個元素（花 `k` 塊）。
上一次搬家之後新放進來的 `k/2` 個元素，每個都存了 2 塊，剛好 `k` 塊 —— **錢永遠夠用**。
所以每次 push 固定付 3 塊錢就夠了 → `O(1)`。

> 加倍不是唯一選擇。GCC 的 `vector` 用 2 倍，MSVC 用 1.5 倍。只要是 **乘以一個大於 1 的常數**，攤銷就是 `O(1)`；**加上一個常數**（+1、+10、+1000）就一定是 `O(n²)`。

# 第四部分：實作細節與陷阱

## 4.1 三法則 (Rule of Three)

**白話**：如果你的 class 自己用 `new` 管理記憶體，通常要自己寫三樣東西：

1. **解構子** `~MyVector()`：`delete[]` 掉記憶體。
2. **複製建構子** `MyVector(const MyVector&)`：做 **深複製**。
3. **複製指定運算子** `operator=`：也要做深複製。

**淺複製 vs 深複製 (Shallow Copy vs Deep Copy)**：

- **淺複製**：只複製指標 → 兩個物件指向 **同一塊** 記憶體。改一個，另一個也被改；兩個都解構時 `delete[]` 同一塊兩次（**double free**）→ 程式當掉。
- **深複製**：配置一塊 **新的** 記憶體，把內容複製過去 → 兩個物件各自獨立。

**比喻**：淺複製是給朋友一把你家的備份鑰匙（同一間房子）；深複製是幫朋友蓋一間一模一樣的房子。

C++ 預設的複製是淺複製。練習題只用到一個物件，寫解構子就夠了；寫正式程式時要注意。

## 4.2 迭代器 / 指標失效 (Iterator Invalidation)

**白話**：`push_back` 如果觸發搬家，**所有指向舊元素的指標、參考、迭代器都會失效**（它們指向已經被釋放的舊記憶體）。

**比喻**：朋友記了你舊家的地址，你搬家之後他照舊地址去找，找到的是空屋（或別人家）。

```cpp
vector<int> v = {1, 2, 3};
int& first = v[0];      // 參考到 v[0]
v.push_back(4);         // 可能觸發搬家！
cout << first;          // ❌ 未定義行為：first 指向舊的、已釋放的記憶體

// 安全做法：存「索引」而不是指標
int idx = 0;
v.push_back(5);
cout << v[idx];         // ✅
```

另一個常見錯誤：一邊用迭代器走訪 `vector`，一邊 `push_back` 或 `erase`。

## 4.3 vector 各操作的複雜度

| 操作 | 寫法 | 複雜度 |
|---|---|---|
| 存取第 i 個 | `v[i]`、`v.at(i)` | `O(1)` |
| 尾端加入 | `push_back`、`emplace_back` | 攤銷 `O(1)` |
| 尾端刪除 | `pop_back` | `O(1)` |
| 中間 / 開頭插入 | `insert(v.begin() + i, x)` | `O(n)` |
| 中間 / 開頭刪除 | `erase(v.begin() + i)` | `O(n)` |
| 搜尋某個值 | `find(v.begin(), v.end(), x)` | `O(n)` |
| 預留空間 | `reserve(k)` | `O(n)`（只做一次搬家） |

`v[i]` 不檢查越界；`v.at(i)` 會檢查，越界時丟出例外（比較慢，但除錯時好用）。

## 4.4 小技巧：O(1) 刪除（不在乎順序時）

如果 **不需要保持順序**，刪除第 `i` 個可以用「和最後一個交換，再 `pop_back`」：

```cpp
swap(v[i], v.back());
v.pop_back();          // O(1)，但順序被打亂了
```

`10_hash_table` 的標準解在桶子裡刪除時就用了這招。

## 4.5 Corner case checklist

- 空陣列 `pop` / `get`。
- 索引是 **負數**：用 `int` 接要檢查 `i < 0`；用 `size_t`（無號）接時，`-1` 會變成超大的數字。
- 容量從 0 開始，第一次 push 要變成 1。
- 搬家後要 `delete[]` 舊記憶體（不然 memory leak），而且不能再用舊指標。
- `pop` 之後 `capacity` 不變。

# 小測驗

1. 為什麼陣列存取第 `i` 個元素是 `O(1)`，而鏈結串列是 `O(i)`？
2. 一個 `vector` 的 `size = 5`、`capacity = 8`。再 push 4 個元素後，`size` 和 `capacity` 各是多少？（容量規則：加倍）
3. 容量規則改成「每次 +100」，push `10⁶` 個元素大約要複製幾次？會不會 TLE？
4. 下面的程式有什麼問題？

```cpp
vector<int> v = {1, 2, 3};
for (auto it = v.begin(); it != v.end(); ++it)
    if (*it == 2) v.push_back(4);
```

5. 為什麼 `pop_back` 不要在 `size < capacity / 2` 時馬上縮小一半？
6. 「攤銷 `O(1)`」和「最壞 `O(1)`」有什麼不同？

### 答案

1. 陣列記憶體連續，位址可以直接算：`起點 + i × 元素大小`。鏈結串列的節點散落各處，只能從頭沿著 `next` 一個一個走。
2. `size = 9`。push 第 4 個時（`size` 從 8 要變 9）容量滿了 → 加倍成 16。所以 `capacity = 16`。
3. 搬家次數是 `10⁶ / 100 = 10⁴` 次，第 `k` 次搬 `100k` 個，總共約 `100 × (1 + 2 + ... + 10⁴) ≈ 5 × 10⁹` 次 → 會 TLE。加固定數量是 `O(n²)`。
4. `push_back` 可能觸發搬家，讓 `it` **失效**，之後的 `++it`、`*it` 都是未定義行為。而且就算沒搬家，`v.end()` 也改變了。
5. 會 **抖動**：在邊界上反覆 push / pop，每次都觸發 `O(n)` 的搬家。等降到 1/4 再縮小一半，縮完之後離兩個邊界都有距離，才不會一直搬。
6. 攤銷 `O(1)`：**一串操作加起來** 平均每次 `O(1)`，但其中某一次可能是 `O(n)`。最壞 `O(1)`：**每一次** 都保證 `O(1)`。如果是即時系統（例如遊戲每一幀不能卡頓），這個差別就很重要。
