# 第一部分：節點與串列

## 1.1 節點 (Node)

**白話**：鏈結串列的基本單位，裡面存兩樣東西：**資料** 和 **指向下一個節點的指標**。

```cpp
struct Node {
    int val;       // 資料
    Node* next;    // 下一個節點在哪裡（沒有下一個就是 nullptr）
    Node(int v) : val(v), next(nullptr) {}
};
```

## 1.2 鏈結串列 (Linked List)

**白話**：一串節點，每個節點用 `next` 指標 **鏈** 到下一個。節點在記憶體中 **散落各處**，不需要連續。

```
head                                   tail
 │                                      │
 ▼                                      ▼
+---+---+    +---+---+    +---+---+    +---+------+
| 3 | ●─┼──▶ | 8 | ●─┼──▶ | 1 | ●─┼──▶ | 6 | null |
+---+---+    +---+---+    +---+---+    +---+------+
```

**比喻**：尋寶遊戲。每一站的紙條寫著「下一站在哪裡」，最後一站的紙條寫「終點」（`nullptr`）。要找第 5 站，只能從第 1 站開始一站一站走。

## 1.3 頭指標 / 尾指標 (Head / Tail Pointer)

- **head**：指向第一個節點。整個串列 **只靠 head 找得到**，head 弄丟了，整條串列就找不回來了（記憶體洩漏）。
- **tail**：指向最後一個節點。不是必要的，但有了它，「在尾端加入」就能 `O(1)`，不用從頭走到尾。
- 空串列：`head == nullptr` 且 `tail == nullptr`。

## 1.4 陣列 vs 鏈結串列

| 操作 | 陣列 / vector | 單向鏈結串列 |
|---|---|---|
| 存取第 `i` 個 | `O(1)` ✅ | `O(i)` ❌ 要從頭走 |
| 頭部插入 / 刪除 | `O(n)` ❌ 全部要搬 | `O(1)` ✅ |
| 尾部插入（有 tail） | 攤銷 `O(1)` | `O(1)` |
| 尾部刪除 | `O(1)` | `O(n)` ❌ 要找倒數第二個 |
| 已知某節點，在它後面插入 / 刪除 | `O(n)` | `O(1)` ✅ 只改指標 |
| 記憶體 | 緊湊 | 每個節點多一個指標 |
| 快取友善 | ✅ | ❌ |

**快取友善 (Cache-Friendly)**：CPU 讀記憶體時會順便把「附近」的資料一起讀進快取。陣列連續，讀 `a[0]` 時 `a[1] ~ a[15]` 可能也一起來了；串列的節點散落各處，每次都要重新讀。所以就算複雜度一樣，**實際上陣列通常比串列快很多**。

**結論**：串列的優勢只在「**已經拿到某個節點的位置**，要在那裡插入 / 刪除」。這正是 LRU Cache 需要的（第四部分）。

# 第二部分：基本操作

## 2.1 走訪 (Traversal)

```cpp
for (Node* p = head; p != nullptr; p = p->next)
    cout << p->val << ' ';
```

**比喻**：沿著紙條一站一站走，直到紙條寫「終點」。

## 2.2 頭部插入 (Push Front)

```cpp
void push_front(int x) {
    Node* nd = new Node(x);
    nd->next = head;       // 新節點指向原本的第一個
    head = nd;             // head 改成新節點
    if (!tail) tail = nd;  // 原本是空的 → 新節點同時也是最後一個
}
```

## 2.3 在中間插入：順序很重要

在 `prev` 後面插入 `nd`：

```
before:  prev ──▶ A
after:   prev ──▶ nd ──▶ A
```

```cpp
nd->next = prev->next;   // ① 先接後面
prev->next = nd;         // ② 再改前面
```

**為什麼順序不能反過來？** 如果先做 ②，`prev->next` 已經變成 `nd`，原本的 `A` 就 **沒有任何指標指著它** 了 —— 從此找不到 A 和後面所有節點。

**比喻**：在一排手牽手的人中間插一個人。新來的人要 **先牽住後面那個人的手**，前面的人才能放開原本的手去牽新來的人。如果前面的人先放手，後面那一整串就走丟了。

## 2.4 刪除節點

要刪除 `prev` 後面的節點 `t`：

```
before:  prev ──▶ t ──▶ B
after:   prev ──────────▶ B      （t 被 delete）
```

```cpp
Node* t = prev->next;
prev->next = t->next;          // 繞過 t
if (t == tail) tail = prev;    // ← 刪的是最後一個，tail 要往前移（最常忘記！）
delete t;                      // 釋放記憶體
```

**單向串列的限制**：要刪除某個節點，必須知道它的 **前一個**。所以「刪除尾巴」要從頭走到倒數第二個，`O(n)`。

# 第三部分：經典技巧

## 3.1 反轉串列 (Reverse)

面試超常考。用三個指標 `prev`、`cur`、`nx`，一個一個把箭頭反過來：

```
一開始:  null    3 ──▶ 8 ──▶ 1 ──▶ null
         prev   cur

一步後:  null ◀── 3    8 ──▶ 1 ──▶ null
                prev  cur

兩步後:  null ◀── 3 ◀── 8    1 ──▶ null
                       prev  cur
```

```cpp
Node *prev = nullptr, *cur = head;
tail = head;                 // 反轉後原本的 head 變成 tail
while (cur) {
    Node* nx = cur->next;    // ① 先記住下一個（不然改完箭頭就找不到了）
    cur->next = prev;        // ② 反轉箭頭
    prev = cur;              // ③ 兩個指標都往前走一步
    cur = nx;
}
head = prev;
```

**比喻**：一排人都面向右邊、手搭在右邊那個人的肩上。從最左邊開始，每個人轉身把手改搭到左邊那個人的肩上。轉身之前要先記住右邊是誰，才知道下一個輪到誰。

## 3.2 哨兵節點 / 虛擬頭節點 (Sentinel / Dummy Head)

**白話**：在最前面放一個 **不存資料的假節點**。這樣「第一個節點」也有「前一個節點」了，插入 / 刪除第一個節點就跟中間的節點寫法一樣，**少寫很多 `if`**。

**比喻**：排隊時隊伍最前面固定站一個「工作人員」。不管誰要插隊到第一個位置，都是「插在工作人員後面」，規則統一。

```cpp
Node dummy(0);
dummy.next = head;
Node* prev = &dummy;
for (int k = 0; k < i; k++) prev = prev->next;   // 走到第 i 個的前一個
// 在 prev 後面插入或刪除，i == 0 也不用特別處理
head = dummy.next;                               // 最後記得更新 head
```

## 3.3 快慢指標 (Fast and Slow Pointers)

**白話**：兩個指標同時從頭出發，**慢指標一次走一步，快指標一次走兩步**。

**用途 1：找中間節點**。快指標走到尾巴時，慢指標剛好在中間。

**用途 2：判斷有沒有環**。如果串列有環（某個節點的 `next` 指回前面），快指標會在環裡繞圈，最後一定會追上慢指標。

**比喻**：兩個人在操場跑步，一個跑得比另一個快兩倍。如果跑道是直線，快的會先到終點；如果跑道是一圈，快的一定會從後面追上慢的。

```cpp
Node *slow = head, *fast = head;
while (fast && fast->next) {
    slow = slow->next;
    fast = fast->next->next;
    if (slow == fast) { /* 有環 */ }
}
// 沒有環的話，迴圈結束時 slow 在中間
```

# 第四部分：雙向串列與 LRU Cache

## 4.1 雙向鏈結串列 (Doubly Linked List)

**白話**：每個節點有 **兩個** 指標：`next` 指向下一個，`prev` 指向上一個。

```
        +------+---+------+    +------+---+------+
null ◀──┼ prev | A | next ┼──▶ ┼ prev | B | next ┼──▶ null
        +------+---+------+ ◀──┼------+---+------+
```

**好處**：拿到任何一個節點，都能 `O(1)` 刪除它（因為可以直接找到前一個），尾端刪除也是 `O(1)`。
**代價**：每個節點多一個指標，插入刪除時要多改兩個指標。

C++ 的 `std::list` 就是雙向串列。

**比喻**：單向串列是單行道；雙向串列是雙向道，可以往回走。

## 4.2 快取 (Cache) 與 LRU

**快取**：把常用的資料放在一個 **比較快但比較小** 的地方。例如瀏覽器把看過的網頁存在電腦裡，下次打開就不用重新下載。

快取空間有限，滿了就要 **踢掉** 一些舊的。踢掉誰？

**LRU (Least Recently Used，最近最少使用)**：踢掉「**最久沒被用到**」的那一個。

**比喻**：書桌上只能放 5 本書。要拿新書上來時，把「最久沒翻過」的那本放回書架。

## 4.3 為什麼 LRU 需要「雙向串列 + 雜湊表」

LRU 需要三個操作都是 `O(1)`：

| 需求 | 用什麼做到 |
|---|---|
| 用 key 找到資料 | **雜湊表**（第 06 課） |
| 把某筆資料移到「最新」的位置 | **雙向串列**：拿到節點就能 `O(1)` 拔出來、插到最前面 |
| 踢掉「最舊」的 | **雙向串列**：最舊的就是最後一個，`O(1)` 刪除 |

只用其中一個都做不到：
- 只用雜湊表：不知道誰最舊。
- 只用串列：找某個 key 要 `O(n)`。

合起來：雜湊表存 **「key → 串列中那個節點的位置」**。

```
雜湊表                      雙向串列（前 = 最新，後 = 最舊）
key 7 ──────────────┐
key 3 ───────┐      │
key 9 ──┐    │      │
        ▼    ▼      ▼
       [9] ⇄ [3] ⇄ [7]
       最新         最舊 ← 要踢就踢這個
```

```cpp
list<pair<int,int>> items;                                // (key, value)，前面 = 最新
unordered_map<int, list<pair<int,int>>::iterator> pos;    // key → 在串列中的位置

// 使用了 key：把它的節點搬到最前面
items.splice(items.begin(), items, pos[key]);
```

**`splice`（拼接）**：把一個節點從串列的某個位置 **剪下來，接到另一個位置**，`O(1)`。
而且節點本身沒有被刪除或複製，**原本指向它的迭代器仍然有效** —— 所以雜湊表裡存的位置不用更新。

# 第五部分：陷阱

## 5.1 最常見的 bug

| bug | 後果 | 怎麼避免 |
|---|---|---|
| 刪除最後一個節點，忘了更新 `tail` | 之後 `push_back` 接到已刪除的節點上 | 刪除時檢查 `t == tail` |
| 串列變空，`head` / `tail` 沒設回 `nullptr` | 存取已釋放的記憶體 | 刪完檢查 `if (!head) tail = nullptr;` |
| `reverse` 後沒更新 `tail` | `tail` 指向第一個節點 | 反轉前先 `tail = head` |
| 插入時先改前面再接後面 | 後半段串列走丟 | 永遠 **先接後面、再改前面** |
| `delete` 之後還用那個節點（例如 `t->next`） | use-after-free，未定義行為 | 先存好需要的東西，最後才 `delete` |
| 對 `nullptr` 做 `->next` | 程式當掉（RE） | 走訪前檢查是否為空 |
| 沒有釋放節點 | 記憶體洩漏 | 解構子裡走一遍全部 `delete` |

## 5.2 除錯技巧

1. **畫圖**：拿紙筆畫出每個節點和箭頭，一行一行模擬你的程式。這是寫串列最有效的方法。
2. **用 `--debug` 評測**：sanitizer 會抓到 use-after-free 和對空指標的存取，告訴你是哪一行。
3. **專門測只有 0 個、1 個、2 個節點的情況**：大部分的 bug 都藏在這裡。

## 5.3 Corner case checklist

- 空串列的 `pop_front` / `pop_back` / `reverse` / `print`。
- 只有一個節點時刪除它：`head` 和 `tail` 都要變 `nullptr`。
- 刪除最後一個節點：`tail` 要往前移。
- `reverse` 之後 `tail` 有沒有更新？
- `insert(size, x)` 是合法的（等於 `push_back`）。
- 刪光之後再加入。

# 小測驗

1. 單向串列有 head 和 tail。哪些操作是 `O(1)`？`push_front`、`push_back`、`pop_front`、`pop_back`
2. 下面插入 `nd` 到 `prev` 後面的寫法有什麼問題？

```cpp
prev->next = nd;
nd->next = prev->next;
```

3. 串列只有一個節點，刪除它之後 `head` 和 `tail` 應該是什麼？
4. 用快慢指標找中間節點，串列長度是 5 時 `slow` 停在第幾個？
5. LRU Cache 為什麼不能只用 `vector` 存「使用順序」？
6. `std::list::splice` 之後，原本指向被搬動節點的迭代器還能用嗎？為什麼這對 LRU 很重要？

### 答案

1. `push_front`、`push_back`、`pop_front` 是 `O(1)`。`pop_back` 是 `O(n)`，因為要從頭走到倒數第二個，才能把它的 `next` 設成 `nullptr` 並更新 `tail`。
2. 第一行做完後 `prev->next` 已經是 `nd`，第二行變成 `nd->next = nd`（自己指向自己），原本 `prev` 後面的節點全部走丟。要先 `nd->next = prev->next;` 再 `prev->next = nd;`。
3. 都是 `nullptr`。
4. 第 3 個（中間）。`fast` 走 1 → 3 → 5，走到第 5 個時 `fast->next` 是 `nullptr`，迴圈結束，`slow` 走了 2 步，在第 3 個。
5. 把某個 key 移到「最新」要先找到它（`O(n)`），再從中間刪掉（`O(n)`，後面要往前搬）。每次操作都是 `O(n)`，太慢。
6. 還能用。`splice` 只改指標，節點本身沒有被刪除或複製。所以雜湊表裡存的迭代器不用更新，每次「移到最前面」都是 `O(1)`。
