# 第一部分：要解決什麼問題

## 1.1 不相交集合 (Disjoint Sets)

**白話**：把一群東西分成好幾組，**每個東西剛好屬於一組**，組和組之間沒有重疊。

**比喻**：班上同學分組做報告，每個人只能在一組。

## 1.2 併查集的兩個操作

| 操作 | 意思 |
|---|---|
| **合併 (Union)** | 把 `a` 所在的組和 `b` 所在的組合成一組 |
| **查詢 (Find)** | `a` 在哪一組？（回傳該組的 **代表**） |

「併」= Union，「查」= Find，所以叫 **併查集**。

判斷 `a`、`b` 是否同組：`find(a) == find(b)`。

**比喻**：社群網路的朋友圈。「A 和 B 成為朋友」就是合併兩個朋友圈；「A 和 C 是不是在同一個朋友圈（透過朋友的朋友可以認識）」就是查詢。

## 1.3 為什麼不用其他方法？

| 方法 | 合併 | 查詢是否同組 |
|---|---|---|
| 每個點記錄組別編號 `group[x]` | `O(n)`：要把整組的編號改掉 | `O(1)` |
| 每次 BFS / DFS 看連不連通 | `O(1)`：只加一條邊 | `O(n + m)` |
| **併查集** | **幾乎 `O(1)`** | **幾乎 `O(1)`** |

# 第二部分：用樹表示群組

## 2.1 代表元素 (Representative)

**白話**：每一組選一個成員當 **代表**（也叫老大、根）。兩個人同組 ⟺ 他們的代表是同一個人。

**比喻**：每組報告有一個組長。問「你們是不是同一組？」只要問「你們的組長是誰？」。

## 2.2 parent 陣列

每一組是一棵 **樹**，**根就是代表**。`parent[x]` 存 `x` 的父節點；根的 `parent` 是 **自己**。

```
組 {1, 2, 3, 5}         組 {4, 6}
      1                     4
     / \                    |
    2   3                   6
        |
        5

parent = [_, 1, 1, 1, 4, 3, 4]
索引:     0  1  2  3  4  5  6
```

初始化：每個人自己一組，`parent[i] = i`。

**比喻**：每個人只記得「我的直屬上司是誰」。要找組長，就一路問上去，直到問到「我的上司就是我自己」的人。

## 2.3 基本版的 find 和 union

```cpp
int find(int x) {
    while (parent[x] != x) x = parent[x];   // 一路往上走到根
    return x;
}

void unite(int a, int b) {                  // union 是 C++ 關鍵字，所以改叫 unite
    a = find(a);
    b = find(b);
    if (a != b) parent[b] = a;              // 把 b 那棵樹的根接到 a 的根下面
}
```

注意 `unite` 一定要 **先找到兩邊的根**，再把根接起來。如果直接寫 `parent[b] = a`，`b` 會脫離原本的組，原本的組員卻沒跟過來。

## 2.4 基本版的問題：長鏈

如果每次都把大樹接到新的點下面：

```
unite(2, 1)：1 接到 2 下面
unite(3, 2)：2 接到 3 下面
unite(4, 3)：3 接到 4 下面
...

        n
        |
       n-1
        |
       ...
        |
        1        ← find(1) 要走 n 步！
```

樹變成一條 **長鏈**，`find` 變成 `O(n)`，`n` 次操作就是 `O(n²)`。
`14_union_find` 的 `corner_long_chain` 就是在測這個。

# 第三部分：兩個優化

## 3.1 優化一：按大小合併 (Union by Size)

**白話**：合併時，把 **小的樹接到大的樹下面**。用 `sz[root]` 記錄每棵樹有幾個節點。

**比喻**：兩家公司合併時，通常是小公司併入大公司，大公司的組織架構不用動，只有小公司的人多了一層上司。

```cpp
void unite(int a, int b) {
    a = find(a); b = find(b);
    if (a == b) return;
    if (sz[a] < sz[b]) swap(a, b);   // 讓 a 是比較大的那棵
    parent[b] = a;
    sz[a] += sz[b];
}
```

**為什麼樹高最多 `log n`？**
某個節點每次「被接到別人下面」（深度 +1），它所在的樹 **至少變成原來的兩倍大**（因為它是比較小的那一棵）。
樹最多 `n` 個節點，所以最多翻倍 `log₂ n` 次 → 深度最多 `log n`。

> 另一種做法是 **按秩合併 (Union by Rank)**：記錄樹的高度（秩）而不是大小，把矮的接到高的下面。效果一樣。

## 3.2 優化二：路徑壓縮 (Path Compression)

**白話**：`find(x)` 走到根之後，**順便把路上經過的每個節點都直接接到根**。下次再查它們，一步就到。

**比喻**：你問上司「組長是誰？」，上司又去問他的上司……最後問到了。下次你就 **直接記住組長的電話**，不用再一層一層問。

```
find(5) 之前：          之後：
      1                    1
     / \                / | \
    2   3              2  3  5
        |
        5
```

```cpp
// 遞迴版：簡潔
int find(int x) {
    return parent[x] == x ? x : parent[x] = find(parent[x]);
}

// 迴圈版：不怕堆疊溢位
int find(int x) {
    int r = x;
    while (parent[r] != r) r = parent[r];   // 第一趟：找到根
    while (parent[x] != r) {                // 第二趟：路上每個點都直接接到根
        int nx = parent[x];
        parent[x] = r;
        x = nx;
    }
    return r;
}
```

## 3.3 兩個一起用：反阿克曼函數

同時用「按大小合併」和「路徑壓縮」，每個操作的 **攤銷** 複雜度是 **`O(α(n))`**。

**反阿克曼函數 (Inverse Ackermann Function) `α(n)`**：成長慢到不可思議的函數。對宇宙中所有原子的數量（約 `10⁸⁰`）來說，`α(n)` 也 **不超過 4**。

所以實務上 **直接當作 `O(1)`**。

| 版本 | 單次操作（最壞 / 攤銷） |
|---|---|
| 沒有優化 | `O(n)` |
| 只有按大小合併 | `O(log n)` |
| 只有路徑壓縮 | 攤銷 `O(log n)` |
| 兩個都有 | 攤銷 `O(α(n))` ≈ `O(1)` |

> **遞迴版 `find` 的風險**：如果 **只做路徑壓縮、沒做按大小合併**，第一次 `find` 仍可能走一條長度 `n` 的鏈，遞迴 `n` 層會 **堆疊溢位**。有做按大小合併的話，樹高最多 `log n`，遞迴版很安全。

# 第四部分：應用與陷阱

## 4.1 完整模板

```cpp
struct DSU {
    vector<int> parent, sz;
    int groups;                                   // 目前有幾組
    DSU(int n) : parent(n + 1), sz(n + 1, 1), groups(n) {
        iota(parent.begin(), parent.end(), 0);    // parent[i] = i
    }
    int find(int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];        // 路徑減半：每次跳兩層，順便壓縮
            x = parent[x];
        }
        return x;
    }
    bool unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;                 // 本來就同組
        if (sz[a] < sz[b]) swap(a, b);
        parent[b] = a;
        sz[a] += sz[b];
        groups--;
        return true;
    }
    bool same(int a, int b) { return find(a) == find(b); }
    int size(int a) { return sz[find(a)]; }       // 一定要先 find！
};
```

`find` 裡的 `parent[x] = parent[parent[x]]` 叫 **路徑減半 (Path Halving)**：一趟迴圈就完成，效果和路徑壓縮差不多。

## 4.2 應用 1：判斷無向圖有沒有環

依序加入每一條邊 `(a, b)`：如果 `a`、`b` **已經同組**（`unite` 回傳 `false`），代表它們之間本來就有路徑，再加這條邊就會形成 **環**。

**比喻**：你跟朋友 A 本來就能透過共同朋友聯絡上，現在又直接加了好友 —— 朋友圈裡就出現了一個「圈」。

## 4.3 應用 2：最小生成樹 (Minimum Spanning Tree) — Kruskal 演算法

**生成樹 (spanning tree)**：用最少的邊（`V - 1` 條）把所有點連起來，沒有環。
**最小生成樹**：邊權總和最小的生成樹。

**比喻**：要在幾個村莊之間鋪路，讓每個村莊都能互通，總長度越短越好。

**Kruskal 演算法**：
1. 所有邊照權重 **由小到大** 排序。
2. 依序看每條邊：如果兩端 **不在同一組**，就選這條邊並 `unite`；同一組就跳過（會形成環）。

```cpp
sort(edges.begin(), edges.end());          // (w, a, b)
long long total = 0;
for (auto [w, a, b] : edges)
    if (dsu.unite(a, b)) total += w;
```

## 4.4 應用 3：動態連通性

「不斷加入連線，隨時問兩點是否連通、目前有幾個連通塊、某個連通塊多大」—— 就是 `14_union_find` 這題。

> 併查集 **只能合併，不能拆開**。如果需要「刪除邊」，就要用其他方法（例如把操作倒過來做：從最後的狀態開始，把刪除變成加入）。

## 4.5 Corner case checklist

- `unite(a, a)`：自己跟自己，組數 **不能減少**。
- 重複合併同一對。
- `n = 1`。
- 長鏈（測試有沒有做優化）。
- 查詢組的大小要用 `sz[find(a)]`，**不是** `sz[a]`（只有根的 `sz` 是正確的）。
- 點的編號是 1-based，陣列要開 `n + 1`。

# 小測驗

1. `n = 5`，依序 `unite(1, 2)`、`unite(3, 4)`、`unite(2, 4)`、`unite(1, 3)`。最後有幾組？哪一次 `unite` 回傳 `false`？
2. 為什麼 `unite(a, b)` 不能直接寫成 `parent[b] = a`？
3. 沒有任何優化，最壞情況下 `find` 是多少？給一個會讓它變慢的操作順序。
4. 只用「按大小合併」，為什麼樹高最多 `log n`？
5. `sz[x]` 什麼時候是正確的？查詢 `x` 所在組的大小要怎麼寫？
6. 無向圖邊依序是 `1-2`、`2-3`、`3-4`、`4-2`。加入哪一條邊時會出現環？

### 答案

1. `{1, 2}`、`{3, 4}` → `{1, 2, 3, 4}`；`unite(1, 3)` 時 1、3 已經同組，回傳 **`false`**。最後 **2** 組：`{1, 2, 3, 4}`、`{5}`。
2. `b` 可能不是根。直接改 `parent[b]` 會讓 `b` 脫離原本的樹，但 `b` 原本的組員（例如 `b` 的上司那一串）不會跟著過來，組別就亂了。要先 `find` 到兩邊的根，再接根。
3. `O(n)`。例如依序 `unite(2, 1)`、`unite(3, 2)`、`unite(4, 3)` ……（每次都把舊的根接到新的點下面），形成一條長鏈，`find(1)` 要走 `n` 步。
4. 一個節點的深度每增加 1，代表它所在的樹被接到一棵 **至少一樣大** 的樹下面，樹的大小至少翻倍。大小最多 `n`，所以最多翻倍 `log₂ n` 次。
5. 只有 `x` 是 **根** 的時候才正確。查詢要寫 `sz[find(x)]`。
6. 加入 **`4-2`** 時。在那之前 `1-2-3-4` 已經連通，2 和 4 已經同組，`unite(4, 2)` 回傳 `false` → 形成環 `2 → 3 → 4 → 2`。
