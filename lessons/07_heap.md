# 第一部分：優先佇列是什麼

## 1.1 優先佇列 (Priority Queue)

**白話**：一種容器，資料可以隨時放進去，但 **拿出來的永遠是「優先權最高」的那一個**（例如最小值或最大值），而不是最早放進去的。

**比喻**：醫院急診室。不是先來先看，而是 **最嚴重的病人先看**。新病人隨時會來，醫生每次都要找出目前最嚴重的那位。

| 操作 | 意思 |
|---|---|
| `push(x)` | 放入一個元素 |
| `top()` | 看目前優先權最高的元素 |
| `pop()` | 移除優先權最高的元素 |

「優先佇列」是一種 **抽象資料型別 (ADT)**：只規定能做什麼。**堆積 (heap)** 是實作它最常見的方法。

## 1.2 用陣列做會怎樣？

| 做法 | push | 取最小值 |
|---|---|---|
| 無序陣列 | `O(1)`：放最後面 | `O(n)`：要全部掃一遍 |
| 有序陣列 | `O(n)`：要找位置、後面全部往後搬 | `O(1)`：就在最前面 |
| **二元堆積** | **`O(log n)`** | **`O(log n)`** |

前兩種總有一個操作是 `O(n)`。堆積兩個都是 `O(log n)`，做 `n` 次操作只要 `O(n log n)`。

# 第二部分：二元堆積的結構

## 2.1 二元樹 (Binary Tree)

**白話**：每個節點 **最多兩個小孩**（左小孩、右小孩）的樹。

名詞：最上面的節點叫 **根 (root)**；沒有小孩的節點叫 **葉 (leaf)**；節點上面那個叫 **父節點 (parent)**。（第 08 課會詳細教樹。）

## 2.2 完全二元樹 (Complete Binary Tree)

**白話**：除了最後一層之外 **每一層都填滿**，最後一層的節點 **從左邊開始連續排**，中間不能有空缺。

```
完全二元樹 ✅              不是完全二元樹 ❌
       1                        1
     /   \                    /   \
    2     3                  2     3
   / \   /                  /     /
  4   5 6                  4     6       ← 4 和 6 之間少了 5
```

**比喻**：電影院從第一排開始坐滿，坐滿一排才坐下一排，而且每一排都從最左邊開始坐。

**好處**：形狀固定，`n` 個節點的高度一定是 `⌊log₂ n⌋ + 1`，**不會退化成一條長鏈**。

## 2.3 堆積性質 (Heap Property)

**最小堆積 (min-heap)**：**每個節點都 ≤ 它的小孩**。所以 **根就是最小值**。
**最大堆積 (max-heap)**：每個節點都 ≥ 它的小孩，根是最大值。

```
最小堆積：
          1
        /   \
       3     2
      / \   /
     7   4 5
```

注意：堆積 **只規定上下關係，不規定左右關係**。`3` 和 `2` 誰在左邊都可以；`7` 比旁邊子樹的 `2` 還大也沒關係。所以堆積 **不是排好序的**，只保證根最小。

**比喻**：公司的組織圖。每個主管的「資歷」都比下屬深，所以最頂端的老闆資歷最深。但兩個不同部門的人誰比較資深，組織圖沒有規定。

## 2.4 用陣列存完全二元樹

因為完全二元樹 **沒有空缺**，可以由上到下、由左到右編號，直接存進陣列，**完全不需要指標**：

```
              1 [0]
           /        \
        3 [1]       2 [2]
       /    \      /
    7 [3]  4 [4] 5 [5]

陣列: [1, 3, 2, 7, 4, 5]
```

**0-based 索引公式**（`i` 是某個節點的索引）：

| 要找 | 公式 | 例：`i = 1`（值 3） |
|---|---|---|
| 父節點 | `(i - 1) / 2` | `0`（值 1） |
| 左小孩 | `2i + 1` | `3`（值 7） |
| 右小孩 | `2i + 2` | `4`（值 4） |

> 如果用 1-based（從索引 1 開始放），公式更漂亮：父 `i / 2`，左 `2i`，右 `2i + 1`。

# 第三部分：插入與刪除

## 3.1 上浮 (Sift Up / Bubble Up)

**push 的步驟**：
1. 把新元素放在陣列 **最後面**（保持完全二元樹的形狀）。
2. 如果它比父節點小，就 **跟父節點交換**；重複直到不比父節點小，或已經到根。

**比喻**：新進員工能力很強，一路往上升職，直到上司比他強為止。

```
push 0：
       1                  1                  0
     /   \              /   \              /   \
    3     2    →       3     0     →      3     1
   / \   / \          / \   / \          / \   / \
  7   4 5   0        7   4 5   2        7   4 5   2
            ↑ 0 < 2，交換      ↑ 0 < 1，交換，到根了
```

```cpp
void sift_up(int i) {
    while (i > 0) {
        int p = (i - 1) / 2;
        if (a[p] <= a[i]) break;   // 父節點比較小，符合堆積性質，停
        swap(a[p], a[i]);
        i = p;
    }
}
```

## 3.2 下沉 (Sift Down / Heapify Down)

**pop 的步驟**：
1. 根（最小值）要被移除。把陣列 **最後一個元素搬到根**，然後刪掉最後一格（保持形狀）。
2. 如果新的根比小孩大，就跟 **比較小的那個小孩** 交換；重複直到比兩個小孩都小，或已經是葉節點。

**比喻**：老闆退休了，臨時找最基層的員工頂上。他能力不夠，就一路往下降職，直到下屬都比他弱為止。

**為什麼要跟「比較小」的小孩交換？** 交換後，那個小孩會變成另一個小孩的 **父節點**，它必須比另一個小孩小才符合堆積性質。

```cpp
void sift_down(int i) {
    int n = a.size();
    while (true) {
        int l = 2 * i + 1, r = 2 * i + 2, m = i;
        if (l < n && a[l] < a[m]) m = l;   // 先檢查小孩存不存在！
        if (r < n && a[r] < a[m]) m = r;
        if (m == i) break;                 // 自己就是最小的，停
        swap(a[i], a[m]);
        i = m;
    }
}

void pop() {
    a[0] = a.back();
    a.pop_back();
    if (!a.empty()) sift_down(0);
}
```

## 3.3 為什麼是 O(log n)？

上浮和下沉都是 **沿著一條從根到葉的路徑** 走，每次往上或往下一層。
完全二元樹的高度是 `log n`，所以最多走 `log n` 步。

`n = 10⁶` 時只要大約 20 步。

# 第四部分：建堆與堆積排序

## 4.1 建堆 (Heapify / Build Heap)

**問題**：已經有一個 `n` 個元素的陣列，要把它變成堆積。

**方法 1**：一個一個 push，`n × O(log n)` = `O(n log n)`。

**方法 2**：從 **最後一個非葉節點** 開始往前，對每個節點做 **下沉**。只要 **`O(n)`**！

```cpp
for (int i = n / 2 - 1; i >= 0; i--)
    sift_down(i);
```

**為什麼是 O(n)？** 下沉的步數取決於節點離 **底部** 有多遠：

| 位置 | 節點數 | 最多下沉幾步 |
|---|---|---|
| 最底層（葉節點） | 約 `n/2` | 0 |
| 倒數第 2 層 | 約 `n/4` | 1 |
| 倒數第 3 層 | 約 `n/8` | 2 |
| …… | …… | …… |

總共 `n/4 × 1 + n/8 × 2 + n/16 × 3 + ...`，這個級數加起來 **小於 `n`**。
直覺：**大部分節點都在底層，沉不了幾步**；只有少數靠近根的節點要沉很多步。

**比喻**：公司重新整頓。基層員工最多（一半），但他們下面沒人，不用動；只有少數高層主管需要重新安排。

## 4.2 堆積排序 (Heap Sort)

1. 建堆：`O(n)`。
2. 重複 `n` 次「取出最小值」：`n × O(log n)`。

總共 **`O(n log n)`**，而且不需要額外的陣列空間。

# 第五部分：STL 與應用

## 5.1 priority_queue

```cpp
priority_queue<int> maxpq;                               // ⚠️ 預設是「最大」堆積！
priority_queue<int, vector<int>, greater<int>> minpq;    // 最小堆積

minpq.push(5);
minpq.top();     // 看最小值
minpq.pop();     // 移除最小值（不回傳值）
minpq.size();
minpq.empty();
```

`greater<int>` 是 **比較器 (comparator)**：告訴 `priority_queue` 怎麼比大小。名字很反直覺 —— 用 `greater` 反而得到 **最小** 堆積。直接背起來就好。

**小技巧**：只有最大堆積可用時，把數字 **取負號** 放進去，就變成最小堆積：

```cpp
priority_queue<int> pq;
pq.push(-x);           // 放進去時取負
int smallest = -pq.top();
```

## 5.2 存 pair：多個條件比較

`pair` 會 **先比 `first`，一樣再比 `second`**。

```cpp
// (距離, 節點編號)，距離最小的先出來
priority_queue<pair<long long,int>, vector<pair<long long,int>>, greater<>> pq;
pq.push({5, 2});
pq.push({3, 7});
auto [d, u] = pq.top();   // d = 3, u = 7
```

## 5.3 常見應用

| 應用 | 怎麼用 heap |
|---|---|
| Dijkstra 最短路徑 | 每次取出「目前距離最小」的點 |
| 拓撲排序要字典序最小 | 每次取出「目前可以做」的最小編號（`16_topo_sort`） |
| 找第 k 大 | 維護一個大小 `k` 的最小堆積，堆頂就是第 k 大 |
| 合併 k 個有序串列 | 每次從 k 個串列的開頭中取最小 |
| 事件模擬 | 每次處理「最早發生」的事件 |

**找第 k 大的技巧**：維護大小 `k` 的 **最小** 堆積。每來一個數就 push，超過 `k` 個就 pop 掉最小的。最後堆裡是最大的 `k` 個，堆頂是其中最小的 —— 就是第 `k` 大。總共 `O(n log k)`。

## 5.4 Corner case checklist

- 空的 heap 呼叫 `pop` / `top`。
- 只有一個元素時 pop（`a[0] = a.back()` 之後陣列是空的，不要再下沉）。
- 節點只有左小孩、沒有右小孩（`r < n` 的檢查）。
- 重複的值。
- `long long` 的極端值：比較時用 `<`，**不要用相減** 判斷大小（`a - b` 可能溢位）。

# 小測驗

1. 陣列 `[1, 3, 2, 7, 4, 5]` 是最小堆積。索引 4 的父節點和索引 2 的左小孩各是哪個索引、值是多少？
2. 對上面的堆積做 `pop`，畫出結果（陣列形式）。
3. `[2, 5, 3, 1]` 是不是最小堆積？為什麼？
4. 為什麼「依序 push `n` 個元素」是 `O(n log n)`，「從下往上下沉」建堆卻是 `O(n)`？
5. `priority_queue<int> pq;` 依序 push `3, 1, 4`，`pq.top()` 是多少？
6. 有 `10⁷` 個數字，只要找最大的 10 個。用什麼方法最省？複雜度是多少？

### 答案

1. 索引 4 的父節點：`(4 - 1) / 2 = 1`，值 **3**。索引 2 的左小孩：`2 × 2 + 1 = 5`，值 **5**。
2. 最後一個 `5` 搬到根 → `[5, 3, 2, 7, 4]`。`5` 的小孩是 `3` 和 `2`，跟較小的 `2` 交換 → `[2, 3, 5, 7, 4]`。`5` 在索引 2，小孩索引 5、6 不存在，停。結果 **`[2, 3, 5, 7, 4]`**。
3. **不是**。索引 3 的 `1` 的父節點是索引 1 的 `5`，`5 > 1`，違反堆積性質。
4. push 是 **上浮**，花費取決於離 **根** 多遠，大部分節點在底層，離根很遠（`log n`）。下沉的花費取決於離 **底部** 多遠，大部分節點在底層，離底部很近（0 或 1）。
5. **4**。`priority_queue` 預設是最大堆積。
6. 維護一個大小 10 的 **最小堆積**：每個數 push 進去，超過 10 個就 pop 最小的。複雜度 `O(n log 10)` ≈ `O(n)`，記憶體只要存 10 個。
