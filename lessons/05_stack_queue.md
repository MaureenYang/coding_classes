# 第一部分：Stack 堆疊

## 1.1 堆疊 (Stack)

**白話**：只能從 **同一端**（頂端 top）放入和拿出的容器。**最後放進去的，最先被拿出來**。

**比喻**：一疊盤子。洗好的盤子放在最上面，要用時也從最上面拿。你不可能從中間抽一個出來。

```
push 1, push 2, push 3        pop → 拿出 3
   |   |                       |   |
   | 3 | ← top                 |   |
   | 2 |                       | 2 | ← top
   | 1 |                       | 1 |
   +---+                       +---+
```

## 1.2 後進先出 (LIFO, Last In First Out)

**白話**：stack 的規則。「後進」= 最後放進去的；「先出」= 最先被拿出來。

## 1.3 三個操作

| 操作 | 意思 | 複雜度 |
|---|---|---|
| `push(x)` | 放到頂端 | `O(1)` |
| `pop()` | 移除頂端（`std::stack` 的 `pop` **不回傳值**） | `O(1)` |
| `top()` | 看頂端是什麼（不移除） | `O(1)` |

```cpp
stack<int> st;
st.push(1); st.push(2);
int x = st.top();   // 2
st.pop();           // 移除 2
st.empty();         // 是否為空
```

> ⚠️ 對 **空的** stack 呼叫 `top()` 或 `pop()` 是 **未定義行為**（不會報錯，結果無法預測）。一定要先檢查 `empty()`。

**用陣列實作**非常簡單：一個陣列 + 一個「頂端位置」的整數。`push` 就是 `a[top++] = x`，`pop` 就是 `top--`。

## 1.4 什麼問題該用 stack？

**判斷口訣**：「**最近的那個** 還沒處理完的東西，要 **最先** 處理」。

| 應用 | 為什麼是「最近的先處理」 |
|---|---|
| 括號配對 | 右括號要和 **最近一個** 還沒配對的左括號比 |
| 復原 (Undo) | 復原的是 **最後一個** 動作 |
| 瀏覽器「上一頁」 | 回到 **最近一個** 看過的頁面 |
| 函式呼叫（呼叫堆疊） | **最後被呼叫** 的函式最先結束 |
| DFS 深度優先搜尋 | 先把 **最新發現** 的路走完 |

## 1.5 範例：括號配對

```
([]{})  → 合法
([)]    → 不合法：] 遇到的最近左括號是 (，不配
((      → 不合法：結束時還有沒配對的左括號
)(      → 不合法：第一個 ) 沒有左括號可以配
```

演算法：
1. 遇到左括號 → `push`。
2. 遇到右括號 → stack 空的就不合法；頂端不是對應的左括號也不合法；配對成功就 `pop`。
3. 全部讀完後，stack 必須是空的。

```cpp
for (char c : s) {
    if (c == '(' || c == '[' || c == '{') st.push(c);
    else {
        char want = c == ')' ? '(' : c == ']' ? '[' : '{';
        if (st.empty() || st.top() != want) return false;   // 先檢查 empty！
        st.pop();
    }
}
return st.empty();
```

## 1.6 範例：最小值堆疊 (Min Stack)

**問題**：stack 除了 `push / pop / top`，還要能 `O(1)` 查詢目前的最小值。

**想法**：另外維護一個 **輔助堆疊 (auxiliary stack)** `mn`，`mn` 的每一層存「**從底部到這一層為止的最小值**」。兩個 stack 一起 push、一起 pop。

```
st（資料）:  3   5   1   1   4
mn（最小）:  3   3   1   1   1     ← mn.top() 永遠是目前的最小值
```

```cpp
void push(int x) {
    st.push(x);
    mn.push(mn.empty() ? x : min(x, mn.top()));
}
void pop() { st.pop(); mn.pop(); }
int getmin() { return mn.top(); }
```

**比喻**：每疊一個盤子，就在旁邊的便條紙上寫「到這個盤子為止，最小的是幾號」。拿走盤子時也撕掉一張便條紙，最上面那張永遠是答案。

> **經典陷阱**：如果為了省空間，只在 `x < mn.top()` 時才 push 到 `mn`，遇到 **重複的最小值** 就會出錯：push 1、push 1，`mn` 只存了一個 1；pop 掉一個 1 之後 `mn` 的 1 也被拿掉了，但 stack 裡其實還有一個 1。要改成 `x <= mn.top()`。

# 第二部分：Queue 佇列

## 2.1 佇列 (Queue)

**白話**：從 **一端放入**（尾端 rear / back），從 **另一端拿出**（前端 front）。**最先放進去的，最先被拿出來**。

**比喻**：排隊買飲料。先來的人先買，後來的排在最後面。

```
放入 (enqueue) →  [ 4 | 3 | 2 | 1 ]  → 拿出 (dequeue)
                  rear          front
```

## 2.2 先進先出 (FIFO, First In First Out)

**白話**：queue 的規則。和 stack 相反。

```cpp
queue<int> q;
q.push(1); q.push(2);   // enqueue
q.front();              // 1
q.pop();                // dequeue，移除 1
```

**應用**：BFS 廣度優先搜尋（第 09 課）、工作排程（印表機佇列）、緩衝區 (buffer)。

## 2.3 用陣列實作的問題：空間浪費

如果用陣列 + 兩個索引 `head`（前端）、`tail`（下一個要放的位置）：

```
dequeue 三次之後：
[ x | x | x | 4 | 5 |   |   ]
              ▲head     ▲tail
前面三格已經沒用了，但再也不會被用到
```

`head` 只會往右走，前面的空間永遠浪費掉。

## 2.4 環狀佇列 (Circular Queue / Ring Buffer)

**白話**：走到陣列底端時 **繞回開頭** 繼續用。用 `% K`（`K` 是容量）讓索引繞圈。

**比喻**：迴轉壽司的輸送帶。盤子繞一圈回到起點，空位會被重新利用。

```
K = 5，head = 3，count = 3
索引:  0    1    2    3    4
     [ c ][   ][   ][ a ][ b ]
                      ▲head
元素順序: a, b, c（c 繞回了開頭）

最後一個元素的位置 = (head + count - 1) % K = (3 + 3 - 1) % 5 = 0
下一個要放的位置   = (head + count) % K     = (3 + 3) % 5     = 1
```

```cpp
bool enqueue(int x) {
    if (count == K) return false;          // 滿了
    buf[(head + count) % K] = x;
    count++;
    return true;
}
bool dequeue() {
    if (count == 0) return false;          // 空的
    head = (head + 1) % K;
    count--;
    return true;
}
```

## 2.5 空和滿怎麼分辨？

**建議用 `head + count`**：空是 `count == 0`，滿是 `count == K`，清清楚楚。

如果用 `head + tail` 兩個索引：**空的時候和滿的時候都是 `head == tail`**，分不出來！常見解法：
- 故意 **少用一格**：`(tail + 1) % K == head` 就算滿。
- 另外加一個 `bool full` 旗標。

# 第三部分：Deque 雙端佇列

## 3.1 雙端佇列 (Deque, Double-Ended Queue)

**白話**：**兩端都可以** 放入和拿出，全部 `O(1)`。發音同 "deck"。

**比喻**：一副撲克牌，上面和下面都可以抽牌、放牌。

```cpp
deque<int> dq;
dq.push_back(1);  dq.push_front(0);   // [0, 1]
dq.pop_back();    dq.pop_front();     // []
dq[i];                                // 也支援隨機存取
```

stack 和 queue 都可以用 deque 實作（`std::stack` 和 `std::queue` 預設就是包裝了一個 `deque`）。

# 第四部分：單調堆疊 (Monotonic Stack)

## 4.1 問題：下一個更大的元素 (Next Greater Element)

對陣列中的每個元素，找 **右邊第一個比它大的元素**。

```
a      = [2, 7, 3, 5, 4, 6]
答案   = [7, -1, 5, 6, 6, -1]
```

**暴力法**：每個元素往右掃，`O(n²)`。`n = 3 × 10⁵` 時會 TLE。

## 4.2 單調 (Monotonic)

**白話**：一直往同一個方向變化，**只增不減**（遞增）或 **只減不增**（遞減）。

**單調堆疊**：stack 裡的元素從底到頂保持單調（例如遞減）。新元素進來時，如果會破壞單調性，就先把頂端不符合的元素 **彈出**，再放進去。

## 4.3 關鍵觀察

從左往右掃，stack 裡放「**還沒找到答案**」的元素。

當新元素 `a[i]` 進來時，stack 頂端所有比 `a[i]` 小的元素，它們的答案 **就是 `a[i]`**（`a[i]` 是它們右邊第一個比它們大的）—— 彈出並記錄答案。

被彈出後，剩下的 stack 一定是 **由底到頂遞減** 的（否則上面那個比較大的早就把下面那個彈掉了）。

**比喻**：一排人由左往右站，每個人都在找「右邊第一個比我高的人」。從左邊開始一個一個進場。新進場的人比前面還在等的矮個子高，那些矮個子就找到答案了，離場。還在場上等的人，一定是左高右矮排著的。

```
a = [2, 7, 3, 5, 4, 6]

i=0 a=2：stack [2]
i=1 a=7：7 > 2 → 2 的答案是 7，彈出。stack [7]
i=2 a=3：3 < 7，直接放入。stack [7, 3]
i=3 a=5：5 > 3 → 3 的答案是 5，彈出。5 < 7，停。stack [7, 5]
i=4 a=4：stack [7, 5, 4]
i=5 a=6：6 > 4 → 答案 6；6 > 5 → 答案 6；6 < 7，停。stack [7, 6]
結束：stack 裡剩下的 7、6 右邊都沒有更大的 → -1
```

```cpp
vector<int> st;                       // 存「索引」，不是值
vector<long long> ans(n, -1);
for (int i = 0; i < n; i++) {
    while (!st.empty() && a[st.back()] < a[i]) {
        ans[st.back()] = a[i];
        st.pop_back();
    }
    st.push_back(i);
}
```

**為什麼存索引？** 要知道答案該填到 `ans` 的哪一格。

## 4.4 為什麼是 O(n)？

`while` 迴圈看起來可能跑很多次，但 **每個索引最多被 push 一次、pop 一次**。
整個程式 push 總共 `n` 次、pop 總共最多 `n` 次 → `O(n)`。這是 **攤銷分析**（第 01 課）。

# 第五部分：單調佇列 (Monotonic Deque)

## 5.1 問題：滑動視窗最大值 (Sliding Window Maximum)

一個長度 `k` 的 **視窗** 從陣列最左邊滑到最右邊，每個位置都要回答「視窗內最大值是多少」。

```
a = [1, 3, -1, -3, 5, 3, 6, 7], k = 3

[1  3  -1] -3  5  3  6  7   → 3
 1 [3  -1  -3] 5  3  6  7   → 3
 1  3 [-1  -3  5] 3  6  7   → 5
 ...
```

**暴力法**：每個視窗掃 `k` 個，`O(nk)`。

## 5.2 滑動視窗 (Sliding Window)

**白話**：在陣列上框出一段連續的範圍，每次往右移一格：右邊加入一個新元素，左邊移出一個舊元素。

**比喻**：火車的車窗。火車往前開，新的風景從右邊進來，舊的風景從左邊離開。

## 5.3 關鍵觀察

如果 `j < i` 而且 `a[j] ≤ a[i]`，那 `a[j]` **永遠不可能再當最大值**：
它比 `a[i]` 舊（會比較早離開視窗），又不比 `a[i]` 大。

**比喻**：公司裡如果有一個 **比你資淺、能力又比你強** 的同事，你就永遠不可能被選為「最強的人」了（他會比你晚退休）。

所以用 deque 存 **索引**，對應的值 **由前到後遞減**：

1. 新元素 `a[i]` 進來：從 **後面** 把所有 `≤ a[i]` 的丟掉（它們沒希望了）。
2. 把 `i` 放到後面。
3. 如果 **前面** 的索引已經不在視窗裡（`≤ i - k`），丟掉。
4. **前面** 就是目前視窗的最大值。

```cpp
deque<int> dq;
for (int i = 0; i < n; i++) {
    while (!dq.empty() && a[dq.back()] <= a[i]) dq.pop_back();   // 1
    dq.push_back(i);                                              // 2
    if (dq.front() <= i - k) dq.pop_front();                      // 3
    if (i >= k - 1) ans.push_back(a[dq.front()]);                 // 4
}
```

每個索引最多進出 deque 各一次 → `O(n)`。

# 小測驗

1. 依序 push 1、2、3，再 pop 兩次，stack 頂端是什麼？如果換成 queue（push → enqueue、pop → dequeue），front 是什麼？
2. 括號配對中，字串 `"))(("` 在第幾個字元就能判斷不合法？為什麼？
3. Min Stack 依序 push `5, 2, 2, 7`，然後 pop 兩次。輔助堆疊 `mn` 的內容是什麼？`getmin` 回傳多少？
4. 環狀佇列 `K = 4`，`head = 3`，`count = 2`。下一個元素要放在哪個索引？
5. 下一個更大的元素：`a = [5, 4, 3, 2, 1]` 的答案是什麼？跑完時 stack 裡有幾個元素？
6. 滑動視窗最大值，為什麼 deque 裡存的是 **索引** 而不是值？

### 答案

1. Stack：pop 掉 3、2，頂端是 **1**。Queue：dequeue 掉 1、2，front 是 **3**。
2. 第 1 個字元。遇到 `)` 時 stack 是空的，沒有左括號可以配對。
3. push 完 `mn = [5, 2, 2, 2]`；pop 兩次後 `mn = [5, 2]`，`getmin` 回傳 **2**（stack 裡剩 `5, 2`）。
4. `(head + count) % K = (3 + 2) % 4 = 1`，放在索引 **1**。
5. 答案 `[-1, -1, -1, -1, -1]`（遞減陣列，右邊都沒有更大的）。所有元素都沒被彈出，stack 裡有 **5** 個。
6. 要判斷某個元素 **是否已經滑出視窗**（`索引 ≤ i - k`），只存值的話不知道它在哪個位置。存索引的話，值用 `a[索引]` 就拿得到。
