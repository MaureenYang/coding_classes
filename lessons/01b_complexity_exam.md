## A. 基本迴圈 解說

**A1 → `O(n)`**
內層固定跑 100 次，總共 `100n` 次。100 是常數，Big-O 不寫常數 → `O(n)`。
重點：**巢狀迴圈不一定是 `O(n²)`**，要看內層跟 `n` 有沒有關係。

**A2 → `O(n²)`**
`i = 0` 時內層跑 `n` 次，`i = 1` 時跑 `n-1` 次 …… 總共 `n + (n-1) + ... + 1 = n(n+1)/2`。
最大項是 `n²/2`，去掉常數 → `O(n²)`。只跑「一半」，複雜度不變。

**A3 → `O(n)`**
三個迴圈是 **接著做**，不是包在裡面，所以是相加：`3n` → `O(n)`。

**A4 → `O(n³)`**
三層，每層 `n` 次，相乘 `n³`。

**A5 → `O(log n)`**
`i` 每次除以 2：`n, n/2, n/4, ..., 1`，跑 `log₂ n` 次。

**A6 → `O(√n)`**
迴圈在 `i² > n` 時停，也就是 `i` 跑到 `√n`。
這種寫法常用在「找因數」、「判斷質數」。`n = 10¹²` 時只要 `10⁶` 次。

**A7 → `O(n log n)`**
外層 `n` 次；內層 `j = 1, 2, 4, ...`，跑 `log n` 次。相乘 → `O(n log n)`。

**A8 → `O(nm)`**
兩個獨立的變數不能合併，要寫成 `O(nm)`（或 `O(n × m)`）。
例如網格 BFS 是 `O(R × C)`，不能隨便寫成 `O(n²)`。

## B. 迴圈陷阱 解說

**B1 → `O(n)`**（很多人會答 `O(n log n)`）
外層跑 `log n` 次沒錯，但內層次數 **不是固定的**：`i = 1, 2, 4, 8, ..., n`，
內層總共 `1 + 2 + 4 + ... + n`。這是等比級數，總和 **小於 `2n`** → `O(n)`。
教訓：**不能直接把兩層的次數相乘**，要把每一次內層真正跑的次數加起來。

**B2 → `O(n log n)`**
`i = 1` 時內層跑 `n` 次，`i = 2` 跑 `n/2` 次，`i = 3` 跑 `n/3` 次 ……
總共 `n × (1 + 1/2 + 1/3 + ... + 1/n)`。括號裡叫 **調和級數**，大約等於 `ln n`。
→ `O(n log n)`。這是「埃拉托斯特尼篩法」（找質數）的結構。

**B3 → `O(n)`**（很多人會答 `O(n²)`）
關鍵：**`j` 在外層迴圈之間不會歸零**。`j` 從 0 開始只會增加，最多加到 `n`，
所以 `j++` 整個程式加起來最多執行 `n` 次。外層 `n` 次 + `j++` 總共 `n` 次 = `O(n)`。
這叫 **雙指標 (two pointers)** 技巧。

**B4 → `O(n)`**
內層迴圈只有在 `i == n-1` 時執行 **一次**。外層 `n` 次 + 內層 `n` 次 = `2n` → `O(n)`。

**B5 → `O(n³)`**
內層跑 `i²` 次，總共 `0² + 1² + ... + (n-1)²`，約等於 `n³/3` → `O(n³)`。

**B6 → `O(n)`**（很多人會答 `O(n²)`）
`while` 看起來可能跑很多次，但 **每個索引最多被 push 一次、pop 一次**。
整個程式 push 總共 `n` 次、pop 總共最多 `n` 次 → `O(n)`。
這種「看全部加起來，而不是看單次最壞」的分析就是 **攤銷分析**。

**B7 → `O(n)`**
內層在 `j == 5` 時就 `break`，每次最多跑 6 次，是常數。總共 `6n` → `O(n)`。

## C. STL 操作的隱藏成本 解說

**C1 → `O(n²)`**
`vector` 在開頭插入，要把後面 **所有元素往後搬一格**，第 `i` 次要搬 `i` 個。
總共 `0 + 1 + ... + (n-1)` → `O(n²)`。
改法：用 `deque::push_front`（`O(1)`），或先 `push_back` 最後再 `reverse`。

**C2 → `O(n)`**
`push_back` 是 **攤銷 `O(1)`**（第 03 課），`n` 次總共 `O(n)`。

**C3 → `O(n²)`**
`s + 'a'` 會 **建立一個新字串**，把 `s` 整個複製過去再加一個字元，第 `i` 次要複製 `i` 個字元 → `O(n²)`。
`s += 'a'` 是直接在原本的字串後面加，攤銷 `O(1)`，總共 `O(n)`。
`n = 10⁵` 時，一個 0.001 秒，一個要好幾秒。

**C4 → `O(n log n)`**
`set` 是平衡樹，每次 `insert` 是 `O(log n)`，`n` 次 → `O(n log n)`。

**C5 → `O(n²)`**
`find` 是從頭到尾一個一個找，`O(n)`。做 `n` 次 → `O(n²)`。
改法：先把 `v` 放進 `unordered_set`（每次查詢平均 `O(1)`），或排序後用 `binary_search`（見 C8）。

**C6 → `O(n²)`**
`erase(v.begin())` 要把後面所有元素往前搬，`O(n)`。做 `n` 次 → `O(n²)`。
改法：從後面刪（`pop_back`，`O(1)`），或直接 `v.clear()`。

**C7 → `O(n²)`**（陷阱題）
參數 `vector<int> v` 是 **傳值**，每次遞迴都會 **複製整個 vector**（`O(n)`）。遞迴 `n` 層 → `O(n²)`。
而且每一層都存了一份完整的副本，記憶體也是 `O(n²)`！
改法：`int sum(const vector<int>& v, int i)`，傳參考不複製，變成 `O(n)`。

**C8 → `O(n log n)`**
`sort` 是 `O(n log n)`；`binary_search` 每次 `O(log n)`，做 `n` 次也是 `O(n log n)`。
相加還是 `O(n log n)`。比 C5 的 `O(n²)` 快很多。

## D. 遞迴 解說

**D1 → `O(2ⁿ)`**
每一層呼叫自己 **兩次**：第 0 層 1 個、第 1 層 2 個、第 2 層 4 個 ……
共 `n` 層，總呼叫數 `1 + 2 + 4 + ... + 2ⁿ ≈ 2ⁿ⁺¹` → `O(2ⁿ)`。這就是河內塔的結構。

**D2 → `O(log n)`**
每次 `n` 減半，呼叫一次，共 `log n` 層，每層 `O(1)`。

**D3 → `O(n²)`**
每一層做 `n` 次迴圈，然後 `n` 減 1：`n + (n-1) + ... + 1 = n(n+1)/2` → `O(n²)`。

**D4 → `O(n)`**（很多人會答 `O(n log n)`）
每一層做的事：`n + n/2 + n/4 + ... + 1`，等比級數，總和小於 `2n` → `O(n)`。
跟 B1 是同一個道理。

**D5 → `O(n log n)`**
畫遞迴樹：
- 第 0 層：1 個呼叫，做 `n` 的事
- 第 1 層：2 個呼叫，各做 `n/2`，共 `n`
- 第 2 層：4 個呼叫，各做 `n/4`，共 `n`
- …… 共 `log n` 層

每一層總共都是 `n`，有 `log n` 層 → `O(n log n)`。這是合併排序的複雜度。
比較 D4 和 D5：**只差一個遞迴呼叫，複雜度就不一樣**。

**D6 → `O(2ⁿ)`；記憶化後 `O(n)`**
`fib(n)` 呼叫 `fib(n-1)` 和 `fib(n-2)`，跟 D1 一樣每層分兩支（稍微少一點，精確來說約 `1.618ⁿ`，Big-O 一般寫 `O(2ⁿ)`）。
大量 **重複計算**：`fib(n-2)` 會在兩個地方被算。
記憶化後，每個 `fib(k)` 只真正算一次，`k = 0 ~ n` → `O(n)`。

## E. 看限制判斷 解說

**E1 → 會超時**
`n² = (10⁵)² = 10¹⁰`，每秒 `10⁸` 次，要 100 秒。需要 `O(n log n)` 以下的方法。

**E2 → 不會超時**
`2²⁰ × 20 ≈ 10⁶ × 20 = 2 × 10⁷`，大約 0.2 秒。
`n ≤ 20` 這種小限制，通常就是在暗示「可以用指數時間」。

**E3 → 只有 `O(log n)` 和 `O(1)`**
- `O(n)` = `10¹⁸`：要 300 年。
- `O(√n)` = `10⁹`：大約 10 秒，**仍然太慢**。
- `O(log n)` ≈ 60：一瞬間。
`n` 大到不可能存下來時，一定是數學公式或「每次砍一半」（例如 `02_hanoi_kth`）。

**E4 → 會超時**
`erase(v.begin())` 每次要把剩下的元素全部往前搬，`O(元素個數)`。
pop 時元素個數從 `2 × 10⁵` 遞減到 1，總共約 `(2 × 10⁵)² / 2 = 2 × 10¹⁰` 次搬移，大約要 200 秒。
改法：用 `std::queue` 或 `std::deque`，`pop` 是 `O(1)`；或用一個「頭指標」變數記錄目前的開頭，不要真的刪（第 05 課的環狀佇列）。

**E5 → 會**
`10000 × 10000 = 10⁸` 個 `int`，每個 4 bytes → `4 × 10⁸` bytes = **400 MB**，超過 256 MB → MLE。
而且如果寫在函式裡（區域變數），它會放在 stack 區，連 8 MB 都放不下，直接當掉。

**E6 → `O(n log n)` 或 `O(n)`**
`3 × 10⁵` 的 `n²` 是 `9 × 10¹⁰`（太慢）；`n log n` ≈ `5.4 × 10⁶`（很快）。
看到 `10⁵ ~ 10⁶` 的限制，就要想排序、heap、雜湊表、單調堆疊、雙指標這類方法。

## F. 最壞情況與攤銷 解說

**F1 → 每次最壞 `O(n)`，總共 `O(n²)`**
依序插入會讓樹變成一條往右的鏈（第 08 課）。插入第 `i` 個要往下走 `i-1` 步，
總共 `0 + 1 + ... + (n-1)` → `O(n²)`。
「BST 是 `O(log n)`」只有在樹 **平衡** 時才成立。這就是 `std::set` 用紅黑樹（會自動平衡）的原因。

**F2 → 約 `n²/20` 次，`O(n²)`**
容量在 `10, 20, 30, ...` 時滿，每次要搬目前所有元素：`10 + 20 + 30 + ... + n` ≈ `n² / 20`。
雖然除以 20，但還是 `n²` 等級。`n = 10⁶` 時是 `5 × 10¹⁰` 次搬移。

**F3 → 少於 `2n` 次，攤銷 `O(1)`**
容量在 `1, 2, 4, 8, ...` 時滿，搬移次數 `1 + 2 + 4 + ... + n < 2n`。
`n` 次 push 總共 `O(n)`，平均每次 `O(1)`。
F2 和 F3 對比：**加固定數量 → `O(n²)`；乘固定倍數 → `O(n)`**。這就是 `vector` 要加倍的原因。

**F4 → 很多 key 都算到同一個桶子（碰撞太多）**
雜湊表把 key 分到不同的桶子，如果大量的 key 剛好都算到同一個桶子，
查詢就要在那個桶子裡一個一個比，變成 `O(n)`。
可能是 key 有特定規律，或是有人故意構造測資（第 06 課、`10_hash_table` 題的 `anti_*` 測資）。

**F5 → 最好 `O(1)`，最壞 `O(n)`**
最好：第一個元素就是 `x`，比一次就結束。
最壞：`x` 在最後面或根本不存在，要比 `n` 次。
評測時以 **最壞情況** 為準 —— 出題者一定會放讓你最慢的測資。
