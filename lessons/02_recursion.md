# 第一部分：遞迴是什麼

## 1.1 遞迴 (Recursion)

**白話**：一個函式在執行的過程中，**呼叫自己** 來解決「比較小的同一個問題」。

**比喻**：俄羅斯娃娃。想知道最裡面那個娃娃長什麼樣子，你的做法是「打開這一個，然後對裡面那個娃娃做一樣的事」，直到打開後裡面沒有娃娃為止。

```cpp
// 算 1 + 2 + ... + n
int sum(int n) {
    if (n == 0) return 0;      // 打開後裡面沒有娃娃了
    return n + sum(n - 1);     // 打開這一個，對裡面那個做一樣的事
}
```

## 1.2 遞迴的三個要素

### 要素 1：終止條件 (Base Case)

**白話**：問題小到可以 **直接回答** 的情況，遞迴在這裡停下來。

**比喻**：排隊時問「你前面有幾個人？」，每個人都去問前面那個人再加 1。**排在第一個的人** 不用問別人，直接回答「0 個」—— 他就是終止條件。

沒有終止條件，函式會永遠呼叫自己，最後 **堆疊溢位 (stack overflow)**，程式當掉。

### 要素 2：縮小問題 (Reduce the Problem)

**白話**：每次遞迴呼叫時，問題一定要 **變小**，而且最後一定會變成終止條件。

```cpp
sum(n - 1);   // ✅ n 每次減 1，最後一定到 0
sum(n);       // ❌ 問題沒變小，永遠停不下來
sum(n - 2);   // ⚠️ n 是奇數時會跳過 0，變成負數，永遠停不下來
```

### 要素 3：相信遞迴 (Recursive Leap of Faith)

**白話**：寫遞迴時，**假設** 對比較小的問題呼叫自己，一定會得到正確答案。你只要想「怎麼用小問題的答案，組出大問題的答案」。

**比喻**：你是公司主管，要算全公司的薪水總和。你不用自己去算每一個人，只要問每個直屬部門的經理「你們部門總共多少？」，再加上自己的薪水。你 **相信** 經理們會算對（他們也是用同樣的方法問他們的下屬）。

> 初學者最常卡住的地方，就是想在腦中把遞迴一層一層展開到底。不要這樣做！只要確認：**終止條件對、問題有變小、組合的方式對**，遞迴就是對的。（這其實就是數學歸納法。）

## 1.3 電腦怎麼執行遞迴：呼叫堆疊 (Call Stack)

**白話**：每呼叫一次函式，電腦就在 **呼叫堆疊** 上疊一個 **框架 (frame)**，記錄這次呼叫的參數、區域變數，以及「做完之後要回到哪裡」。函式 `return` 時，框架就被拿掉。

`sum(3)` 的執行過程：

```
呼叫 sum(3)          | sum(0) |  ← return 0
  呼叫 sum(2)        | sum(1) |  ← return 1 + 0 = 1
    呼叫 sum(1)      | sum(2) |  ← return 2 + 1 = 3
      呼叫 sum(0)    | sum(3) |  ← return 3 + 3 = 6
                     +--------+
                     呼叫堆疊最深的時候
```

先一路往下呼叫到終止條件（**遞 / 往下**），再一路把答案傳回來（**迴 / 往上**）——這就是「遞迴」兩個字的由來。

## 1.4 遞迴深度 (Recursion Depth)

**白話**：呼叫堆疊最多疊了幾層。`sum(n)` 的深度是 `n + 1`。

深度太大就會堆疊溢位。一般的 stack 區大約 8 MB，簡單的函式大約能疊 **十萬到幾十萬層**，複雜一點的更少。

# 第二部分：河內塔 (Tower of Hanoi)

## 2.1 題目

三根柱子 A、B、C。A 上疊著 `n` 個大小不同的圓盤，大的在下。要把全部移到 C，規則：

1. 一次只能移動一個圓盤（某根柱子最上面那個）。
2. 大的不能放在小的上面。

```
    |         |         |
   -+-        |         |       ← 圓盤 1（最小）
  --+--       |         |       ← 圓盤 2
 ---+---      |         |       ← 圓盤 3（最大）
=========================
    A         B         C
```

## 2.2 關鍵想法：用「相信遞迴」來想

先看 **最大的圓盤 `n`**。它一定要在某一步從 A 直接移到 C。在那一刻：
- A 上只剩它（不然它上面有東西，拿不起來）。
- C 是空的（不然它不能放上去 —— C 上的一定比它小）。
- 所以其他 `n-1` 個圓盤 **全部都在 B 上**。

於是解法自然就出來了：

1. 把上面 `n-1` 個從 A 搬到 B（C 當暫存）—— **這是一個比較小的河內塔！**
2. 把圓盤 `n` 從 A 搬到 C。
3. 把 `n-1` 個從 B 搬到 C（A 當暫存）—— **又是一個比較小的河內塔！**

步驟 1 和 3 要怎麼做？**不用管，相信遞迴。**

```cpp
// 把 n 個圓盤從 from 搬到 to，可以借用 via
void hanoi(int n, char from, char via, char to) {
    if (n == 0) return;                // 終止條件：沒有圓盤，什麼都不用做
    hanoi(n - 1, from, to, via);       // 1. n-1 個：from → via（借用 to）
    cout << "move disk " << n << " from " << from << " to " << to << '\n';  // 2.
    hanoi(n - 1, via, from, to);       // 3. n-1 個：via → to（借用 from）
}
```

注意參數的順序：第 1 步的「目的地」是 `via`，所以把 `to` 和 `via` 對調傳進去。

## 2.3 遞迴樹 (Recursion Tree)

**白話**：把每一次函式呼叫畫成一個節點，誰呼叫誰就連一條線，畫出來像一棵樹。用來看清楚遞迴到底做了什麼、做了幾次。

`n = 3` 的遞迴樹：

```
hanoi(3,A,B,C)
├── hanoi(2,A,C,B)
│   ├── hanoi(1,A,B,C)  → move 1 A→C       第 1 步
│   ├── move 2 A→B                          第 2 步
│   └── hanoi(1,C,A,B)  → move 1 C→B       第 3 步
├── move 3 A→C                              第 4 步 ← 正中間
└── hanoi(2,B,A,C)
    ├── hanoi(1,B,C,A)  → move 1 B→A       第 5 步
    ├── move 2 B→C                          第 6 步
    └── hanoi(1,A,B,C)  → move 1 A→C       第 7 步
```

## 2.4 遞迴關係式 (Recurrence Relation)：算步數

**白話**：用「小問題的答案」來表示「大問題的答案」的式子。

設 `T(n)` = 搬 `n` 個圓盤需要的步數：

```
T(0) = 0
T(n) = T(n-1) + 1 + T(n-1) = 2 T(n-1) + 1
```

算幾個看看：`T(1) = 1`、`T(2) = 3`、`T(3) = 7`、`T(4) = 15` …… 規律是 **`T(n) = 2ⁿ - 1`**。

這也是 **最少** 的步數（第 2.2 節的推理說明了每一步都是必要的）。

**指數成長有多可怕？** 傳說中的河內塔有 64 個圓盤，要 `2⁶⁴ - 1 ≈ 1.8 × 10¹⁹` 步。每秒搬一次，要 5800 億年。

## 2.5 進階：不走完也能知道第 k 步（`02_hanoi_kth`）

觀察遞迴樹：`hanoi(n)` 一共 `2ⁿ - 1` 步，分成三段：

| 段落 | 步數 | 內容 |
|---|---|---|
| 前段 | 第 `1` ~ `2ⁿ⁻¹ - 1` 步 | `hanoi(n-1, from, to, via)` |
| 中間 | 第 `2ⁿ⁻¹` 步 | 搬圓盤 `n`：`from → to` |
| 後段 | 第 `2ⁿ⁻¹ + 1` ~ `2ⁿ - 1` 步 | `hanoi(n-1, via, from, to)` |

所以要找第 `k` 步：
- `k` 剛好是中間 → 答案就是「圓盤 `n`」。
- `k` 在前段 → 只往前段遞迴（另一半完全不用看）。
- `k` 在後段 → `k` 減掉前面的 `2ⁿ⁻¹`，往後段遞迴。

每次 `n` 減 1，最多 `n` 次就找到 → **`O(n)`**，`n = 60` 也是一瞬間。

**比喻**：查字典時不會從第一頁翻到最後一頁，而是「翻到中間，看要往前還是往後，只翻那一半」。

> 注意：`2⁵⁹` 超過 `int`，要寫 `1LL << 59`。

# 第三部分：回溯法 (Backtracking)

## 3.1 列舉 (Enumeration) / 暴力法 (Brute Force)

**白話**：把所有可能的答案 **一個一個試**，看哪些符合條件。

**比喻**：忘記 3 位數密碼鎖的密碼，就從 000 試到 999。

暴力法一定找得到答案，但可能非常慢。

## 3.2 回溯法 (Backtracking)

**白話**：一步一步做選擇。每做一個選擇就往下走；如果發現 **這條路走不通**，就 **退回上一步**，改做另一個選擇。

**比喻**：走迷宮。到了岔路就選一條走；走到死路，就退回上一個岔路口，換另一條路。

回溯法的程式碼幾乎都長這樣：

```cpp
void backtrack(目前的狀態) {
    if (已經完成) { 記錄答案; return; }
    for (每一個可以做的選擇) {
        if (這個選擇不合法) continue;   // 剪枝
        做這個選擇;
        backtrack(下一個狀態);
        撤銷這個選擇;                  // ← 「回溯」：恢復原狀，才能試下一個選擇
    }
}
```

## 3.3 狀態 (State)

**白話**：「目前做到哪裡、已經做了哪些選擇」的完整紀錄。

例如排列問題的狀態是「目前已經排好的數字」和「哪些數字用過了」。

## 3.4 撤銷選擇 (Undo)

**白話**：遞迴回來之後，把剛剛做的改變 **還原**，讓狀態回到做選擇之前的樣子。

**比喻**：試穿衣服。試完一件要脫下來，才能試下一件。如果忘了脫，就會越穿越多件。

忘記撤銷是回溯法最常見的錯誤。

## 3.5 範例：列出 1 ~ n 的所有排列 (Permutation)

**排列**：把 `n` 個東西排成一列的所有方法，共 `n!` 種。`n = 3` 有 6 種：`123 132 213 231 312 321`。

```cpp
int n;
vector<int> cur;        // 狀態：目前排好的數字
vector<bool> used;      // 狀態：哪些數字已經用過

void perm() {
    if ((int)cur.size() == n) {                  // 完成：n 個都排好了
        for (int x : cur) cout << x << ' ';
        cout << '\n';
        return;
    }
    for (int x = 1; x <= n; x++) {               // 每一個可以選的數字
        if (used[x]) continue;                   // 用過了，不能選
        used[x] = true;  cur.push_back(x);       // 做選擇
        perm();                                  // 往下走
        used[x] = false; cur.pop_back();         // 撤銷選擇
    }
}
```

## 3.6 剪枝 (Pruning)

**白話**：在走下去 **之前** 就發現「這條路一定不會成功」，直接不走。越早剪越好。

**比喻**：修剪樹枝。整根枝幹都是壞的，就從根部剪掉，不用等它長出一堆葉子再一片片摘。

剪枝不會改變答案，但能 **大幅減少** 要試的數量。

## 3.7 N 皇后 (N-Queens)

在 `n × n` 的棋盤上放 `n` 個皇后，任兩個不能在同一列、同一行、同一條斜線上。

**沒有剪枝的暴力法**：每一列選一個位置，總共 `nⁿ` 種，`n = 13` 時大約 `3 × 10¹⁴` 種，跑不完。

**回溯 + 剪枝**：一列一列放，每放一個就檢查會不會衝突，衝突就馬上換位置。

快速檢查衝突的技巧（`r` 是列、`c` 是行）：

| 衝突種類 | 同一條線上的格子有什麼共同點 | 用什麼陣列記錄 |
|---|---|---|
| 同一行 | `c` 相同 | `col[c]` |
| 「/」斜線 | `r + c` 相同 | `diag1[r + c]` |
| 「\」斜線 | `r - c` 相同 | `diag2[r - c + n - 1]`（加 `n-1` 避免負數索引） |

```
「/」斜線上的格子 r + c 都一樣：     「\」斜線上的格子 r - c 都一樣：
  (0,2) (1,1) (2,0) → 都是 2           (0,0) (1,1) (2,2) → 都是 0
```

這樣檢查是 `O(1)`。`n = 13` 時只需要試幾百萬個狀態，一秒內就跑完。

# 第四部分：遞迴的成本與陷阱

## 4.1 時間成本：數遞迴樹的節點

| 遞迴的樣子 | 遞迴樹 | 時間複雜度 |
|---|---|---|
| 呼叫自己 1 次，`n` 減 1（`sum`） | 一條鏈，`n` 個節點 | `O(n)` |
| 呼叫自己 1 次，`n` 減半（第 k 步、二分搜尋） | 一條鏈，`log n` 個節點 | `O(log n)` |
| 呼叫自己 2 次，`n` 減 1（河內塔） | 每層加倍，`2ⁿ` 個節點 | `O(2ⁿ)` |
| 每層試 `n` 個選擇（排列） | `n!` 片葉子 | `O(n × n!)` |

## 4.2 重複計算 (Overlapping Subproblems)

**白話**：同一個小問題被算了很多次，浪費時間。

經典例子 —— 費氏數列 (Fibonacci) `F(n) = F(n-1) + F(n-2)`：

```cpp
long long fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);   // fib(n-2) 在 fib(n-1) 裡面又被算一次！
}
```

`fib(50)` 要呼叫幾百億次。解法是 **記憶化 (memoization)**：算過的答案存起來，下次直接拿。

```cpp
long long memo[100];   // 0 代表還沒算過
long long fib(int n) {
    if (n <= 1) return n;
    if (memo[n]) return memo[n];
    return memo[n] = fib(n - 1) + fib(n - 2);   // 每個 n 只算一次 → O(n)
}
```

**比喻**：寫考卷時，把算過的答案寫在草稿紙上，下次遇到同一題就直接抄，不用重算。

（這就是「動態規劃 Dynamic Programming」的入門概念。）

## 4.3 堆疊溢位 (Stack Overflow)

遞迴深度太大時會當掉（評測結果是 **RE**）。容易出事的情況：
- 對一條很長的鏈結串列遞迴（深度 = 長度）。
- 對退化成一條鏈的樹遞迴。
- 在很大的迷宮上做 DFS（深度可能是幾十萬）。

**解法**：改成迴圈，或自己用 `stack` 容器模擬呼叫堆疊（因為容器放在 heap 區，空間大很多）。

## 4.4 遞迴 vs 迴圈 (Recursion vs Iteration)

| | 遞迴 | 迴圈 |
|---|---|---|
| 寫起來 | 問題本身就是遞迴結構時（樹、河內塔）很簡潔 | 有時候要自己管理很多狀態 |
| 速度 | 每次呼叫有一點額外成本 | 稍快 |
| 深度限制 | 有，太深會堆疊溢位 | 沒有 |

任何遞迴都能改寫成迴圈（例如 `02_hanoi_kth` 的標準解就是用 `while` 迴圈）。

# 小測驗

1. 下面的函式有什麼問題？

```cpp
int f(int n) {
    return n * f(n - 1);
}
```

2. `hanoi(5, ...)` 總共會印出幾步？其中圓盤 5 是第幾步移動的？
3. 回溯法裡，如果忘了「撤銷選擇」會發生什麼事？
4. N 皇后中，`(1, 3)` 和 `(3, 1)` 在同一條斜線上嗎？是哪一種斜線？
5. 遞迴版的 `fib(n)`（沒有記憶化）為什麼很慢？要怎麼改？
6. 為什麼在 `1000 × 1000` 的迷宮上用遞迴 DFS 可能會 RE？

### 答案

1. 沒有 **終止條件**，`n` 會一直減下去變成負數，永遠不停，最後 **堆疊溢位**。要加上 `if (n == 0) return 1;`。
2. `2⁵ - 1 = 31` 步。圓盤 5 在正中間，是第 `2⁴ = 16` 步。
3. 狀態會殘留上一次選擇的痕跡。例如排列問題中 `used[x]` 一直是 `true`，之後的分支就不能再用 `x`，會漏掉很多答案。
4. 是。`1 + 3 = 4`、`3 + 1 = 4`，`r + c` 相同 → 同一條「/」斜線。
5. 因為有 **重複子問題**，同一個 `fib(k)` 被算了非常多次，時間是指數級。用 **記憶化** 把算過的存起來，變成 `O(n)`。
6. 遞迴深度可能等於路徑長度，蛇形迷宮可達 50 萬層，超過 stack 區的大小 → **堆疊溢位**。應該改用 BFS（第 09 課）或自己用 `stack` 容器。
