# 第一部分：測試的基本觀念

## 1.1 範例只是「最基本」的檢查

題目附的範例通常只是用來 **說明題意**，很少包含刁鑽的情況。
評測系統的測資才是真正的考驗：它會包含極端值、最大範圍、各種特殊形狀。

**比喻**：駕照路考只考幾個項目，但真正上路會遇到下雨、塞車、有人突然衝出來。

## 1.2 測資的三種類型

| 類型 | 目的 | 例子 |
|---|---|---|
| **邊界測資 (Corner / Edge Case)** | 檢查特殊情況有沒有處理 | 空的、只有 1 個、全部一樣 |
| **隨機測資 (Random Test)** | 檢查一般情況的正確性 | 隨機產生的陣列 |
| **極限測資 (Stress / Max Test)** | 檢查 **時間複雜度** 和 **記憶體** | `n` 是上限、最壞的形狀 |

這個平台的測資就是這樣分的：`corner_*`、`random_small_*`、`random_medium_*`、`random_large_*`。

## 1.3 反例 (Counterexample)

**白話**：一筆 **會讓你的程式出錯** 的輸入。找到反例，除錯就成功一半了。

最好的反例是 **小** 的：小到可以用手算出正確答案，再一步一步追蹤你的程式哪裡算錯。

# 第二部分：找 corner case 的清單

拿到題目後，對每一項問自己：「**這個情況，我的程式會怎樣？**」

## 2.1 大小的邊界

| 檢查 | 常見的錯 |
|---|---|
| **最小**：`n = 0`、`n = 1`、空字串、空的容器 | 迴圈沒跑、存取 `a[0]` 越界、`v.size() - 1` 變成超大的數 |
| **最大**：`n` 等於上限 | TLE、溢位、堆疊溢位、陣列開太小 |
| **剛好**：容量剛好滿、`k = n`、`k = 1` | 差一錯誤 (off-by-one) |

**差一錯誤 (Off-by-one Error)**：迴圈多跑或少跑一次、範圍多算或少算一個。例如 `<` 和 `<=` 寫錯。

**比喻**：一條 10 公尺的路，每隔 1 公尺種一棵樹，要種幾棵？是 11 棵，不是 10 棵。

## 2.2 數值的邊界

| 檢查 | 常見的錯 |
|---|---|
| 負數、0 | 負數取餘數是負的、除以 0 |
| `int` 的極值 `-2³¹`、`2³¹ - 1` | 取絕對值、相減、相加時溢位 |
| `±10¹⁸` | 兩個相加超過 `long long` |
| 結果很大 | 答案要用 `long long`，例如很多個 `int` 相加 |

## 2.3 結構的特殊形狀

| 結構 | 特殊形狀 |
|---|---|
| 陣列 | 全部相同、嚴格遞增、嚴格遞減、交錯（大小大小）|
| 樹 | 一條鏈（退化）、星狀（一個中心連所有點）、只有根 |
| 圖 | 不連通、有自環、有重邊、有環、只有一個點、沒有邊 |
| 網格 | `1 × n`、`n × 1`、全是牆、起點被包圍、蛇形長路 |
| 字串 | 只有一種字元、長度 1、全部都是同一個字 |

**全部相同** 特別重要：很多 bug 出在「`<` 還是 `<=`」、「嚴格大於還是大於等於」。

## 2.4 操作序列的特殊情況

- 對 **空的** 結構做刪除 / 查詢。
- **刪光之後再加入**（頭尾指標有沒有重設？）。
- 同一個元素 **重複加入**、**重複刪除**。
- 刪除 **第一個**、**最後一個**、**唯一一個**。
- 查詢 **不存在** 的東西。

## 2.5 輸出格式

- 每行結尾、最後要不要換行（本平台忽略行尾空白和結尾空行）。
- 「無解」時要輸出什麼？（`-1`、`IMPOSSIBLE`、`none`……照題目寫）
- 不要印多餘的提示文字或除錯訊息（除錯訊息請印到 `cerr`，不會被評測）。

```cpp
cerr << "debug: x = " << x << '\n';   // 印到 stderr，不影響評測結果
```

> 在這個平台上，`corner_xxx` 測資的名稱就是在告訴你它測什麼。
> 建議：做題前 **先自己列出你想到的 corner case**，寫完再去「測資」分頁對照，看看漏了哪些。

# 第三部分：讓程式自己告訴你錯在哪

## 3.1 斷言 (Assertion)

**白話**：在程式裡寫下「**這裡一定要成立**」的條件。如果不成立，程式立刻停下來，告訴你是哪一行。

**比喻**：工廠生產線上的檢查站。每一站都檢查產品合不合格，有問題就立刻停機，不要等到出貨才發現。

```cpp
#include <cassert>
assert(i >= 0 && i < n);         // 越界就停下來
assert(!st.empty());             // 空的時候不該走到這裡
```

失敗時會印出類似 `Assertion 'i >= 0 && i < n' failed`，並顯示行號。

## 3.2 消毒器 / 檢查器 (Sanitizer)

**白話**：編譯器提供的檢查工具。開啟後，程式執行時會 **自動檢查** 各種記憶體錯誤和未定義行為，出事時告訴你是 **哪一行**。

```bash
python3 judge.py test 04_linked_list --debug
```

等同於用這些參數編譯：

```bash
g++ -std=c++17 -g -fsanitize=address,undefined -D_GLIBCXX_DEBUG my.cpp
```

| 參數 | 名稱 | 會抓到什麼 |
|---|---|---|
| `address` | AddressSanitizer (ASan) | 陣列越界、使用已釋放的記憶體 (use-after-free)、記憶體洩漏 |
| `undefined` | UndefinedBehaviorSanitizer (UBSan) | 有號整數溢位、空指標、位移太多位 |
| `_GLIBCXX_DEBUG` | STL 除錯模式 | `vector` 越界、對空的 `stack` 呼叫 `top()` |
| `-g` | 除錯資訊 | 讓錯誤訊息能顯示 **行號** |

程式會變慢 2 ~ 5 倍（所以 debug 模式的時間限制放寬 4 倍），但錯誤訊息非常清楚。

**比喻**：一般模式是在黑暗中開車，撞到東西才知道；debug 模式是開了車燈加倒車雷達。

## 3.3 看懂錯誤訊息

ASan 的錯誤訊息很長，重點看這幾行：

```
==12345==ERROR: AddressSanitizer: heap-use-after-free on address ...
    #0 0x... in LinkedList::erase(int) main.cpp:52        ← 出錯的地方
    #1 0x... in main main.cpp:98                          ← 誰呼叫它的
freed by thread T0 here:
    #0 0x... in operator delete(void*)
    #1 0x... in LinkedList::erase(int) main.cpp:50        ← 在哪裡被 delete 的
```

| 錯誤類型 | 意思 |
|---|---|
| `heap-buffer-overflow` | 用 `new` / `vector` 配置的陣列越界 |
| `stack-buffer-overflow` | 區域陣列越界 |
| `heap-use-after-free` | 使用已經 `delete` 的記憶體 |
| `SEGV on unknown address 0x000000000000` | 存取空指標 |
| `signed integer overflow` | 有號整數溢位 |
| `stack-overflow` | 遞迴太深 |

# 第四部分：對拍 (Stress Testing)

## 4.1 對拍是什麼

**白話**：寫一個 **暴力但一定對** 的版本，用大量 **隨機小測資** 同時跑兩個程式，比較輸出，直到找到 **不一樣** 的那一筆。

「對拍」這個名稱來自中國的程式競賽圈，英文叫 stress testing 或 random testing。

**比喻**：新的計算機不確定準不準，就拿一台確定沒問題的舊計算機，兩台同時算 1000 道隨機的題目，看哪一題答案不一樣。

## 4.2 為什麼一定要用「小」測資？

1. 小測資跑得快，一秒能比對幾百筆。
2. **找到反例後，可以用手算出正確答案**，一步一步追蹤你的程式。
3. 很多 bug 在很小的輸入就會出現（例如 `n = 1`、兩個元素相等）。

**值的範圍也要小**：`randint(-10⁹, 10⁹)` 幾乎不會產生兩個相等的數，就永遠測不到「相等」的情況。用 `randint(-5, 5)` 很容易出現重複。

## 4.3 平台內建的對拍

這個平台已經幫你寫好了，標準解就是「一定對的版本」：

```bash
python3 judge.py stress 06_min_stack           # 比對 300 筆隨機小測資
python3 judge.py stress 06_min_stack -n 2000   # 比對 2000 筆
```

找到反例後會存在 `workspace/<題目>.failed.in`，可以這樣重現：

```bash
python3 judge.py run workspace/06_min_stack.cpp workspace/06_min_stack.failed.in
```

## 4.4 自己寫對拍（沒有標準解的時候）

1. **`brute.cpp`**：暴力解。越簡單越好，簡單到不可能錯（例如 next greater 用雙層迴圈 `O(n²)`）。
2. **`gen.py`**：隨機產生小測資。
3. **比對腳本**：

```bash
g++ -O2 -o mine mine.cpp && g++ -O2 -o brute brute.cpp
for i in $(seq 1 1000); do
    python3 gen.py $i > in.txt          # 用 i 當 seed，每次都不一樣
    ./mine  < in.txt > out1.txt
    ./brute < in.txt > out2.txt
    if ! diff -wq out1.txt out2.txt > /dev/null; then
        echo "第 $i 筆不同："
        cat in.txt
        break
    fi
done
```

`gen.py` 範例：

```python
import random, sys
rng = random.Random(int(sys.argv[1]))      # 用 seed，同一個 i 每次產生一樣的測資
n = rng.randint(1, 8)                      # 小！方便手算
print(n)
print(*[rng.randint(-5, 5) for _ in range(n)])   # 值的範圍也小，才會出現重複
```

## 4.5 種子 (Seed)

**白話**：隨機數產生器的 **起始值**。同一個 seed 每次產生的「隨機數」都 **一模一樣**。

**比喻**：洗牌的手法。用同一套手法洗同一副牌，結果每次都一樣。

為什麼重要？找到反例後，用同一個 seed 就能 **重現** 同一筆測資，不會「剛剛明明有錯，再跑一次就不見了」。

這個平台的 `gen` 和 `stress` 都可以指定 `--seed`。

# 第五部分：自己寫測資產生器

## 5.1 平台的產生器格式

想新增題目，或幫現有題目加測資，看任何一題的 `gen.py`：

```python
TITLE = "題目名稱"
TOPIC = "主題"
DIFFICULTY = "★★☆"
TIME_LIMIT = 1.0          # 秒

def manual_cases():
    """手工設計的 corner case，回傳 [(名稱, 輸入字串), ...]
    名稱會變成 corner_名稱，所以請取一個看得懂的名字"""
    return [
        ("n1", "1\n5"),
        ("all_equal", "4\n3 3 3 3"),
    ]

def random_case(rng, size):
    """size 是 'small' / 'medium' / 'large'；rng 是 random.Random"""
    n = {"small": rng.randint(1, 8), "medium": 1000}.get(size, 200000)
    v = 5 if size == "small" else 10**9
    return f"{n}\n" + " ".join(str(rng.randint(-v, v)) for _ in range(n))
```

## 5.2 卡掉錯誤解法的測資 (Anti-test)

好的極限測資不只是「`n` 很大」，還要 **專門讓錯誤的做法變慢或出錯**：

| 要卡掉的錯誤 | 測資怎麼設計 | 本平台的例子 |
|---|---|---|
| `O(n²)` 暴力 | `n` 開到上限 | 每題的 `random_large` |
| 雜湊函數太簡單 | key 都是某個數的倍數，全部碰撞 | `10_hash_table` 的 `anti_*` |
| 併查集沒優化 | 讓樹變成一條長鏈 | `14_union_find` 的 `long_chain` |
| BST 沒平衡 | 依序插入 | `13_bst` 的 `skewed_*` |
| 遞迴 DFS | 很長的路徑讓遞迴很深 | `15_maze_bfs` 的 `serpentine_*` |
| 單調堆疊寫錯成 `O(n²)` | 遞減陣列（每個元素都要等很久） | `08_next_greater` 的 `big_decreasing_then_max` |

**比喻**：設計考題時，不只出「會就能答對」的題目，還要出「**常見的錯誤觀念一定會答錯**」的題目，才能分辨誰真的懂。

# 除錯流程總結

1. **範例過了嗎？** 沒過就先從範例開始手動追蹤。
2. **自己列 corner case**，用網頁版的「自訂輸入」一個一個試。
3. **WA**：看失敗測資的名稱、看第幾行不一樣，想想那個 corner case 你有沒有處理。
4. **RE**：用 `--debug` 跑，看錯誤訊息指出的行號。
5. **TLE**：重新算複雜度；檢查有沒有加速 I/O、有沒有用 `endl`、STL 操作有沒有隱藏成本（見 `01b_complexity_exam.md` C 大題）。
6. **還是找不到**：**對拍**。

# 小測驗

1. 題目：「給 `n` 個整數，輸出最大值」。請列出至少 4 個 corner case。
2. 對拍時，為什麼隨機值的範圍要設成 `-5 ~ 5` 而不是 `-10⁹ ~ 10⁹`？
3. 你的程式 RE 了，下一步應該做什麼？
4. 為什麼產生測資要固定 seed？
5. 你寫了一個雜湊表，隨機測資都過了，但某一筆大測資 TLE。可能是什麼原因？
6. 除錯時想印出變數的值，又不想影響評測結果，要怎麼印？

### 答案

1. 例如：`n = 1`；全部是負數（初始值設成 0 的話會錯）；全部相同；最大值在第一個 / 最後一個；值是 `int` 的極值 `-2³¹`（初始值設成 `-1e9` 的話會錯）。
2. 小範圍才容易產生 **重複的值** 和 **特殊排列**（例如全部相同），很多 bug 只在這些情況出現。而且小數字方便手算。
3. 用 `--debug` 模式重跑（`python3 judge.py test <題目> --debug`），看 sanitizer 指出的 **錯誤類型** 和 **行號**。
4. 才能 **重現** 同一筆測資。找到反例後要反覆修改、反覆測試，如果測資每次都不一樣就沒辦法確認有沒有修好。
5. 大測資的 key 可能有 **規律**（例如都是 2 的次方的倍數），讓你的雜湊函數把它們全部放進同一個桶子，退化成 `O(n)`。要用能打亂位元的雜湊函數（第 06 課）。
6. 印到 `cerr`（標準錯誤輸出），評測只比對 `cout` 的內容。
