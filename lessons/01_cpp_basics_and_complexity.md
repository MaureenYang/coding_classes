# 第一部分：程式是怎麼跑起來的

## 1.1 原始碼 (Source Code)

**白話**：你用人看得懂的文字寫出來的程式，例如 `main.cpp`。

**比喻**：一份用中文寫的食譜。人看得懂，但機器（電腦的 CPU）看不懂。

## 1.2 編譯 / 編譯器 (Compile / Compiler)

**白話**：把原始碼翻譯成電腦看得懂的機器碼。負責翻譯的程式叫 **編譯器**，我們用的是 `g++`。

**比喻**：翻譯社把中文食譜翻成機器人看得懂的指令。翻譯時如果發現文法錯誤（例如少了分號），就會拒絕翻譯 —— 這就是 **編譯錯誤 (Compile Error, CE)**。

```bash
g++ -std=c++17 -O2 main.cpp -o main
#    ^C++ 版本  ^最佳化  ^原始碼   ^輸出的執行檔名稱
```

## 1.3 執行檔 (Executable)

**白話**：編譯出來的成品，可以直接執行（`./main`）。

```
main.cpp ──(g++ 編譯)──▶ main ──(執行)──▶ 結果
 原始碼                  執行檔
```

## 1.4 標準輸入 / 標準輸出 (stdin / stdout)

**白話**：
- **標準輸入 (stdin)**：程式「讀資料」的地方。平常是鍵盤，評測時是測資檔案。
- **標準輸出 (stdout)**：程式「印結果」的地方。平常是螢幕，評測時會被收集起來和正確答案比對。

```cpp
int n;
cin >> n;              // 從 stdin 讀一個整數
cout << n * 2 << '\n'; // 印到 stdout
```

**這就是評測系統的運作方式**：

```
測資 .in ──▶ [你的程式] ──▶ 你的輸出 ──┐
                                        ├──▶ 比對 ──▶ AC / WA
測資 .out（正確答案）───────────────────┘
```

> 所以 **不要印多餘的東西**（例如「請輸入數字：」），那也會被當成輸出拿去比對，結果就是 WA。

## 1.5 測資 (Test Case / Test Data)

**白話**：一組「輸入 + 正確輸出」，用來檢查程式對不對。

## 1.6 邊界情況 (Corner Case / Edge Case)

**白話**：在「極端」或「特殊」條件下的輸入，最容易讓程式出錯。

**比喻**：測試一台電梯，不能只試「3 個人搭到 5 樓」，還要試「0 個人」、「剛好滿載」、「超重」、「從 1 樓到 1 樓」。

常見的 corner case：空的、只有 1 個、最大值、負數、全部一樣、重複的值。（第 11 課會詳細教）

# 第二部分：記憶體

## 2.1 記憶體 (Memory / RAM)

**白話**：程式執行時用來放資料的地方。可以想成一排很長的格子，每一格是 **1 個位元組 (byte)**，每一格都有一個編號，叫做 **位址 (address)**。

```
位址:   1000  1001  1002  1003  1004  1005  ...
       +-----+-----+-----+-----+-----+-----+
       |     |     |     |     |     |     | ...
       +-----+-----+-----+-----+-----+-----+
```

**比喻**：一整條街的房子，每間房子都有門牌號碼（位址），裡面放著東西（資料）。

## 2.2 位元 / 位元組 (Bit / Byte)

- **位元 (bit)**：最小單位，只能是 `0` 或 `1`。
- **位元組 (byte)**：8 個 bit。8 個 bit 有 `2^8 = 256` 種組合，所以 1 byte 能表示 256 種不同的值。

`int` 通常佔 **4 bytes = 32 bits**，所以能表示 `2^32` 種不同的值（大約 43 億種）。

## 2.3 變數 (Variable)

**白話**：一塊有名字的記憶體，用來存一個值。

```cpp
int age = 20;   // 跟記憶體要 4 bytes，取名叫 age，放入 20
```

**比喻**：一個貼了標籤的盒子。標籤是名字 `age`，盒子的大小由 **型別** `int` 決定。

## 2.4 Stack 記憶體 vs Heap 記憶體

程式的記憶體分成好幾區，最重要的是這兩個：

| | Stack（堆疊區） | Heap（堆積區） |
|---|---|---|
| 放什麼 | 函式裡的區域變數、函式參數 | 用 `new` 要來的記憶體 |
| 誰管理 | 自動：函式結束就自動清掉 | 你自己：要用 `delete` 還回去 |
| 大小 | 小（通常 8 MB） | 大（可以用到整台電腦的記憶體） |
| 速度 | 很快 | 稍慢 |

**比喻**：
- **Stack** 像是餐廳的托盤：吃飯時拿一個，吃完就自動收走。但托盤不能疊太高。
- **Heap** 像是租倉庫：可以租很大的空間，用多久都行，但 **不用了要自己去退租**，不然會一直佔著（這叫 **記憶體洩漏 memory leak**）。

```cpp
void f() {
    int x = 5;              // x 在 stack 上，f 結束時自動消失
    int* p = new int(7);    // 7 存在 heap 上，p（指標本身）在 stack 上
    delete p;               // 手動把 heap 上的空間還回去
}
```

> ⚠️ 注意：記憶體的「stack 區」、「heap 區」，和後面要學的資料結構「stack（堆疊）」、「heap（堆積）」**名字一樣但不是同一個東西**。只是剛好都叫這個名字。

## 2.5 呼叫堆疊 (Call Stack) 與堆疊溢位 (Stack Overflow)

**白話**：每次呼叫函式，就會在 stack 區放一個 **框架 (frame)**，裡面放這次呼叫的參數和區域變數。函式結束時把框架拿掉。

```
main 呼叫 f，f 呼叫 g：

  | g 的框架 |  ← 最上面：正在執行的函式
  | f 的框架 |
  | main 框架 |
  +----------+
```

**堆疊溢位 (stack overflow)**：函式一層呼叫一層，疊太多層（例如遞迴 100 萬層），超過 stack 區的大小，程式就會當掉（評測結果是 **RE**）。

**比喻**：托盤疊到天花板，倒了。

# 第三部分：C++ 必備語法觀念

## 3.1 型別 (Type)

**白話**：告訴電腦「這個變數存的是哪一種資料」，同時決定它佔多少記憶體、能存的範圍。

| 型別 | 大小 | 範圍（大約） | 用途 |
|---|---|---|---|
| `bool` | 1 byte | `true` / `false` | 是非 |
| `char` | 1 byte | `-128 ~ 127` | 一個字元，例如 `'A'` |
| `int` | 4 bytes | `±2.1 × 10^9`（約 ±21 億） | 一般整數 |
| `long long` | 8 bytes | `±9.2 × 10^18` | 很大的整數 |
| `unsigned long long` | 8 bytes | `0 ~ 1.8 × 10^19` | 不會是負數的大整數 |
| `double` | 8 bytes | 約 15~16 位有效數字 | 小數 |

**記法**：`int` 大約到 `2 × 10^9`；`long long` 大約到 `9 × 10^18`。題目數字超過 `10^9` 就要想到 `long long`。

## 3.2 有號 / 無號 (Signed / Unsigned)

- **有號 (signed)**：可以是負數，例如 `int`。
- **無號 (unsigned)**：只能是 0 或正數，例如 `unsigned int`、`size_t`。

**陷阱**：無號數「往下減到 0 以下」會繞回最大值！

```cpp
vector<int> v;               // 空的
cout << v.size() - 1;        // 不是 -1，而是 18446744073709551615
```

`v.size()` 回傳的是無號數 `size_t`，`0 - 1` 會繞回最大值。所以這樣寫很危險：

```cpp
for (int i = 0; i < v.size() - 1; i++)       // v 是空的 → 迴圈幾乎跑不完
for (int i = 0; i + 1 < (int)v.size(); i++)  // 安全的寫法
```

## 3.3 溢位 (Overflow)

**白話**：數字超過型別能存的範圍，結果就會出錯（常常變成奇怪的負數）。

**比喻**：汽車里程表只有 6 位數，開到 999999 公里之後再開 1 公里，就變回 000000。

```cpp
int a = 2000000000, b = 2000000000;
int c = a + b;                 // 溢位！結果是錯的
long long d = (long long)a + b; // 正確：先轉成 long long 再加

int x = 1 << 40;               // 溢位！1 是 int
long long y = 1LL << 40;       // 正確：1LL 是 long long
```

## 3.4 陣列 (Array) 與索引 (Index)

**白話**：一排 **連續的** 格子，每格放同型別的資料，用 **索引**（第幾格）來存取。**索引從 0 開始。**

```cpp
int a[5] = {12, 7, 33, -4, 9};
//  索引:     0  1   2   3  4
cout << a[2];   // 33
```

**比喻**：一排置物櫃，編號 0 到 4。

**越界 (out of bounds)**：存取不存在的格子，例如 `a[5]` 或 `a[-1]`。C++ **不會** 幫你檢查，可能讀到垃圾值、也可能直接當掉。這是最常見的 RE 原因。

## 3.5 指標 (Pointer)

**白話**：一個存放「**位址**」的變數。它不存資料本身，而是存「資料放在哪裡」。

**比喻**：一張寫著門牌號碼的紙條。紙條本身不是房子，但照著它可以找到房子。

```cpp
int x = 42;
int* p = &x;      // &x：取得 x 的位址；p 存的就是這個位址
cout << *p;       // *p：照著位址去找，拿到 42（這個動作叫「解參考 dereference」）
*p = 100;         // 透過指標修改 x，現在 x == 100
```

| 寫法 | 意思 |
|---|---|
| `int* p` | 宣告一個「指向 int 的指標」 |
| `&x` | 取得 x 的位址 |
| `*p` | 取得 p 指向的那個值 |
| `p->val` | 等於 `(*p).val`，指標指向的 struct 的成員 |
| `nullptr` | 空指標：不指向任何東西 |

**空指標 (null pointer)**：值為 `nullptr` 的指標，代表「沒有指向任何東西」。對空指標做 `*p` 或 `p->val` 程式會當掉。鏈結串列、樹都用 `nullptr` 表示「後面沒有了」。

**懸空指標 (dangling pointer)**：指向的東西已經被 `delete` 了，但指標還留著舊位址。再用它就會出錯（**use-after-free**）。

## 3.6 參考 (Reference)

**白話**：幫一個已經存在的變數取 **別名**。對別名做任何事，就等於對原本的變數做。

**比喻**：「小明」和「明明」是同一個人。叫「明明」去洗碗，洗碗的就是小明。

```cpp
void addOne(int x)  { x++; }   // 傳值：x 是複製品，改它不影響外面
void addOne2(int& x) { x++; }  // 傳參考：x 就是外面那個變數

int a = 5;
addOne(a);   // a 還是 5
addOne2(a);  // a 變成 6
```

**為什麼重要？**
1. 想讓函式改到外面的變數。
2. 傳大東西（例如很大的 `vector`）時避免複製：`void f(const vector<int>& v)`。複製一個有 100 萬個元素的 vector 很花時間！

## 3.7 動態記憶體配置 (Dynamic Memory Allocation)

**白話**：程式執行到一半時，才決定要多少記憶體，用 `new` 跟系統要（在 heap 上），用 `delete` 還回去。

```cpp
int n;
cin >> n;
int* arr = new int[n];   // 執行時才知道 n 是多少
// ... 使用 arr[0] ~ arr[n-1] ...
delete[] arr;            // 陣列要用 delete[]
```

**記憶體洩漏 (memory leak)**：`new` 了卻忘記 `delete`，那塊記憶體就一直被佔著。程式跑久了記憶體會越用越多。

> 平常寫程式用 `vector` 就好，它會自動幫你管理記憶體。這個平台有些題目要你「不用 vector 自己做」，就是為了讓你學會這些底層觀念。

## 3.8 結構 / 類別 (struct / class)

**白話**：把好幾個相關的資料「包成一個新型別」，也可以包含操作它們的函式。

**比喻**：一張學生資料卡，上面有姓名、學號、成績 —— 這幾個欄位合起來才是「一個學生」。

```cpp
struct Node {
    int val;       // 成員變數 (member)
    Node* next;    // 指向下一個 Node 的指標
};

Node a;
a.val = 5;         // 用 . 存取成員
Node* p = &a;
p->val = 6;        // 透過指標用 -> 存取成員
```

`struct` 和 `class` 幾乎一樣，差別只在預設的存取權限：`struct` 預設是 `public`（外面可以存取），`class` 預設是 `private`（只有自己的函式可以存取）。

- **建構子 (constructor)**：物件「出生」時自動執行的函式，用來設定初始值。
- **解構子 (destructor)**：物件「消失」時自動執行的函式，寫成 `~類別名()`，常用來 `delete` 自己 `new` 過的記憶體。

## 3.9 函式與遞迴 (Function / Recursion)

- **函式 (function)**：一段有名字、可以重複使用的程式碼。
- **遞迴 (recursion)**：函式 **自己呼叫自己**。必須有 **終止條件 (base case)**，否則會無限呼叫下去，最後 stack overflow。

```cpp
int sum(int n) {             // 算 1 + 2 + ... + n
    if (n == 0) return 0;    // 終止條件
    return n + sum(n - 1);   // 自己呼叫自己，但問題變小了
}
```

## 3.10 STL、容器、迭代器 (STL / Container / Iterator)

- **STL (Standard Template Library，標準模板函式庫)**：C++ 內建的工具箱，裡面有寫好的資料結構和演算法。
- **容器 (container)**：STL 裡「裝資料的東西」，例如 `vector`、`stack`、`map`。
- **模板 (template)**：讓同一份程式碼可以用在不同型別上。`vector<int>` 和 `vector<string>` 用的是同一份 vector 程式，只是角括號裡的型別不同。
- **迭代器 (iterator)**：指向容器中某個元素的「游標」，用法很像指標。`v.begin()` 指向第一個元素，`v.end()` 指向「最後一個元素的 **下一個** 位置」（不是最後一個元素本身）。

```cpp
vector<int> v = {3, 1, 2};
sort(v.begin(), v.end());           // 排序整個範圍
for (auto it = v.begin(); it != v.end(); ++it) cout << *it << ' ';
for (int x : v) cout << x << ' ';   // 更簡單的寫法：range-based for
```

**STL 速查**（後面每一課會一個一個學）：

| 容器 | 中文 | 一句話說明 | 主要操作 |
|---|---|---|---|
| `vector<T>` | 動態陣列 | 會自動變大的陣列 | `push_back`, `pop_back`, `[i]`, `size` |
| `deque<T>` | 雙端佇列 | 頭尾都能快速加入刪除 | `push_front/back`, `pop_front/back` |
| `list<T>` | 雙向串列 | 已知位置時插入刪除很快 | `insert`, `erase`, `splice` |
| `stack<T>` | 堆疊 | 後進先出 | `push`, `pop`, `top` |
| `queue<T>` | 佇列 | 先進先出 | `push`, `pop`, `front` |
| `priority_queue<T>` | 優先佇列 | 隨時拿出最大值 | `push`, `pop`, `top` |
| `set<T>` / `map<K,V>` | 有序集合 / 對照表 | 自動排序，可找前後 | `insert`, `erase`, `find`, `lower_bound` |
| `unordered_map<K,V>` | 雜湊表 | 用 key 查 value，平均很快 | `[]`, `find`, `erase`, `count` |

## 3.11 未定義行為 (Undefined Behavior, UB)

**白話**：C++ 標準 **沒有規定** 會發生什麼事的寫法。結果可能是「看起來正常」、「算錯」或「當掉」，**而且換一台電腦、換一筆測資，結果可能就不一樣**。

**比喻**：闖紅燈。大部分時候好像沒事，但總有一天會出事，而且你無法預測是哪一天。

常見的未定義行為：
- 陣列越界 `a[n]`
- 對空指標或懸空指標解參考
- 對空的 `stack` 呼叫 `top()`、對空的 `vector` 呼叫 `back()`
- 有號整數溢位
- 函式說要回傳值，卻沒有 `return`

**怎麼抓？** 用這個平台的 `--debug` 模式（sanitizer，消毒器 / 檢查器），它會在出事的那一行停下來告訴你。

## 3.12 快速輸入輸出 (Fast I/O)

```cpp
int main() {
    ios::sync_with_stdio(false);  // 讓 cin/cout 不用跟 C 的 scanf/printf 同步，變快
    cin.tie(nullptr);             // 讀入前不用先清空輸出，變快
    ...
    cout << x << '\n';            // 用 '\n' 換行
}
```

**為什麼不用 `endl`？** `endl` = 換行 + **立刻把輸出送出去 (flush)**。每一行都 flush 很慢，輸出 10 萬行時差別可以到好幾倍。`'\n'` 只換行，會累積起來一次送出。

**比喻**：寄信。`endl` 是每寫一封就跑一趟郵局；`'\n'` 是寫完一疊再一起寄。

# 第四部分：資料結構是什麼

## 4.1 資料結構 (Data Structure)

**白話**：**資料怎麼存放** + **能對它做哪些操作、每個操作要花多少時間**。

**比喻**：同樣是 1000 本書：
- 隨便堆在地上 → 放書很快，找書要一本一本翻。
- 按書名排在書架上 → 放書要找位置（比較慢），找書很快（可以從中間開始找）。
- 用圖書館的索書號系統 → 找書和放書都快，但要先建好系統。

沒有「最好」的資料結構，只有「**最適合這個問題**」的資料結構。

## 4.2 操作 (Operation)

資料結構常見的操作：

| 操作 | 英文 | 意思 |
|---|---|---|
| 存取 | access | 拿第 i 個元素 |
| 搜尋 | search / find | 找某個值在不在、在哪裡 |
| 插入 | insert | 加入一個元素 |
| 刪除 | delete / erase | 拿掉一個元素 |
| 走訪 | traverse | 從頭到尾每個元素都看一次 |

## 4.3 抽象資料型別 (Abstract Data Type, ADT)

**白話**：只說「**能做什麼**」，不說「**怎麼做到**」的規格。

**比喻**：「自動販賣機」的規格是：投錢、按按鈕、出飲料。至於裡面是用齒輪還是電腦控制，使用者不用知道。

例如「stack」是一種 ADT：規格是 `push`、`pop`、`top`，後進先出。
你可以用陣列實作它，也可以用鏈結串列實作它 —— 這兩種是不同的 **實作 (implementation)**，但都符合 stack 的規格。

## 4.4 怎麼選？一張表看懂

| 你的需求 | 好的選擇 | 操作時間 |
|---|---|---|
| 用索引快速存取 | 陣列 / `vector` | `O(1)` |
| 在頭尾快速加入刪除 | `deque`、鏈結串列 | `O(1)` |
| 後進先出（復原、括號配對） | stack | `O(1)` |
| 先進先出（排隊、BFS） | queue | `O(1)` |
| 用 key 快速查詢 | 雜湊表 `unordered_map` | 平均 `O(1)` |
| 隨時拿出最小 / 最大值 | heap `priority_queue` | `O(log n)` |
| 資料要保持有序 | 平衡樹 `set` / `map` | `O(log n)` |
| 動態合併群組、判斷是否同組 | 併查集 | 幾乎 `O(1)` |

表格裡的 `O(1)`、`O(log n)` 是什麼？這就是第五部分要講的。

# 第五部分：時間複雜度

## 5.1 為什麼不直接用「秒數」比快慢？

同一個程式：
- 在新電腦上跑 0.1 秒，在舊電腦上跑 1 秒。
- 輸入 100 筆資料跑 0.001 秒，輸入 100 萬筆資料可能跑 10 秒，也可能跑 3 小時。

秒數會受電腦、輸入大小影響，沒辦法公平比較 **方法本身** 的好壞。

所以我們改問：**當輸入的量 `n` 變大時，要做的步驟數會怎麼增加？**

## 5.2 輸入規模 `n` (Input Size)

**白話**：輸入資料有「多大」。通常是陣列長度、操作次數、圖的點數等。題目的「限制」區塊會告訴你 `n` 最大是多少。

## 5.3 基本運算 (Basic Operation)

**白話**：花固定時間就能做完的小動作：一次加減乘除、一次比較、一次陣列存取 `a[i]`、一次賦值。
我們數的就是「**大約要做幾次基本運算**」。

## 5.4 時間複雜度 (Time Complexity) 與 Big-O 表示法

**白話**：時間複雜度描述「**步驟數隨著 `n` 長大的速度**」。我們用 **Big-O 符號** 寫成 `O(某個式子)`，讀作「Big-O of ...」或「O 的 ...」。

**Big-O 的兩條簡化規則：**

1. **只留成長最快的那一項**：`3n² + 5n + 100` → 只看 `n²`。
   因為 `n` 很大時（例如 `n = 100萬`），`n²` 是 1 兆，`5n` 才 500 萬，根本可以忽略。
2. **常數倍數不寫**：`3n²` → `n²`，`n/2` → `n`。
   因為常數倍數只跟電腦快慢一樣，不影響「成長的趨勢」。

所以 `3n² + 5n + 100` 的時間複雜度是 **`O(n²)`**。

**比喻**：比較兩種交通方式 —— 走路和開車。走路快一點或慢一點（常數倍數）不重要，重要的是距離變成 100 倍時，走路要多花 100 倍時間；而有些方式（例如每到一個路口都要繞回起點再出發）距離變 100 倍，時間會變 10000 倍。Big-O 看的是 **這種趨勢**。

> 嚴格來說，Big-O 是「**上界**」：`O(n²)` 代表「最多跟 `n²` 同等級」。不過平常說「這個演算法是 `O(n²)`」，通常就是指它大約跟 `n²` 一樣快 / 慢。

## 5.5 常見的複雜度（由快到慢）

| 複雜度 | 名稱 | 白話 | 生活比喻 | 程式例子 |
|---|---|---|---|---|
| `O(1)` | 常數時間 | 不管 `n` 多大，步驟數都一樣 | 打開置物櫃第 5 格 | `a[i]`、`stack.push` |
| `O(log n)` | 對數時間 | `n` 變 2 倍，只多 1 步 | 翻字典：每次翻到中間，砍掉一半 | 二分搜尋、heap 的 push / pop |
| `O(n)` | 線性時間 | `n` 變 2 倍，步驟也變 2 倍 | 點名：每個人叫一次 | 走過整個陣列一次 |
| `O(n log n)` | 線性對數 | 比 `n` 慢一點點 | 把一疊考卷排序 | `sort` |
| `O(n²)` | 平方時間 | `n` 變 2 倍，步驟變 4 倍 | 每個人都要跟其他每個人握手 | 雙層迴圈 |
| `O(n³)` | 立方時間 | `n` 變 2 倍，步驟變 8 倍 | | 三層迴圈 |
| `O(2ⁿ)` | 指數時間 | `n` 多 1，步驟就變 2 倍 | 河內塔、列出所有子集合 | 每個元素都「選或不選」 |
| `O(n!)` | 階乘時間 | 極慢 | 列出所有排列順序 | 暴力試所有排列 |

### `log n` 是什麼？

**白話**：`log₂ n` =「`n` 要一直除以 2，除幾次才會變成 1」。

```
n = 8：   8 → 4 → 2 → 1          除了 3 次，log₂ 8 = 3
n = 1024：1024 → 512 → ... → 1   除了 10 次，log₂ 1024 = 10
n = 100萬：大約 20 次
n = 10億：大約 30 次
```

所以 `O(log n)` 非常快 —— 就算 `n` 有 10 億，也只要大約 30 步。
在 Big-O 裡不用寫底數（`log₂` 或 `log₁₀` 只差常數倍），直接寫 `log n`。

### 實際感受一下（`n = 100萬 = 10⁶` 時大約要幾步）

| 複雜度 | 步驟數 | 每秒 `10⁸` 步的電腦要跑多久 |
|---|---|---|
| `O(1)` | 1 | 一瞬間 |
| `O(log n)` | 20 | 一瞬間 |
| `O(n)` | 100 萬 | 0.01 秒 |
| `O(n log n)` | 2000 萬 | 0.2 秒 |
| `O(n²)` | 1 兆 | **約 3 小時** |
| `O(2ⁿ)` | 天文數字 | 宇宙毀滅也跑不完 |

**這就是為什麼資料結構重要**：從 `O(n²)` 改成 `O(n log n)`，可以從 3 小時變成 0.2 秒。

## 5.6 怎麼算時間複雜度？—— 五個套路

### 套路 1：單層迴圈 → 看跑幾次

```cpp
for (int i = 0; i < n; i++) sum += a[i];   // 跑 n 次 → O(n)
```

### 套路 2：巢狀迴圈 → 次數相乘

```cpp
for (int i = 0; i < n; i++)          // n 次
    for (int j = 0; j < n; j++)      // 每次又 n 次
        cnt++;                       // 總共 n × n → O(n²)
```

就算內層是 `j < i`（總共 `0+1+...+(n-1) = n(n-1)/2` 次），去掉常數後還是 `O(n²)`。

### 套路 3：前後接著做 → 取最大的

```cpp
sort(a.begin(), a.end());               // O(n log n)
for (int i = 0; i < n; i++) ...         // O(n)
// 總共 O(n log n + n) = O(n log n)
```

### 套路 4：每次砍一半 → `O(log n)`

```cpp
while (n > 1) n /= 2;    // 跑 log₂ n 次 → O(log n)
```

### 套路 5：呼叫函式 → 要算進去

```cpp
for (int i = 0; i < n; i++)
    v.insert(v.begin(), x);   // vector 從開頭插入是 O(n)，總共 O(n²)！
```

> 很多人以為一行程式就是 `O(1)`，但 **STL 函式也要花時間**。每一課都會列出各操作的複雜度。

### 遞迴怎麼算？

畫出「**遞迴樹**」，數總共呼叫幾次、每次做多少事：

- `sum(n)` 呼叫 `sum(n-1)` 一次 → 總共 `n` 次呼叫 → `O(n)`
- 河內塔 `hanoi(n)` 呼叫 `hanoi(n-1)` **兩次** → 每多一層呼叫數變 2 倍 → `O(2ⁿ)`

## 5.7 最好、最壞、平均 (Best / Worst / Average Case)

同一個演算法，不同的輸入快慢可能不一樣。

例：在陣列裡從頭找某個數字：
- **最好情況**：第 1 個就是 → 1 步
- **最壞情況**：在最後一個，或根本不在 → `n` 步
- **平均情況**：大約 `n/2` 步 → `O(n)`

**評測時要看最壞情況**：出題者一定會放最刁鑽的測資。
例如「BST 平均 `O(log n)`」，但如果測資依序插入 `1, 2, 3, ...`，就會退化成最壞的 `O(n)`。

## 5.8 攤銷分析 (Amortized Analysis)

**白話**：有些操作「**偶爾很慢，但大部分很快**」，把總時間平均分攤到每次操作上來看。

**比喻**：每個月繳一次房租很痛（一次付很多），但平均到每天其實不多。

例：`vector::push_back`
- 平常：直接放到最後面，`O(1)`。
- 偶爾：容量滿了，要換一塊 **兩倍大** 的記憶體，把全部資料搬過去，`O(n)`。
- 因為容量每次加倍，搬家的次數很少。`n` 次 push 總共只要大約 `3n` 步 → 平均每次 `O(1)`。

我們說 `push_back` 是「**攤銷 `O(1)`** (amortized `O(1)`)」。（第 03 課會證明）

## 5.9 空間複雜度 (Space Complexity)

**白話**：程式用的 **記憶體** 隨 `n` 增加的速度，表示法跟時間複雜度一樣。

```cpp
vector<int> a(n);                          // O(n) 空間
vector<vector<int>> g(n, vector<int>(n));  // O(n²) 空間：n = 10⁵ 時要 40 GB，開不起來！
```

題目通常會限制記憶體（例如 256 MB），超過就是 **MLE**。估算方法：`int` 4 bytes，`long long` 8 bytes。
`10⁷` 個 `int` ≈ 40 MB，沒問題；`10⁹` 個 `int` ≈ 4 GB，太多了。

## 5.10 看題目限制，估算能不能過

**經驗法則：電腦每秒大約可以做 `10⁸`（一億）次基本運算。**

把 `n` 的最大值代入你的複雜度，算出來的步驟數：
- `≤ 10⁸`：通常可以在 1 秒內跑完 ✅
- `≈ 10⁹`：很危險，可能 TLE ⚠️
- `≥ 10¹⁰`：一定 TLE ❌

反過來，**從 `n` 的範圍可以猜出題目要你用的方法**：

| `n` 的上限 | 可以接受的複雜度 | 通常是什麼方法 |
|---|---|---|
| `n ≤ 10` | `O(n!)` | 暴力試所有排列 |
| `n ≤ 20 ~ 25` | `O(2ⁿ)` | 列舉所有子集合、回溯法 |
| `n ≤ 500` | `O(n³)` | 三層迴圈 |
| `n ≤ 5000` | `O(n²)` | 雙層迴圈 |
| `n ≤ 10⁶` | `O(n log n)` 或 `O(n)` | 排序、heap、雜湊表、單調 stack |
| `n ≤ 10¹⁸` | `O(log n)` 或 `O(1)` | 數學公式、二分、每次砍一半 |

**範例**：題目說 `n ≤ 3 × 10⁵`。
- `O(n²)` = `9 × 10¹⁰` → ❌ 一定 TLE
- `O(n log n)` ≈ `3×10⁵ × 18` ≈ `5.4 × 10⁶` → ✅ 輕鬆過

> **養成習慣：寫程式之前，先看限制、先算複雜度。** 這是這一課最重要的一句話。

# 小測驗

先自己想，再看下面的答案。

1. `int x = 50000 * 50000;` 會發生什麼事？要怎麼改？
2. 下面這段程式的時間複雜度是多少？

```cpp
for (int i = 1; i < n; i *= 2)
    for (int j = 0; j < n; j++)
        cnt++;
```

3. 題目說 `n ≤ 2000`，你的方法是 `O(n²)`，會不會超時？如果 `n ≤ 2 × 10⁵` 呢？
4. 為什麼 `void f(vector<int> v)` 在 `v` 很大、`f` 又被呼叫很多次時會很慢？怎麼改？
5. `int* p = new int(5); delete p; cout << *p;` 有什麼問題？
6. 記憶體的「stack 區」和資料結構的「stack」是同一個東西嗎？
7. `3n² + 100n log n + 7` 的時間複雜度是多少？

### 答案

1. `50000 × 50000 = 25 億`，超過 `int` 的上限（約 21 億）→ **溢位**，結果是錯的。改成 `long long x = 50000LL * 50000;`（要讓乘法本身就用 `long long` 計算，只改左邊的型別沒有用）。
2. 外層 `i = 1, 2, 4, 8, ...` 跑 `log n` 次，內層每次 `n` 次 → **`O(n log n)`**。
3. `n = 2000`：`n² = 4 × 10⁶` → ✅ 沒問題。`n = 2 × 10⁵`：`n² = 4 × 10¹⁰` → ❌ 會 TLE，要找 `O(n log n)` 或 `O(n)` 的方法。
4. 傳值會 **複製** 整個 vector，每次呼叫都是 `O(n)`。改成傳參考 `void f(const vector<int>& v)`，不會複製，是 `O(1)`。
5. `p` 已經被 `delete`，變成 **懸空指標**，再 `*p` 是 **use-after-free**，屬於未定義行為。用 `--debug` 模式執行會被抓到。
6. **不是**。只是名字一樣：記憶體的 stack 區是放區域變數和函式框架的地方；資料結構的 stack 是「後進先出」的容器。（不過呼叫堆疊確實是用「後進先出」的方式運作，這也是它叫 stack 的原因。）
7. 成長最快的是 `n²`（`n log n` 比 `n²` 慢很多），去掉常數 → **`O(n²)`**。
