# 第一部分：公開金鑰密碼的誕生

## 1.1 單向函數

**單向函數**（one-way function）：容易計算、但 **很難反過來算** 的函數 f——給 x 很快算出 f(x)，給 y 卻很難找到 x 使 f(x) = y。

**陷門單向函數**（trapdoor one-way function）：單向函數再加上一份 **陷門資訊**，有了它就能輕鬆反轉。公鑰密碼就是用這種函數建的：公鑰定義 f，私鑰就是陷門。

> 令人驚訝的事實：**到現在還沒有人能證明單向函數存在。** 證明它存在就等於解決了 P ≠ NP 問題（一百萬美元的千禧年難題之一，第 17 課）。所有公鑰密碼的安全性都建立在「某個問題 **看起來** 很難」的假設上。

## 1.2 歷史

| 年份 | 事件 |
|---|---|
| 1976 | Diffie 與 Hellman 發表〈New Directions in Cryptography〉：提出公鑰密碼的概念、金鑰交換協定、數位簽章的概念，但 **沒有** 給出實際的公鑰加密系統 |
| 1977～78 | Rivest、Shamir、Adleman 發表 **RSA**（第 10 課）；Merkle 與 Hellman 發表 **背包密碼**（後來被破解，第 21 課） |
| 1985 | ElGamal 用離散對數做出公鑰加密系統（本課第四部分） |
| 1997 | 英國政府解密文件顯示：GCHQ 的 Ellis、Cocks、Williamson 在 1970 年代初就發現了同樣的想法，但被列為機密 |

# 第二部分：離散對數問題

## 2.1 定義

設 p 是質數、g 是 F_p 的原根（第 04 課）。因為 g 的次方跑遍所有非零元素，任何 `h ∈ F_p*` 都能寫成 g 的某個次方。

**離散對數問題**（Discrete Logarithm Problem, DLP）：給定 g、h，找出 x 使得

```
g^x ≡ h (mod p)
```

x 叫做 h 以 g 為底的 **離散對數**，記作 `log_g(h)`（舊稱 **指標** index，記作 `ind_g(h)`）。

**方向的不對稱**：給 x 求 `g^x` 用快速冪，O(log x) 次乘法；給 h 求 x，目前沒有快速的方法（第 07、08、13 課會看到各種演算法，但對選得好的 p 都太慢）。

## 2.2 只定義到 mod p − 1

因為 `g^(p−1) ≡ 1`（費馬小定理），如果 x 是解，`x + k(p − 1)` 也是解。所以離散對數其實是 **模 p − 1 的數**。課本用這個觀點說：`log_g` 是一個 **同構**

```
log_g : F_p* → Z/(p − 1)Z，  而且 log_g(ab) = log_g(a) + log_g(b)
```

把乘法變成加法——這點和實數對數一樣。

## 2.3 和實數對數的差別

實數的 `2^x` 隨 x 平滑增加，可以用二分法逼近；模 p 的 `g^x` 卻 **跳來跳去，毫無規律**：

```python
p, g = 941, 627
print([pow(g, x, p) for x in range(1, 16)])
print(sorted((pow(g, x, p), x) for x in range(1, 941))[:10])     # 前幾個 h 的離散對數
```
```output
[627, 732, 697, 395, 182, 253, 543, 760, 374, 189, 878, 21, 934, 316, 522]
[(1, 940), (2, 183), (3, 469), (4, 366), (5, 356), (6, 652), (7, 483), (8, 549), (9, 938), (10, 539)]
```
第二行是「h = 1, 2, 3, … 的離散對數」，一樣沒有規律。課本例 2.4：p = 56509、g = 2、h = 38679，只能一個一個試：

```python
p, g, h = 56509, 2, 38679
x, cur = 0, 1
while cur != h:
    cur = cur * g % p
    x += 1
print(x, pow(2, x, p))
```
```output
11235 38679
```
這種「逐一試」要 O(p) 步。p 有 1000 位元時，這是 2¹⁰⁰⁰ 步——完全不可能。

## 2.4 推廣到任意群

DLP 可以放在任何 **群** G 裡（群的定義在第 07 課）：給 `g, h ∈ G`，找 x 使 `g ⋆ g ⋆ … ⋆ g`（x 次）`= h`。不同的群難度天差地遠：
- 在 `(Z/pZ, +)` 裡，「g 加 x 次 = h」就是 `xg ≡ h`，用模反元素一步解完——**一點都不難**。
- 在 F_p* 裡相對難（第 13 課有次指數時間的演算法）。
- 在 **橢圓曲線** 的點群裡更難（第 18 課），所以同樣的安全度只需要短很多的金鑰。

# 第三部分：Diffie–Hellman 金鑰交換

## 3.1 協定

**目標**：Alice 和 Bob 只能在被 Eve 監聽的頻道上溝通，卻想要一個 **共同的秘密**（之後拿來當對稱密碼的金鑰）。

| 步驟 | Alice | 公開頻道 | Bob |
|---|---|---|---|
| 1. 公開參數 | | 大質數 p、F_p 中階數很大的元素 g | |
| 2. 選秘密 | 選秘密整數 a | | 選秘密整數 b |
| 3. 算公開值 | `A ≡ g^a (mod p)` | | `B ≡ g^b (mod p)` |
| 4. 交換 | 送出 A → | A、B 都被 Eve 看到 | ← 送出 B |
| 5. 算共同秘密 | `A' ≡ B^a` | | `B' ≡ A^b` |

**為什麼兩人算出一樣的值**：`B^a ≡ (g^b)^a = g^(ab) = (g^a)^b ≡ A^b`。

課本例 2.7：p = 941、g = 627、a = 347、b = 781：

```python
p, g = 941, 627
a, b = 347, 781                      # 各自的秘密
A, B = pow(g, a, p), pow(g, b, p)    # 公開交換
print(A, B)
print(pow(B, a, p), pow(A, b, p))    # 兩人各自算出的共同秘密
```
```output
390 691
470 470
```
共同秘密是 470。Eve 看到 p、g、A = 390、B = 691，但看不到 a、b。

## 3.2 Eve 要解的問題

**Diffie–Hellman 問題**（DHP）：知道 `g^a`、`g^b`，求 `g^(ab)`。

- 如果能解 DLP，就能解 DHP：從 A 求出 a，再算 `B^a`。所以 **DHP 不比 DLP 難**。
- 反過來，能解 DHP 是否就能解 DLP？**不知道**。一般相信兩者一樣難，但沒有證明。

在小數字下，Eve 可以直接暴力解 DLP：

```python
p, g, A, B = 941, 627, 390, 691
a = next(x for x in range(1, p) if pow(g, x, p) == A)
print(a, pow(B, a, p))
```
```output
347 470
```
Eve 找到的 a 可能不是 Alice 選的 347（只要模 g 的階相等就行），但算出的共同秘密一樣。實務上 p 至少 2048 位元。

## 3.3 參數怎麼選

- p 要夠大，而且 **p − 1 要有大質因數**（否則 Pohlig–Hellman 演算法能把 DLP 拆成小問題，第 08 課）。常見做法：選安全質數 `p = 2q + 1`，取階為 q 的 g。
- g 的階要大：如果 g 的階只有 N，Eve 只需要在 0～N−1 裡找。

## 3.4 中間人攻擊

Diffie–Hellman 擋得住 **被動** 的竊聽者，擋不住 **主動** 的攻擊者。如果 Eve 能攔截並竄改訊息：

```
Alice ── A ──▶ Eve（換成 g^e）──▶ Bob
Alice ◀── g^e ── Eve ◀── B ── Bob
```

Alice 以為和 Bob 共享 `g^(ae)`，Bob 以為和 Alice 共享 `g^(be)`，其實兩把都在 Eve 手上，Eve 可以解密、竄改、再加密轉送。解法是 **認證**——用數位簽章（第 25 課）或憑證確認公開值真的來自對方。

# 第四部分：ElGamal 公鑰密碼

## 4.1 從金鑰交換到加密

Diffie–Hellman 讓兩人得到一個 **隨機** 的共同秘密，但不能用來傳送 **指定的** 訊息。ElGamal（1985）把它改成公鑰加密：Alice 的公開值 A 當成公鑰，Bob 每次加密時臨時產生自己的那一半。

| | 做什麼 |
|---|---|
| **公開參數** | 大質數 p、階很大的 g |
| **Alice 建金鑰** | 選私鑰 a（1 ≤ a ≤ p − 1），公布公鑰 `A ≡ g^a` |
| **Bob 加密 m** | 選 **隨機的臨時金鑰** k，算 `c₁ ≡ g^k`、`c₂ ≡ m · A^k`，送出 `(c₁, c₂)` |
| **Alice 解密** | `(c₁^a)⁻¹ · c₂ ≡ m` |

**為什麼解得開**：`c₁^a = g^(ka) = A^k`，所以 `(c₁^a)⁻¹ · c₂ = (A^k)⁻¹ · m · A^k = m`。直觀地說，`A^k` 是一個 Diffie–Hellman 共同秘密，`c₂` 是用它把 m「遮起來」（乘法版的一次性密碼本）。

課本例 2.8：p = 467、g = 2、a = 153、m = 331、k = 197：

```python
p, g = 467, 2
a = 153
A = pow(g, a, p)
print("公鑰 A =", A)

m, k = 331, 197
c1, c2 = pow(g, k, p), m * pow(A, k, p) % p
print("密文", (c1, c2))

x = pow(c1, a, p)
print("c1^a =", x, " 解密 =", pow(x, -1, p) * c2 % p)
print(pow(c1, p - 1 - a, p) * c2 % p)    # 另一種寫法：c1^(p−1−a) 就是 (c1^a)⁻¹
```
```output
公鑰 A = 224
密文 (87, 57)
c1^a = 367  解密 = 331
331
```
最後一行的技巧：因為 `c₁^(p−1) ≡ 1`，`(c₁^a)⁻¹ ≡ c₁^(p−1−a)`，一次快速冪就搞定，不用另外求反元素。

## 4.2 密文膨脹

ElGamal 的明文是一個 mod p 的數，密文卻是 **兩個** mod p 的數，長度變兩倍，叫做 **2 比 1 的訊息膨脹**。這是用隨機性換安全性的代價：同一個 m 每次加密都得到不同的密文（因為 k 不同），Eve 無法比對「這兩則密文是不是同一個明文」——這叫 **機率式加密**（第 14 課）。

## 4.3 ⚠️ 臨時金鑰絕對不能重複使用

如果 Bob 用同一個 k 加密了 m 和 m'，兩組密文的 `c₁` 一樣，而且

```
c₂ / c₂' ≡ (m · A^k) / (m' · A^k) = m / m'
```

只要 Eve 知道其中一個明文（例如格式固定的開頭），另一個立刻解出：

```python
p, g, a = 467, 2, 153
A = pow(g, a, p)
k = 197                                    # 不小心重複用的臨時金鑰
m1, m2 = 331, 100
c = [(pow(g, k, p), m * pow(A, k, p) % p) for m in (m1, m2)]
print(c)
m2_eve = c[1][1] * pow(c[0][1], -1, p) * m1 % p      # Eve 只知道 m1
print(m2_eve)
```
```output
[(87, 57), (87, 274)]
100
```
這和第 05 課「一次性密碼本不能重複用」是同一個道理。真實事故：2010 年 Sony PS3 的簽章系統（ECDSA，同樣的原理）重複使用臨時金鑰，導致私鑰外洩。

## 4.4 ElGamal 有多安全？

**命題 2.10**：如果 Eve 有一個能解密 **任意** ElGamal 密文的「神諭」（oracle），她就能解 Diffie–Hellman 問題。

**為什麼**：給定 DHP 的 `A = g^a`、`B = g^b`，把 A 當公鑰、把 `(c₁, c₂) = (B, 1)` 交給神諭解密，神諭回傳 `m = (B^a)⁻¹ · 1 = (g^(ab))⁻¹`，取倒數就是 `g^(ab)`。

所以 **破解 ElGamal 和解 DHP 一樣難**。（這種「給攻擊者一個解密神諭」的情境叫 **選擇密文攻擊**。課本說這表示 ElGamal 在 DHP 困難的假設下是安全的；不過要注意，原始的 ElGamal 有 **可塑性**：把 `c₂` 乘以 2，解出來的明文也乘以 2。現代對選擇密文攻擊的安全定義更嚴格，第 26 課的填充方案會談到。）

# 習題

### 題 1：Diffie–Hellman 手算

Alice 和 Bob 用 p = 23、g = 5，Alice 選 a = 6、Bob 選 b = 15。算出 A、B 和共同秘密。

### 題 2：ElGamal 解密

Alice 的參數 p = 1373、g = 2、私鑰 a = 947。她收到密文 `(c₁, c₂) = (877, 719)`。解密。

### 題 3：觀念

為什麼 ElGamal 加密每次都要選新的隨機 k？如果 Bob 偷懶一直用 k = 1 會怎樣？

### 題 4：中間人

描述 Eve 怎麼對 Diffie–Hellman 發動中間人攻擊，並說明為什麼 Alice 和 Bob 察覺不到。

### 題 5：可塑性

給你一個 ElGamal 密文 `(c₁, c₂)`，在不知道私鑰的情況下，造出另一個密文，讓它解密後是原明文的 3 倍。

---

# 習題解答

**題 1**：

```python
p, g, a, b = 23, 5, 6, 15
A, B = pow(g, a, p), pow(g, b, p)
print(A, B, pow(B, a, p), pow(A, b, p))
```
```output
8 19 2 2
```
**題 2**：

```python
p, g, a = 1373, 2, 947
c1, c2 = 877, 719
print(pow(c1, p - 1 - a, p) * c2 % p)
```
```output
1194
```
**題 3**：k 必須保密且只用一次。k = 1 時 `c₁ = g`、`c₂ = m · A`，任何人都能算 `m = c₂ · A⁻¹`（A 是公開的），完全沒有加密效果。k 重複用則會洩漏 `m / m'`（4.3 節）。

**題 4**：Eve 攔下 A，改送自己的 `g^e` 給 Bob；攔下 B，也改送 `g^e` 給 Alice。Alice 算出 `g^(ae)`、Bob 算出 `g^(be)`，Eve 兩把都會算。之後 Eve 把 Alice 的密文用 `g^(ae)` 解開、看完、再用 `g^(be)` 加密轉給 Bob。因為 Diffie–Hellman 本身 **沒有認證**——Alice 無法確認收到的 B 真的是 Bob 產生的——兩人看到的一切都像正常通訊。

**題 5**：送出 `(c₁, 3c₂ mod p)`。解密得到 `(c₁^a)⁻¹ · 3c₂ = 3m`。

```python
p, g, a = 467, 2, 153
A = pow(g, a, p)
m, k = 100, 55
c1, c2 = pow(g, k, p), m * pow(A, k, p) % p
print(pow(c1, p - 1 - a, p) * (3 * c2 % p) % p)
```
```output
300
```
