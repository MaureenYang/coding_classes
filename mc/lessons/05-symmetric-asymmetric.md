# 第一部分：密碼系統的數學定義

## 1.1 五個元件

一個 **對稱密碼**（symmetric cipher）由五樣東西組成：

| 符號 | 意思 |
|---|---|
| K | 金鑰空間（所有可能的金鑰） |
| M | 明文空間 |
| C | 密文空間 |
| `e : K × M → C` | 加密函數，常寫成 `e_k(m)` |
| `d : K × C → M` | 解密函數，常寫成 `d_k(c)` |

唯一的要求是 **解密能還原加密**：

```
d_k(e_k(m)) = m，對所有 k ∈ K、m ∈ M
```

由此推出 `e_k` 一定是 **一對一** 的：如果 `e_k(m) = e_k(m')`，兩邊套 `d_k` 就得到 `m = m'`。

叫「對稱」是因為 Alice 和 Bob 擁有 **一樣的知識**（同一把 k），兩個人都能加密也都能解密。

## 1.2 Kerckhoffs 原則

> **密碼系統的安全性只應該依賴金鑰的保密，而不是演算法的保密。**

也就是假設 Eve 知道 `e` 和 `d` 是什麼，她只是不知道 k。理由：演算法會被逆向工程、被洩漏、被員工帶走；金鑰則可以隨時更換。「靠隱藏演算法來安全」（security through obscurity）在歷史上一再失敗。

## 1.3 好密碼的四個性質

1. 知道 k 時，`e_k(m)` **容易** 計算。
2. 知道 k 時，`d_k(c)` **容易** 計算。
3. 只看到一些密文 `c₁, c₂, …, cₙ`，不知道 k 時，**很難** 求出任何明文。
4. 即使看到一些 **明文—密文配對** `(m₁, c₁), …, (mₙ, cₙ)`，還是很難解出其他密文。這叫做 **抵抗選擇明文攻擊**（chosen plaintext attack）。

性質 4 最難做到：簡單替換密碼只要一組配對就洩漏大半張表（課本例 1.34）。「容易」和「很難」的精確定義要等到第 17 課的計算複雜度。

# 第二部分：編碼與分組

## 2.1 編碼不是加密

**編碼方案**（encoding scheme）把一種資料轉成另一種資料，例如文字 → 數字。它和加密的差別在 **意圖**：編碼是 **公開的**、大家都用同一套（例如 ASCII 把 `A` 編成 65）；加密則要靠秘密金鑰。

```python
msg = "Bed bug."
codes = [ord(ch) for ch in msg]
print(codes)
print(" ".join(f"{c:08b}" for c in codes))
n = int.from_bytes(msg.encode(), "big")          # 把整段訊息當成一個大整數
print(n)
print(n.to_bytes(8, "big").decode())
```
```output
[66, 101, 100, 32, 98, 117, 103, 46]
01000010 01100101 01100100 00100000 01100010 01110101 01100111 00101110
4784340269404612398
Bed bug.
```
最後兩行很重要：**公鑰密碼處理的是數字**，所以要先把訊息編碼成一個（或一串）整數 `m < N`，加密後再解碼回來。

## 2.2 區塊大小

實務上把明文切成固定長度 B 位元的 **區塊**（block），B 叫 **區塊大小**（blocksize），然後一塊一塊加密。最後一塊不足 B 位元時要 **填充**（padding），第 26 課會談填充方式的安全問題。

# 第三部分：幾個對稱密碼的例子

## 3.1 模 p 乘法密碼

取一個大質數 p（例如 2¹⁵⁹ < p < 2¹⁶⁰），`K = M = C = F_p* = {1, …, p−1}`：

```
e_k(m) ≡ k · m (mod p)，  d_k(c) ≡ k⁻¹ · c (mod p)
```

**性質 1、2**：成立，乘法和擴展歐幾里得都很快。

**性質 3**：成立。對 **任何** 密文 c 和 **任何** 明文 m，都存在金鑰 `k ≡ m⁻¹ · c` 能把 m 加密成 c——光看密文完全沒有關於明文的資訊。

**性質 4**：**不成立**。只要一組 `(m, c)`，Eve 就能算出 `k ≡ m⁻¹ · c`。

```python
p = 2**160 + 7                      # 一個 160 位元的質數
k = 1234567890123456789012345678901234567890 % p
m = int.from_bytes(b"attack at dawn", "big")
c = k * m % p
k_eve = pow(m, -1, p) * c % p       # Eve 只用一組 (m, c)
print(k_eve == k)
c2 = k * int.from_bytes(b"retreat", "big") % p
print((pow(k_eve, -1, p) * c2 % p).to_bytes(7, "big"))
```
```output
True
b'retreat'
```
## 3.2 不取模會怎樣：gcd 攻擊

如果偷懶，直接 `e_k(m) = k · m`（不取模）？性質 1、2 還在，但 **性質 3 也壞了**：Eve 收集幾個密文，`gcd(c₁, c₂, …) = k · gcd(m₁, m₂, …)`，而幾個隨機數的 gcd 通常是 1 或很小的數，所以 gcd **就是 k 或 k 的小倍數**。

```python
from math import gcd
from functools import reduce
import random

random.seed(7)
k = random.getrandbits(64)
ms = [random.getrandbits(64) for _ in range(5)]
cs = [k * m for m in ms]
g = reduce(gcd, cs)
print(g == k, g // k)
```
```output
True 1
```
這說明 **取模有「混合」的效果**，破壞了整除這種結構。但光取模也不夠（3.1 已經看到性質 4 被破）。

## 3.3 加法、仿射、Hill 密碼

| 密碼 | 加密 | 解密 |
|---|---|---|
| 加法（就是移位密碼） | `m + k (mod p)` | `c − k` |
| 仿射 | `k₁ · m + k₂` | `k₁⁻¹ · (c − k₂)` |
| Hill | 同上，但 m、c、k₂ 是 **向量**，k₁ 是 **可逆矩陣** | 用反矩陣 |

全部都擋不住選擇明文攻擊：它們都是 **線性**（或仿射）的，幾組配對就能解出金鑰。下面示範 2×2 的 Hill 密碼被兩組配對破解：

```python
p = 26

def mat_mul(A, B):
    return [[sum(A[i][t] * B[t][j] for t in range(2)) % p for j in range(2)] for i in range(2)]

def mat_inv(A):
    det = (A[0][0] * A[1][1] - A[0][1] * A[1][0]) % p
    d = pow(det, -1, p)                         # 行列式必須和 26 互質
    return [[A[1][1] * d % p, -A[0][1] * d % p], [-A[1][0] * d % p, A[0][0] * d % p]]

K = [[3, 3], [2, 5]]                            # 秘密金鑰矩陣
M = [[7, 11], [4, 11]]                          # 兩個明文向量當成「行」：(7,4)=he、(11,11)=ll
C = mat_mul(K, M)                               # Eve 看到對應的密文
K_eve = mat_mul(C, mat_inv(M))                  # K = C · M⁻¹
print(C)
print(K_eve == K, K_eve)
```
```output
[[7, 14], [8, 25]]
True [[3, 3], [2, 5]]
```

# 第四部分：XOR 與一次性密碼本

## 4.1 XOR

**互斥或**（exclusive or，XOR，記作 ⊕）：兩個位元相同得 0、不同得 1。對整串位元就逐位做。重要性質：

```
x ⊕ x = 0，  x ⊕ 0 = x，  所以 (m ⊕ k) ⊕ k = m
```

XOR 比加法還快（沒有進位），而且 **加密和解密是同一個運算**。

## 4.2 一次性密碼本

**一次性密碼本**（one-time pad）：金鑰是和訊息 **一樣長的真亂數** 位元串 k，`c = m ⊕ k`。

如果 k 真的隨機且 **只用一次**，那 c 對 Eve 來說也是完全隨機的——任何同長度的明文都可能，因為對每個 m' 都有 `k' = c ⊕ m'`。這是 **完全保密**（perfect secrecy，第 17 課用資訊理論證明）。

**致命的弱點**：金鑰和訊息一樣長，而且 **絕不能重複使用**。如果同一把 k 加密了兩則訊息：

```
c₁ ⊕ c₂ = (m₁ ⊕ k) ⊕ (m₂ ⊕ k) = m₁ ⊕ m₂
```

金鑰消失了，Eve 得到兩則明文的 XOR；只要猜中其中一則的一段，另一則的對應部分就出來了。

```python
import os

def xor(a, b):
    return bytes(x ^ y for x, y in zip(a, b))

m1 = b"meet me at the north gate at ten"
m2 = b"the password is red velvet cake!"
k = os.urandom(len(m1))
c1, c2 = xor(m1, k), xor(m2, k)
print(xor(c1, c2) == xor(m1, m2))
guess = b"the password"                       # Eve 猜第二則的開頭
print(xor(xor(c1, c2)[:len(guess)], guess))
```
```output
True
b'meet me at t'
```
歷史上真的發生過：二戰後美國的 **Venona 計畫** 就是因為蘇聯重複使用了一次性密碼本，破解了大量電報。

## 4.3 偽亂數產生器

能不能用一把 **短** 金鑰（例如 160 位元）產生一長串「看起來隨機」的位元，再拿去做 XOR？我們想要一個函數 `R(k, j)`（第 j 個位元），滿足：

1. 容易計算；
2. 看到很多 `R(k, j₁), R(k, j₂), …` 也很難求出 k；
3. 看到這些值，也沒辦法以超過 50% 的機率猜中下一個沒看過的位元。

這樣的 R 叫 **偽亂數產生器**（pseudorandom number generator, PRNG）。它產生的不是真亂數，只是「沒有人分得出來」。**到現在沒有人能證明這樣的函數存在**（它會是一個單向函數，第 06 課）。

兩種實際做法：
- **混合運算**：反覆做一大堆位元打亂，快但沒有數學證明——DES、AES 都是這類（第 26 課）。
- **基於數學難題**：例如用「分解很難」或「離散對數很難」構造，有理論依據但慢很多。

> ⚠️ Python 的 `random` 模組（Mersenne Twister）**不是** 密碼學安全的 PRNG：看到 624 個輸出就能預測之後所有的值。密碼用途請用 `secrets` 或 `os.urandom`。

# 第五部分：非對稱密碼登場

## 5.1 金鑰交換的難題

對稱密碼要求 Alice 和 Bob **事先** 共享金鑰 k。如果他們從沒見過面、所有通訊都被 Eve 監聽呢？大多數人的直覺是「不可能」。Diffie 和 Hellman 在 1976 年提出：**在某些假設下，可以**。這就是 **公開金鑰密碼學**（public key cryptography），也叫 **非對稱密碼學**——本書的主題。

## 5.2 有投信口的保險箱

**比喻**：Alice 買了一個上方有窄縫的保險箱，放在公共場所。任何人都能檢查它很堅固，也都能把信從縫裡投進去；但只有握有鑰匙的 Alice 能打開。

| 比喻 | 對應 |
|---|---|
| 保險箱（大家都看得到） | Alice 的 **公鑰** `k_pub` |
| 把信投進縫裡 | 加密 `e_{k_pub}(m)` |
| 開保險箱的鑰匙（只有 Alice 有） | Alice 的 **私鑰** `k_priv` |

而且 Alice 只要放一個保險箱，全世界都能重複使用，不用為每個通訊對象各準備一個。

## 5.3 數學定義

金鑰是一對 `k = (k_priv, k_pub)`，

```
e_{k_pub} : M → C，  d_{k_priv} : C → M，  d_{k_priv}(e_{k_pub}(m)) = m
```

**安全的要求**：就算知道 `k_pub`，也很難算出 `d_{k_priv}(c)`。私鑰是讓 Alice 能「抄捷徑」反轉加密函數的資訊，叫做 **陷門**（trapdoor）。加密容易、沒有陷門時反轉很難、有陷門時反轉容易——這叫 **陷門單向函數**。

之後的課程會介紹各種陷門建立在什麼難題上：

| 系統 | 依賴的難題 | 課 |
|---|---|---|
| Diffie–Hellman、ElGamal | 離散對數 | 06 |
| RSA | 大數分解 | 10 |
| 橢圓曲線密碼 ECC | 橢圓曲線離散對數 | 18～19 |
| NTRU、GGH | 格上的最短 / 最近向量 | 21～24 |

# 習題解答

**題 1**：性質 1、2 成立（乘法與求反元素都很快）；性質 3 成立（任何密文都可能對應任何明文）；性質 4 不成立（一組 `(m, c)` 就能算出 `k = m⁻¹c`）。

**題 2**：`e = 4 → F = 5`、`t = 19 → O = 14`：`4k₁ + k₂ ≡ 5`、`19k₁ + k₂ ≡ 14`。相減 `15k₁ ≡ 9 (mod 26)`，`15⁻¹ ≡ 7`，所以 `k₁ ≡ 63 ≡ 11`、`k₂ ≡ 5 − 44 ≡ 13`。

```python
k1 = 9 * pow(15, -1, 26) % 26
k2 = (5 - 4 * k1) % 26
print(k1, k2)
print(chr((k1 * 4 + k2) % 26 + 65), chr((k1 * 19 + k2) % 26 + 65))
```
```output
11 13
F O
```
**題 3**：

```python
m, k = 0b10110011, 0b01101010
c = m ^ k
print(f"{c:08b}", f"{c ^ k:08b}", c ^ k == m)
```
```output
11011001 10110011 True
```
**題 4**：`c₁ ⊕ c₂ = m₁ ⊕ m₂`，金鑰完全消失。Eve 拿到兩則明文的 XOR，就能用常見字詞去猜，一旦猜中一則的某段，另一則的對應位置立刻解出。

**題 5**：公鑰可以公開傳送，不怕被 Eve 看到，所以 Alice 和 Bob **不需要事先見面** 交換秘密。和 1000 人通訊：對稱密碼每一對要一把獨立的金鑰，Alice 要管 1000 把（全體兩兩通訊則要 1000·999/2 = 499500 把）；公鑰密碼每個人只要一對金鑰，Alice 只要公布一把公鑰。
