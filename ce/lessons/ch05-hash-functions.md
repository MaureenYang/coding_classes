# 第 5 章　雜湊函式（Hash Functions）

> 《Cryptography Engineering》— Ferguson, Schneier, Kohno，本章頁碼：p.77–88

---

## 1. 本章定位

**雜湊函式**：輸入任意長度的位元字串，輸出**固定長度**的結果（又稱 digest、fingerprint）。

典型用途是數位簽章：公鑰運算很貴，所以不簽 m 本身，而是簽 h(m)（128–1024 bits，遠小於訊息）。為了安全，必須**無法找出 h(m1) = h(m2) 的兩則訊息**。

⚠️ **別和雜湊表的雜湊函式搞混**：

| | 雜湊表用的 hash | 密碼學雜湊 |
|---|---|---|
| 目的 | 把 key 平均分到桶子 | 抵抗攻擊者 |
| 要求 | 分佈均勻、速度快 | 單向、抗碰撞、像隨機映射 |

> 對照第一本書：Hanson 的 `Table`、`Atom` 用的是前者（例如 `Atom` 的 scatter 表）；這種 hash 完全不能拿來做安全用途。

雜湊函式在密碼系統中是**萬用膠水**：

- 把可變長度的值對應到固定長度；
- 在偽亂數產生器中，從一個共享秘密衍生出多把金鑰；
- 提供**單向性**，把系統各部分隔離——攻擊者得知一個值，也推不出其他值。

作者坦言：**社群對雜湊函式的了解，比對區塊加密器還少。** 當時 NIST 正在舉辦 SHA-3 競賽（過程類似 AES）。

---

## 2. 雜湊函式的安全性 ⭐⭐

### 2.1 常見性質

| 性質 | 意義 |
|---|---|
| **單向（one-way / 抗原像）** | 給 x，找不到 m 使 h(m) = x |
| **抗碰撞（collision resistance）** | 碰撞一定存在（無限輸入、有限輸出），但**找不到** |

抗碰撞讓雜湊適合簽章，但**有抗碰撞的雜湊，未必適合做金鑰衍生、單向函式等其他用途**。實務上，設計者都把雜湊當成**隨機映射**來用——所以作者直接把定義拉到最高：

> **定義 4**：理想雜湊函式的行為像一個「從所有可能輸入到所有可能輸出」的**隨機映射**。
>
> **定義 5**：對雜湊函式的**攻擊**，就是一個能把它與理想雜湊函式**區分開來的非泛用方法**。

和第 3 章一樣，理由是：唯有如此，設計者才能把雜湊當成**理想黑盒子**，不必考慮它的性質如何與周圍系統交互作用。

### 2.2 區分器可以花多少成本？

雜湊沒有金鑰，所以沒有「窮舉金鑰」這種基準；關鍵參數是**輸出長度 n**：

| 泛用攻擊 | 成本 |
|---|---|
| 生日攻擊（找碰撞） | 約 2^(n/2) |
| 原像攻擊 | 約 2^n |

判斷原則：

> 有人宣稱一個攻擊時，問自己：**用不依賴這個雜湊細節的泛用攻擊，能不能得到相同或更好的結果？** 能 → 區分器沒用；不能 → 是真的攻擊。

也可以明確指定較低的安全等級，例如「512-bit 雜湊、安全等級 128 bits」，則區分器限 2^128 步。

## 3. 真實的雜湊函式

當時的選擇幾乎只有 SHA 家族（SHA-1、SHA-224/256/384/512）。它們分析得也不夠，但至少經 NIST 標準化、由 NSA 設計。（作者註：不論你怎麼看 NSA，它發表的密碼學至今都相當不錯。）

### 3.1 迭代式雜湊（Merkle–Damgård）⭐

```
        m1          m2                mk(含填充與長度)
        │           │                 │
H0 ──► h' ──H1──►  h' ──H2── … ──►   h' ──► Hk = h(m)
```

- 輸入切成固定大小區塊（典型 512 bits），最後一塊填充並附上**訊息長度**。
- **壓縮函式** h' 與固定大小的中間狀態：`Hi = h'(Hi−1, mi)`，從固定值 H0 開始。

優點：

- 比直接處理可變長度的設計容易規範與實作。
- **串流處理**：拿到第一段資料就能開始算，不必把整份資料存起來。

### 3.2 一個簡單但不安全的雜湊（教學用）

用 AES-256，金鑰 K = 全 0，H0 = 全 0：

```
Hi = AES_K(Hi−1 ⊕ mi)
```

**非泛用碰撞攻擊**：取兩區塊訊息 m = (m1, m2)，中間值 H1, H2。構造

```
m1' = m2 ⊕ H1
m2' = H2 ⊕ m2 ⊕ H1
```

則 m' = (m1', m2') 也雜湊為 H2（證明見習題 5.5）。因為 K 是公開的，任何人都能「往回推」——這利用的是這個構造本身的弱點，所以是**非泛用攻擊**。

### 3.3 MD5

- Ron Rivest 設計，128-bit 輸出；改良自 MD4（MD4 快但已破）。
- 512-bit 區塊；128-bit 狀態 = 4 個 32-bit 字；壓縮函式 4 輪，每輪把整個訊息區塊混入狀態（每個訊息字用 4 次）；最後把輸入狀態加回輸出。
- 開創「在 32-bit 字上做加法、xor、and、or、rotate」的風格，在 32-bit CPU 上非常有效率。

問題：

1. **128 bits 太短**：生日攻擊只要 2^64。
2. 十多年前就知道壓縮函式有碰撞；**王小雲與于紅波**的突破後，已能用遠少於 2^64 的計算找到**完整 MD5** 的碰撞。

> **MD5 非常脆弱，不應再使用。**

### 3.4 SHA-1

- NSA 設計、NIST 標準化。最初版本 SHA（現稱 SHA-0）有弱點，NSA 修正後發佈 SHA-1，但未公開原因；三年後 Chabaud 與 Joux 公開了 SHA-0 的弱點。
- **SHA-0 → SHA-1 唯一的差別：在訊息擴展的線性遞迴中加了一個 1-bit 旋轉。**
- 160-bit 輸出；5 個 32-bit 字的狀態；4 輪；用線性遞迴把 16 個訊息字「拉長」成 80 個，每個訊息位元至少影響混合函式十幾次。
- 設計比 MD5 保守，也比較慢。

問題：

1. **160 bits 太短**：碰撞只需 2^80，低於 128-bit 設計強度。
2. 已發現遠低於 2^80 的碰撞攻擊（王小雲等）。

> **「攻擊只會越來越好」**——SHA-1 已不可信任。
>
> 後見之明：2017 年 Google 與 CWI 公開 **SHAttered**，產生了第一組真實的 SHA-1 碰撞（兩份 PDF）。

### 3.5 SHA-2 家族（SHA-224/256/384/512）

- 2001 年草案、2004 年增補；輸出 224/256/384/512 bits，對應 3DES 112-bit 與 AES 128/192/256-bit 金鑰。
- 結構與 SHA-1 很像。
- 「新」本身是個警訊，但 SHA-1 的已知弱點嚴重得多；而且要更高安全就需要更長輸出，其他大輸出設計的公開分析更少。
- SHA-256 比 SHA-1 慢很多：雜湊長訊息的時間約等於用 AES 或 Twofish 加密它——這是保守設計的代價，不一定是壞事。

## 4. 雜湊函式的弱點 ⭐⭐

依本書的嚴格定義，上述**所有**雜湊函式都不合格。

### 4.1 長度擴展（Length Extension）

設 m 切成 m1…mk，雜湊為 H。另取 m' = m1…mk, mk+1，則：

```
h(m') = h'( h(m), mk+1 )
```

因為迭代結構在**最後沒有任何特殊處理**，h(m) 直接就是 h(m') 計算到第 k 塊時的**中間狀態**。（實際操作時 m' 要包含 m 的填充與長度欄位，但這些構造方法是公開的，不成問題。）

- 作為區分器：構造幾組 (m, m') 檢查此關係，只需幾次雜湊計算。理想雜湊絕不會有此關係。

**實際危害**：

```
認證碼 = h(X ‖ m)        X = Alice 與 Bob 共享的秘密
```

若 h 是理想雜湊，這是不錯的認證方式。但有了長度擴展，Eve 可以在 m 後面**附加文字**，並算出新的、正確的認證碼——**不必知道 X**。

> NIST 對 SHA-3 的要求之一：**不可有長度擴展性質**。（第 6 章的 HMAC 也是為此設計。）

### 4.2 部分訊息碰撞（Partial-Message Collision）

情境：系統用 h(m ‖ X) 認證訊息，X 是認證金鑰；攻擊者能選 m，但系統只肯認證**一則**訊息。

- 對理想 n-bit 雜湊：攻擊者最多只能窮舉 X → n bits 安全。
- 對迭代雜湊：
  1. 用生日攻擊（約 2^(n/2) 步）找出 h(m) = h(m') 的兩則訊息；
  2. 讓系統認證 m；
  3. 把訊息換成 m'。因為迭代雜湊一旦碰撞，**後面輸入相同就一直相同**：h(m ‖ X) = h(m' ‖ X)。
- 這個攻擊**與 X 無關**。

> 這也示範了區分器的一般形式：區分器**自訂一個「遊戲」**（攻擊情境），然後在其中攻擊；成功就是迭代雜湊，失敗就是理想雜湊。

## 5. 修補弱點 ⭐

### 5.1 為什麼一定要修？

> 在雜湊函式裡留下弱點是非常壞的主意——**可以保證它一定會在某處被以暴露弱點的方式使用**。即使寫在文件裡，真實系統也不會去檢查。

而且還有複雜度問題：雜湊有 3 個弱點、區塊加密器 2 個、簽章方案 4 個……很快就要檢查**上百種交互作用**——實際上不可能。

### 5.2 短期修補一：h_dbl

> **定義 6**：`h_dbl(m) := h( h(m) ‖ m )`

- 把 h(m) 放在訊息前面 → 迭代計算一開始就依賴訊息的所有位元，長度擴展與部分訊息碰撞都失效。
- 作者相信用 SHA-2 時安全等級為 n bits。
- 缺點：**慢兩倍**；而且必須**緩衝整個訊息**，無法串流處理。

### 5.3 短期修補二：h_d（推薦）⭐⭐

> **定義 7**：`h_d(m) := h( h(0^b ‖ m) )`，宣稱安全等級 **min(k, n/2)**。
> （b 為壓縮函式的區塊長度，0^b 即在訊息前加一整個全 0 區塊。）

例：`SHA_d-256(m) = SHA-256( SHA-256( 0^512 ‖ m ) )`

**「作弊」之處**：通常期望 n-bit 雜湊在無法碰撞攻擊的情境提供 n bits 安全；這裡只宣稱 **n/2 bits**。部分訊息碰撞攻擊都靠生日攻擊，於是落在宣稱範圍之外。

**為什麼這樣剛好？**

```
SHA_d-256 → 128-bit 安全    ←→    AES 用 256-bit 金鑰 → 128-bit 安全
```

兩者「數值大小 vs. 安全等級」的落差，**都來自碰撞攻擊**。既然假設碰撞攻擊總是可能，各種大小與安全等級就能完美對齊（第 3 章的 2n 原則）。

- 例如有人想用 SHA-256 產生 AES 的 256-bit 金鑰，並以為有 256 bits 安全——這正是要防止的誤解。
- Coron 等人也獨立描述了這個修補；可證明 h_d 至少和 h 一樣強。
- **HMAC** 用的是類似「再雜湊一次」的手法。
- 前置全 0 區塊，使內層雜湊的第一個輸入通常與外層不同。

作者對 h_dbl 與 h_d 都只信任到 n/2 bits，所以實務上用**較有效率的 h_d**。

### 5.4 另一種修補：截斷輸出

只輸出 n 位元中的前 n − s 位元：

- **SHA-224** ≈ SHA-256 去掉 32 bits；**SHA-384** ≈ SHA-512 去掉 128 bits。
- 要 128-bit 安全：用 **SHA-512，截成 256 bits**——因生日攻擊，正好符合 128-bit 目標。

| 修補 | 公式 | 安全等級 | 代價 |
|---|---|---|---|
| h_dbl | h(h(m) ‖ m) | 可能 n | 慢 2 倍、無法串流 |
| **h_d** | h(h(0^b ‖ m)) | n/2 | 只多一次短雜湊 |
| 截斷 | SHA-512 前 256 bits | 128 | 幾乎無 |

## 6. 該選哪個雜湊？⭐

- **短期**：SHA-2 家族（SHA-224/256/384/512）；並且使用 **SHA_d 家族**，或 **SHA-512 截斷成 256 bits**。
- **長期**：很可能推薦 SHA-3 競賽的贏家。

> 後見之明：2012 年 **Keccak** 勝出，2015 年成為 SHA-3（FIPS 202），採用海綿結構，天生沒有長度擴展問題；NIST 同時也標準化了 **SHA-512/256**（截斷版），正是本章建議的做法。

## 7. 設計觀念整理

| 觀念 | 說明 |
|---|---|
| 理想黑盒子 | 雜湊必須像隨機映射，否則上層要逐一檢查交互作用 |
| 結尾處理很重要 | 迭代雜湊「最後沒做事」造成長度擴展 |
| 區分器自訂遊戲 | 只要能在某個情境下與理想函式區分，就是攻擊 |
| 弱點必修 | 寫進文件也沒人檢查；弱點交互作用會爆炸 |
| 安全等級對齊 | 256-bit 值 ↔ 128-bit 安全，都源自碰撞攻擊 |
| 攻擊只會變強 | MD5、SHA-1 一路從理論弱點走到實際碰撞 |

> 對照第一本書：Hanson 強調「介面的語意要完整描述、不留隱藏陷阱」。本章的長度擴展正是一個**沒寫在介面上的隱藏行為**——使用者以為拿到的是「隨機映射」，實際上拿到的是「會洩漏中間狀態的迭代機器」。

## 10. 本章重點整理

1. 密碼學雜湊 ≠ 雜湊表的 hash。
2. 要求：與**理想隨機映射**不可區分（定義 4、5）；泛用碰撞 2^(n/2)、原像 2^n。
3. 實際雜湊多為**迭代式**（Merkle–Damgård）：易實作、可串流。
4. **MD5、SHA-1 已破**；SHA-2 是當時的選擇。
5. 迭代結構的兩個弱點：**長度擴展**（h(X‖m) 認證會被附加資料）與**部分訊息碰撞**。
6. 修補：**SHA_d**（h(h(0^b ‖ m))，宣稱 n/2 bits）或 **SHA-512 截斷為 256 bits**。
7. 256-bit 雜湊 ↔ 128-bit 安全，與 256-bit 金鑰的道理一致。

> **一句話**：雜湊要能被當成隨機映射使用——但迭代式設計「結尾沒做事」，所以要用 SHA_d 或截斷輸出把長度擴展這個暗坑填起來。
