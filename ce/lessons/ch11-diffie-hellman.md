# 第 11 章　Diffie-Hellman

> 《Cryptography Engineering》— Ferguson, Schneier, Kohno，本章頁碼：p.181–193

---

## 1. 本章定位

到目前為止，加密和認證都用**共享秘密金鑰**。但這些金鑰從哪裡來？

**金鑰數量的平方爆炸**：

```
N 個人兩兩通訊需要 N(N − 1)/2 把金鑰
10 人 → 45 把        100 人 → 4950 把        200 人 → 19900 把
而且金鑰要定期更新 → 全部重來
```

**Diffie 與 Hellman（1976，*New Directions in Cryptography*）** 提出問題：若加密金鑰和解密金鑰不同，就可以**公開加密金鑰、保密解密金鑰**——任何人都能加密給你，只有你能解密。

他們只給出部分答案：**Diffie-Hellman 金鑰交換協定（DH）**——

> 兩個人在不安全的線路上對話，最後得到**同一把金鑰**，而竊聽者無法得知。

本章沿著歷史路徑：先 DH（本章），再 RSA（ch12）。

## 2. 群（Groups）⭐

p 為大質數（2000–4000 bits），計算都在 **Zp\***（模 p 乘法群）中進行。

### 2.1 階與生成元

取 g，看 1, g, g², g³, …（mod p）。群是有限的，所以序列一定會重複：若 g^i = g^j（i < j），兩邊除以 g^i 得 g^(j−i) = 1。

- **g 的階（order）**：使 g^q = 1 的最小正整數 q。
- g **生成**集合 {1, g, g², …, g^(q−1)}，恰有 q 個元素。
- 模 p 乘法中**至少有一個 g 生成整個群**（q = p − 1），稱為**原根（primitive element）**。
- 其他 g 生成較小的集合——它們本身也是群，即**子群**。子群在各種攻擊中非常重要。

### 2.2 階一定整除 p − 1

設 g 為原根，h = g^x。h 的階是使 g^(xq) = 1 的最小 q，即 xq ≡ 0 (mod p−1) 的最小 q：

```
q = (p − 1) / gcd(x, p − 1)        ⇒  q | (p − 1)
```

**例：p = 7**

| 元素 | 生成的集合 | 階 |
|---|---|---|
| 3（原根） | 1, 3, 2, 6, 4, 5 | 6 |
| 2 | 1, 2, 4 | 3 |
| 6 | 1, 6 | 2 |

子群大小 3、2 都整除 p − 1 = 6。

**順帶解釋 Fermat 測試**：a = g^x ⇒ a^(p−1) = g^(x(p−1)) = (g^(p−1))^x = 1^x = 1。

## 3. 基本 DH ⭐⭐

公開常數：大質數 p、原根 g（所有人包括攻擊者都知道）。

```
        Alice                                   Bob
        x ∈R Zp*
                      ───── g^x ─────►
                                                y ∈R Zp*
                      ◄──── g^y ──────
        k ← (g^y)^x                             k ← (g^x)^y

        雙方得到 k = g^(xy)
```

- 攻擊者看得到 g^x 與 g^y，但看不到 x、y。
- **DH 問題**：已知 g^x、g^y，求 g^(xy)。只要 p、g 選得正確，沒有已知的有效演算法。
- 已知最好的方法：先從 g^x 求出 x，再算 (g^y)^x。
- 在實數中，從 g^x 求 x 叫**對數**；在有限群中叫**離散對數**——**DL 問題**。

**另一種用法：數位電話簿** ——每個人選隨機 x、公布 g^x。Alice 想和 Bob 通訊，就從電話簿查 g^y，用自己的 x 算 g^(xy)；Bob 也能**不經互動**算出同一把金鑰——適用於 e-mail 這類非互動情境。

## 4. 中間人攻擊（Man-in-the-Middle）⭐⭐

DH 唯一不防的就是**中間人攻擊**（注意：和 §2.7.2 的 *meet-in-the-middle* 攻擊不同）。

Alice 知道她在跟**某人**通訊，但不知道是**誰**：

```
   Alice                     Eve                        Bob
   x ∈R Zp*
             ── g^x ──►
                             v ∈R Zp*
                                        ── g^v ──►
                                                         y ∈R Zp*
                                        ◄── g^y ──
                             w ∈R Zp*
             ◄── g^w ──
   k ← (g^w)^x               k  ← (g^x)^w
                             k' ← (g^y)^v               k' ← (g^v)^y
```

- 對 Alice 而言，這看起來和原始 DH 一模一樣；Bob 也是。
- 之後 Eve 只要轉送所有通訊：用 k 解密 Alice 的資料、用 k' 重新加密給 Bob，反方向亦然——工作量不大，想維持多久都行。

**對策**：

| 方法 | 說明 | 限制 |
|---|---|---|
| 電話簿出版者驗證身分 | 只要出版者在收到 g^x 時驗證身分，Alice 就確定用的是 Bob 的值 | 需要可信的出版者 → 數位簽章與 PKI（ch12、ch18–20） |
| **語音比對雜湊** | 用 k 加密電話/視訊時，Bob 念出 h(k) 的前幾位，Alice 確認一致；再由 Alice 念接下來幾位給 Bob | 只在能把「知道 k」和「對面那個人」綁在一起時有效；Eve 若做出能模仿 Bob 的語音合成器就破功；**最大的問題是需要使用者的紀律**，而使用者經常忽略安全程序 |

> 一般而言，**技術機制**遠比依賴使用者紀律好。
>
> 後見之明：Signal 的「安全碼（safety number）」、ZRTP 的 SAS（Short Authentication String）就是語音比對法的現代版本。

## 5. 陷阱 ⭐⭐

### 5.1 把 g^x 換成 1

Eve 把 g^x 和 g^y 都換成 1 → 雙方都得到 k = 1。協定看起來成功完成，**但 Eve 知道金鑰**。

### 5.2 g 只生成小子群

若 g 不是原根、只生成階為一百萬的子群，k 只有一百萬種可能，Eve 輕易窮舉。

→ g 必須有**高階**。但 p 和 g 是誰選的？所有使用者共用，大多從別人那裡拿到——所以**Alice 和 Bob 都應該檢查 p 是質數、g 是原根**。

### 5.3 小子群攻擊

Eve 把 g^x 換成某個**小階元素 h**，Bob 算出的金鑰就落在 h 生成的小集合中，Eve 可以全部試過（對 Alice 也一樣）。

→ 雙方都必須**驗證收到的數不會生成小子群**。

子群的結構：

- 模質數時，所有乘法子群都由單一元素生成；
- 子群大小一定整除 p − 1；**反之，p − 1 的每個因數 d 恰好對應一個大小為 d 的子群**；
- 要避免小子群，就要避免 p − 1 有小因數。

**另一個理由**：若已知 p − 1 的質因數分解，離散對數可以**拆成各子群上的離散對數**分別計算（Pohlig-Hellman）。

但 p 是大質數 → p − 1 一定是偶數 → 一定有大小為 2 的子群 {1, p − 1}。除此之外，可以要求 p − 1 沒有其他小因數。

## 6. 安全質數（Safe Primes）

**安全質數**：p = 2q + 1，且 q 也是質數。Zp\* 的子群只有：

| 子群 | 大小 |
|---|---|
| {1} | 1 |
| {1, p − 1} | 2 |
| **平方數構成的子群** | **q** |
| 整個群 | 2q |

前兩個很容易避開。為什麼不用整個群？

**Legendre 符號洩漏一個位元** ⭐：

- 1 … p−1 中恰好一半是**平方數**（二次剩餘），一半不是。
- 整個群的生成元一定**不是**平方數（若是，它的冪次永遠是平方數，生成不了非平方數）。
- **Legendre 符號**能有效判斷一個數是否為平方數，不需要求平方根。
- g 非平方數時，g^x 是平方數 ⟺ x 是偶數 → Eve 看到 g^x 就知道 **x 的最低位元**。

→ 只使用**平方數**，也就是大小為 q 的子群。q 是質數，所以沒有更小的子群要擔心。

**使用方法**：

```
選 (p, q)：p = 2q + 1，兩者皆質數（用 isPrime 試誤）
選隨機 α ∈ 2 … p − 2，令 g = α² mod p
檢查 g ≠ 1 且 g ≠ p − 1（否則換 α）

每收到一個應為 g 的冪次的值 r，檢查：
    r ≠ 1  ∧  r^q mod p = 1          （r 是平方數 ⟺ r^q = 1）
```

---

## 7. 使用較小的子群 ⭐

安全質數的缺點：**慢**。p 有 n bits → q 有 n − 1 bits → 指數都是 n − 1 bits，平均每次冪次約 3n/2 次模乘法。

**標準解法**：

```
選 q 為 256-bit 質數（2^255 < q < 2^256）
選隨機偶數 N，令 p = N·q + 1，直到 p 是質數（p 有數千位元）
選隨機 α ∈ Zp*，令 g = α^N
檢查 g ≠ 1 且 g^q = 1（q 為奇數，所以 g = p−1 的情況已被第二條排除）

每收到一個應屬於子群的 r，檢查：
    1 < r < p  ∧  r^q = 1
```

- 子群中所有 r 都滿足 r^q = 1 → 計算 r^e 時只需算 r^(e mod q)。
- **效率比較**（p 為 2000 bits）：

| 方式 | 指數長度 | 每次 g^x 約需模乘法 |
|---|---|---|
| 安全質數 | ~2000 bits | ~3000 次 |
| 256-bit 子群 | 256 bits | ~384 次 |

將近 **8 倍**，p 越大差距越大——這就是子群被廣泛使用的原因。

## 8. p 該多大？⭐

- 若堅持攻擊者需 2^128 步，p 約需 **6800 bits**——以今天的效能來說是個大問題。
- 公鑰運算比對稱運算昂貴得多，而且成本隨安全等級成長得快很多。

> **永遠、永遠不要拿對稱金鑰長度（128、256 bits）和公鑰長度（數千 bits）直接比較。** 公鑰總是大得多。（橢圓曲線等其他方案的參數又完全不同。）

**對稱 vs. 公鑰的生命週期差異**：

| | 對稱金鑰 | 公鑰 |
|---|---|---|
| 長度 | 系統設計時固定，伴隨系統一生 | 幾乎總是**可變**的，容易調整 |
| 需要保護多久 | 系統壽命 30 年 + 資料保密 20 年 = **50 年** | 金鑰有效期（例如 1 年）+ 20 年 ≈ **21 年** |
| 調整方式 | 難 | 每年產生新公鑰，可隨技術進步加大 |

**Lenstra 的估計**：

| p 的長度 | 預估安全到 |
|---|---|
| 2048 bits | 約 2022 年 |
| 3072 bits | 約 2038 年 |
| 4096 bits | 約 2050 年 |
| 6800 bits | 2^128 步 |

> 對這類預測要非常小心。預測未來 10 年還算合理，預測 50 年後相當荒謬——比較一下今天和 50 年前的電腦與密碼學就知道了。

**作者的建議**：

1. **2048 bits 為絕對最低**（而且這個下限會隨時間增加）；
2. 效能允許時用 **4096 bits**，或盡量接近；
3. **系統一定要能處理到 8192 bits**——若密碼分析突然進步，可以在部署中直接換成大得多的金鑰：損失一些效能，但系統基本運作得以保留，遠勝過失去所有安全、必須重新設計。
4. 資料需要保密遠超過 20 年 → 現在就用更大的金鑰。

> 對照：§3.5.7 要求對稱元件留「可替換」的彈性；這裡對公鑰要求「可放大」的彈性——同樣是為不可預期的密碼分析進展預留退路。

## 9. 實用規則 ⭐⭐⭐

**建立子群**：

- q 為 **256-bit** 質數（DH 的指數有碰撞式攻擊，指數要 256 bits 才能逼攻擊者做 2^128 次運算）。
- p = Nq + 1 為大質數（大小見 §8）。
- g = α^N，確認 g ≠ 1 且 g^q = 1。

**收到 (p, q, g) 的一方必須驗證**：

1. p、q 都是質數；q 為 256 bits；p 夠大（**不要信任太小的金鑰**）；
2. q | (p − 1)；
3. g ≠ 1 且 g^q = 1。

> **即使參數來自可信來源也要檢查。** 你會很驚訝系統出錯的方式有多有趣，尤其是在遭受攻擊時。同一組參數通常會用很久，這些檢查只需做一次（但每次重開機或重新初始化後要重做，因為參數可能變了）。

**每收到一個應屬於子群的 r**：檢查 **1 < r < p 且 r^q = 1**（r = 1 不被允許）。

**子群中的 DH**：

```
  Alice                                             Bob
  known: (p, q, g)                                  known: (p, q, g)
  check(p, q, g)                                    check(p, q, g)
  x ∈R 1, …, q − 1
                     ──── X := g^x ────►
                                                    1 <? X <? p,  X^q =? 1
                                                    y ∈R 1, …, q − 1
                     ◄─── Y := g^y ─────
  1 <? Y <? p,  Y^q =? 1
  k ← Y^x                                           k ← X^y
```

- 「=?」「<?」表示**必須檢查**這個關係；不成立就**假設正在遭受攻擊**：停止協定、不再送出任何訊息、**銷毀所有協定相關資料**（例如 Alice 要銷毀 x 與 Y）。詳見 §13.5.5。
- 這個版本是安全的，但**不應直接這樣使用**：結果 k 必須先經過**雜湊**才能交給系統其他部分（§14.6）。

## 10. 會出什麼錯？——IKE 的真實案例 ⭐⭐

很少有書或文章談到「檢查收到的數在正確子群中」的重要性。Niels 最早是在 IPsec 的 **IKE（Internet Key Exchange）** 中發現這個問題。

**情境**：

- IKE 要處理訊息遺失：Bob 沒收到回應就**重送**上一則訊息；但 IKE 沒規定 Alice 該怎麼處理重送的訊息。
- 假設 Alice 不檢查 X、Y，交換後立刻用 k 加密並認證一則訊息給 Bob。
- **危險的行為**：Alice 收到重送的 Y 時，就**重新計算 k** 並送出回覆。聽起來完全無害，對吧？

**Eve 的攻擊**：

```
設 d 為 p − 1 的小因數
1. Eve 把 Y 換成 d 階元素 h（「重送」給 Alice）
2. Alice 算出 k = h^x —— 只有 d 種可能，由 h 和 (x mod d) 決定
3. Alice 用 k 加密下一則訊息
4. Eve 窮舉 x mod d 的 d 種值，看哪一個能正確解密 → 學到 (x mod d)
5. 對 p − 1 的每個小因數 d1, d2, …, dk 重複
6. 用中國剩餘定理（§12.2）合併 → 得到 x mod (d1·d2·…·dk)
7. 最後把原本的 Y 轉給 Alice，讓協定正常完成
   ——但 Eve 已掌握足夠的 x 資訊，可以求出 k
```

- 攻擊者能做 2^128 步 → 可利用 p − 1 所有小於約 2^128 的因數；粗估平均能得到約 **128 bits** 的 x 資訊，剩下的部分再用碰撞式攻擊——x 只有 256 bits，這就是真實的攻擊。
- **這不是對 IKE 的攻擊，而是對「標準所允許的」某種 IKE 實作的攻擊。** 但作者認為：協定應該包含足夠資訊讓稱職的程式設計師寫出安全實作；遺漏這類資訊很危險——**總會有人在某處用錯誤的方式實作**。

**如果參數是 Eve 選的呢？**

- 她可以在挑 p 時**故意**放入小因數；或者她坐在推薦標準參數的委員會裡。
- 這並不荒唐：美國政府（NIST）提供 DSA 用的質數；同一政府的其他部門（NSA、CIA、FBI）有破解私人通訊的既得利益。作者並非暗示這些質數有問題，但**用之前應該檢查**——NIST 也公開了不會插入額外小因數的參數產生演算法，可以驗證是否照做。但很少人真的去做。

**結論**：

> **最簡單的解法，就是檢查收到的每一個值都在正確的子群中。** 其他防小子群攻擊的方法都複雜得多——直接偵測 p − 1 的小因數太複雜；要求參數產生者提供 p − 1 的分解，會大幅增加整個系統的複雜度。驗證收到的值雖然要花點功夫，卻是**最簡單、最穩健**的方案。

> 後見之明：2015 年的 **Logjam** 攻擊顯示大量伺服器使用相同的 512/1024-bit DH 參數，可被預先計算後即時破解；2016 年研究也發現許多實作不做子群檢查——本章的警告一一應驗。

## 11. 參考實作（Python）

依 §11.8 的規則寫成（`is_prime`、`generate_large_prime` 來自第 10 章的參考實作）。示範：產生 1024-bit 群並完成 DH、拒絕不在子群中的元素，以及用玩具參數重現 §10 的**小子群攻擊**——Eve 在 Alice 不做檢查時學到 x mod 30030。

```python
import secrets
from primes import is_prime, generate_large_prime

def generate_group(pbits: int):
    """§11.8：q 為 256-bit 質數，p = N·q + 1，g = α^N 為 q 階元素"""
    q = generate_large_prime(2**255 + 1, 2**256 - 1)
    while True:
        N = secrets.randbits(pbits - 256) | (1 << (pbits - 257))  # 讓 p 約 pbits 位元
        N -= N % 2                                                 # p 為奇數 ⇒ N 為偶數
        p = N * q + 1
        if p.bit_length() == pbits and is_prime(p):
            break
    while True:
        alpha = 2 + secrets.randbelow(p - 3)
        g = pow(alpha, N, p)
        if g != 1 and pow(g, q, p) == 1:
            return p, q, g

def check_group(p, q, g, min_pbits=2048):
    """收到 (p, q, g) 時的檢查——即使來源可信也要做"""
    assert is_prime(p) and is_prime(q)
    assert q.bit_length() == 256 and p.bit_length() >= min_pbits
    assert (p - 1) % q == 0
    assert g != 1 and pow(g, q, p) == 1

def check_element(r, p, q):
    """每個收到的群元素：1 < r < p 且 r^q = 1"""
    if not (1 < r < p and pow(r, q, p) == 1):
        raise ValueError("not in subgroup — abort, wipe x")

def dh_demo(p, q, g):
    x = 1 + secrets.randbelow(q - 1); X = pow(g, x, p)     # Alice
    y = 1 + secrets.randbelow(q - 1); Y = pow(g, y, p)     # Bob
    check_element(X, p, q); check_element(Y, p, q)
    kA, kB = pow(Y, x, p), pow(X, y, p)
    assert kA == kB
    return kA

def small_subgroup_attack_demo():
    """玩具參數：p−1 有小因數 d；Alice 不檢查 Y，Eve 就能學到 x mod d"""
    p = 2 * 3 * 5 * 7 * 11 * 13 * 1031 + 1           # = 30030·1031 + 1 = 30960931
    assert is_prime(p)
    x = secrets.randbelow(p - 1)                      # Alice 的秘密
    learned = {}
    for d in (2, 3, 5, 7, 11, 13):
        h = next(pow(a, (p - 1) // d, p) for a in range(2, p) if pow(a, (p - 1) // d, p) != 1)  # d 階元素
        k_alice = pow(h, x, p)                         # Alice 用被換掉的 Y = h 算出 k
        learned[d] = next(i for i in range(d) if pow(h, i, p) == k_alice)  # Eve 窮舉 d 種可能
    # 中國剩餘定理合併
    M = 2 * 3 * 5 * 7 * 11 * 13
    r = sum(v * (M // d) * pow(M // d, -1, d) for d, v in learned.items()) % M
    return x % M, r

if __name__ == "__main__":
    p, q, g = generate_group(1024)                    # 示範用；實務 ≥ 2048
    check_group(p, q, g, min_pbits=1024)
    print("p bits:", p.bit_length(), " q bits:", q.bit_length())
    print("shared k ok:", hex(dh_demo(p, q, g))[:20], "…")
    try:
        check_element(p - 1, p, q)
    except ValueError as e:
        print("Y = p−1 rejected:", e)
    print("x mod 30030 (truth, Eve's):", small_subgroup_attack_demo())
```

實測輸出：

```
p bits: 1024  q bits: 256
shared k ok: 0x3fa7564e8f40ddd7d5 …
Y = p−1 rejected: not in subgroup — abort, wipe x
x mod 30030 (truth, Eve's): (14765, 14765)
```

> 玩具參數 p = 30030·1031 + 1 = 30960931，p − 1 含有小因數 2、3、5、7、11、13；Eve 對每個因數只需試 d 次，再用中國剩餘定理合併。真實攻擊的規模更大，但原理完全相同。

## 12. 設計觀念整理

| 觀念 | 說明 |
|---|---|
| 金鑰數平方成長 | 對稱金鑰無法擴展到大群體 → 公鑰 |
| DH 只防竊聽 | 不認證身分，擋不住中間人 |
| 技術機制勝過使用者紀律 | 語音比對雜湊可行但脆弱 |
| 子群決定安全 | 小子群讓金鑰空間縮小、洩漏指數資訊 |
| 只用質數階子群 | 安全質數取平方數子群；或 256-bit q 的子群 |
| 驗證一切 | 參數 (p, q, g) 與每個收到的元素都要檢查，來源可信也一樣 |
| 失敗就停 | 檢查失敗：停止、不再送訊息、銷毀資料 |
| 公鑰長度可放大 | 現在 ≥ 2048、盡量 4096、系統支援到 8192 |
| 結果要雜湊 | k 不可直接當金鑰 |
| 標準要寫清楚 | 允許不安全實作的標準，必然有人寫出不安全的實作 |

> 對照第一本書：Hanson 的「checked runtime error」概念正是本章「每個收到的值都要檢查」的同類——**介面入口處的檢查**把錯誤擋在最外層，不讓它深入系統。不同的是，這裡的錯誤輸入來自**攻擊者**，檢查失敗的處置也更嚴格（銷毀狀態、靜默中止）。

## 15. 本章重點整理

1. 對稱金鑰數量隨人數平方成長 → Diffie-Hellman（1976）讓雙方在不安全線路上協商共享金鑰。
2. 元素的**階**整除 p − 1；每個因數對應唯一一個子群。
3. DH 的安全依賴 **DH 問題 / 離散對數問題**。
4. DH **不防中間人**——需要簽章、PKI 或其他認證機制。
5. 陷阱：替換成 1、小階生成元、**小子群攻擊**、Legendre 符號洩漏最低位元。
6. 解法：使用**質數階 q 的子群**（q 為 256 bits，p = Nq + 1）；**驗證參數**與**每個收到的元素**（1 < r < p 且 r^q = 1）；檢查失敗立即中止並銷毀資料。
7. p 至少 2048 bits、盡量 4096、系統要支援 8192；DH 結果 k 必須先雜湊。

> **一句話**：DH 讓兩個陌生人在大庭廣眾下協商出秘密，但它不知道對面是誰——而且每一個收到的數字都必須檢查是否落在正確的子群裡。
