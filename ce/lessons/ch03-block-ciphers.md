# 第 3 章　區塊加密（Block Ciphers）

> 《Cryptography Engineering》— Ferguson, Schneier, Kohno，本章頁碼：p.43–62

---

## 1. 本章定位

第 2 章介紹了「加密」這個抽象功能；本章開始進入第二部「訊息安全」，從最底層的積木——**區塊加密器（block cipher）**——談起。後面的加密模式（ch4）、雜湊（ch5，Davies–Meyer 結構）、MAC（ch6，CBC-MAC/CMAC）、安全通道（ch7）全都建立在它之上。

本章要回答三個問題：

1. 區塊加密器「是什麼」——一個以金鑰為索引的**置換（permutation）**。
2. 區塊加密器「怎樣才算安全」——與**理想區塊加密器**不可區分。
3. 實務上「該用哪一個」——AES，搭配 256-bit 金鑰。

> 對照第一本書：Hanson 強調「介面要簡單、實作可替換」；本章對區塊加密器的安全定義，其實就是在替它訂一份**乾淨的介面合約**——只要符合定義，上層就可以把它當成理想元件，不必知道內部細節。

---

## 2. 什麼是區塊加密器 ⭐

區塊加密器把**固定長度**的明文區塊加密成同樣長度的密文區塊：

```
c = E(K, p)        加密
p = D(K, c)        解密
```

| 參數 | 現代常見值 |
|---|---|
| 區塊大小 | 128 bits（DES/3DES 為 64 bits） |
| 金鑰大小 | 128 或 256 bits |

**重要提醒**：區塊加密器本身只處理一個區塊；**絕對不要直接拿它加密資料**，而要搭配「區塊加密模式」（第 4 章）。

### 2.1 把區塊加密器看成一張巨大的表

對固定金鑰 K，E(K, ·) 就是一張「輸入 → 輸出」查表；這張表必須是**置換**（一對一），否則無法解密。

| 區塊大小 | 一把金鑰的表大小 |
|---|---|
| 32 bits | 2^32 項 × 4 bytes = 16 GB |
| 64 bits | 約 1.5 億 TB |
| 128 bits | 約 5·10^39 bytes |

所以區塊加密器是一種「用小小的金鑰，**模擬**出一張天文數字大小隨機置換表」的演算法。

> ⚠️ 置換的是 **2^n 個可能的輸入值**，不是把位元重新排列。

## 3. 攻擊的種類

回顧第 2 章的攻擊模型，在區塊加密器上：

- **唯密文 / 已知明文 / 選擇明文 / 選擇密文**：已發表的攻擊大多是**選擇明文攻擊**。
- **相關金鑰攻擊（related-key attack）** ⭐（Biham, 1993）：攻擊者可以拿到在「彼此有已知關係的多把金鑰」下的加密。
  - 聽起來不切實際？書中舉例：有真實系統每則訊息把金鑰 **+1**；也有標準同時使用 K 與 K ⊕ 常數。
- **選擇金鑰攻擊（chosen-key attack）**：攻擊者連金鑰都能選一部分。最初是作者在分析 Twofish 時提出，後來證明對 Twofish 並無效。
  - 何時會出現？例如用區塊加密器建雜湊函式（**Davies–Meyer**，第 5 章），訊息就被當作金鑰——攻擊者自然能選金鑰。

**設計哲學**：與其要求使用者小心翼翼地避免這些情境，不如**讓區塊加密器的介面簡單、能力過剩（over-engineered）**，任何使用方式都安全。

---

## 4. 理想區塊加密器

**理想區塊加密器**：對每一把金鑰，都是一個**彼此獨立、均勻隨機選出**的置換。

- 嚴格說，它是「所有可能加密器構成的集合上的均勻分佈」。
- 它無法實作（表太大），只是一個**抽象的比較基準**。

---

## 5. 安全的定義 ⭐⭐

### 5.1 定義演進

| 版本 | 內容 |
|---|---|
| **定義 1** | 安全的區塊加密器，就是**沒有攻擊**的區塊加密器。 |
| **定義 2** | **攻擊** = 一個能把該區塊加密器與理想區塊加密器**區分開來的非泛用（non-generic）方法**。 |
| **定義 3** | 同定義 2，但理想區塊加密器改成「隨機**偶置換**」（見 5.4）。 |

**區分器（distinguisher）** 的遊戲規則：

```
  區分器 ──► 黑盒子：E 或 D（可自選金鑰）
              │
              └─ 內部是「真實加密器 X」或「理想加密器」？
  區分器輸出猜測；猜對機率顯著 > 1/2 ⇒ 成功
```

### 5.2 泛用 vs. 非泛用

**泛用攻擊**對任何區塊加密器都有效（例如窮舉金鑰），不算數。哪些算「非泛用」？作者坦言：

> 就像美國大法官 Potter Stewart 對色情的名言——**「看到就知道」**（*I know it when I see it*）。

書中例子：

1. 用金鑰 0 加密明文 0，若結果有特殊值 → 非泛用。
2. 對 2^32 把金鑰做統計，發現偏差 → 非泛用。
3. 準備 1000 種統計方法，挑效果最好的那種 → 要小心，這可能只是「多重比較」的運氣。

### 5.3 成本門檻

區分器的成本必須**低於同等安全等級的窮舉搜尋**。
注意要拿來比較的是**部分金鑰搜尋**：

- 只搜尋一半金鑰空間：工作量 2^(n−1)，成功率 75%（猜中 50% + 猜不中時亂猜對 25%）。

### 5.4 為何要這麼嚴格？

因為它給了一個**乾淨、模組化的介面**：

> 只要區塊加密器符合定義，設計上層系統時就**可以把它當成理想加密器**，不必考慮各種奇怪交互作用。

這正是「正確性必須是局部性質」（第 2 章）的體現。

### 5.5 奇偶性（Parity）的插曲 ⭐

- 置換可以分成**偶置換**與**奇置換**（可由偶數 / 奇數次對調組成）。
- 由 32-bit 基本運算（xor、加法、查表…）組成的加密器，**只會產生偶置換**。
- 理想加密器（任意置換）有一半是奇置換 → 判斷奇偶就能區分，成功率 75%。
- 但這個攻擊需要**幾乎全部**的明文/密文對，完全不實際，也不構成實際威脅。

結論：修正定義，把理想加密器限制為**隨機偶置換**（定義 3）。

> **方法論教訓**：先考慮一個「攻擊的超集合」，再把確定無害的剔除；而不是只列出想得到的攻擊。

## 6. 真實的區塊加密器

- 區塊加密器**很容易設計，但要設計得好極其困難**。
- **不要使用沒聽過、沒被公開分析過的加密器。**
- 幾乎所有加密器都由「**許多輪（round）較弱的函式重複疊加**」構成；攻擊通常先從**減少輪數的版本**下手，觀察安全餘裕。

### 6.1 DES ⭐

| 項目 | 值 |
|---|---|
| 金鑰 | 56 bits |
| 區塊 | 64 bits |
| 結構 | Feistel，16 輪 |
| 輪金鑰 | 48 bits（由 key schedule 產生） |

**Feistel 結構**：

```
   L_i            R_i
    │              │
    │      ┌───────┤
    │      ▼       │
    ⊕◄──── F(K_i) ─┘
    │              │
    └─────┐  ┌─────┘
          ╳            （左右交換）
    ┌─────┘  └─────┐
  L_{i+1}       R_{i+1}
```

F 函式內部：

1. **擴展**：32 → 48 bits
2. **xor** 輪金鑰
3. **8 個 S-box**：每個 6 → 4 bits
4. **位元重排（shuffle）**

| 元件 | 角色 |
|---|---|
| xor 輪金鑰 | 把金鑰混入資料 |
| S-box | 提供**非線性** |
| 擴展 + 重排 + S-box | 提供**擴散（diffusion）** |

**Feistel 的優點**：解密 = 用**反向順序的輪金鑰**再做一次加密，F 本身不必可逆。

**DES 的缺陷（依本章定義，DES 不合格）**：

- **4 把弱金鑰**：例如金鑰全 0 時，加密 = 解密。
- **互補性質**：`E(~K, ~P) = ~E(K, P)`——把金鑰與明文都取反，密文也取反。
- **金鑰太短**：56 bits 已被實際窮舉破解。

**3DES**：`C = E(K3, D(K2, E(K1, P)))`（加密-解密-加密，EDE）

- 速度只有 DES 的 1/3。
- **繼承**了弱金鑰、互補性質與 64-bit 區塊。
- 新設計不建議使用。

### 6.2 AES（Rijndael）⭐⭐

- NIST 公開競賽：15 個提案 → 5 個決選 → 2001 年成為標準。
- **不是** Feistel 結構（SPN 型）。

一輪的結構：

```
  16 bytes 狀態
     │
     ▼  xor 輪金鑰
     ▼  16 個 8-bit S-box（每個 byte 各自代換）
     ▼  byte 重排（ShiftRows）
     ▼  以 4 bytes 為一組做線性混合（MixColumns）
```

| 金鑰長度 | 輪數 |
|---|---|
| 128 | 10 |
| 192 | 12 |
| 256 | 14 |

- 優點：運算可大量平行，速度快。
- 缺點：解密與加密的運算不同，要分別實作。

**安全餘裕偏低（作者的擔憂）**：

- 設計者自己就有 6 輪攻擊；選拔期間就已出現 7 / 8 / 9 輪攻擊（128-bit 版約被攻破 70% 的輪數）。
- 近年的**相關金鑰攻擊**：
  - 192-bit AES 全輪：4 把相關金鑰、2^176 運算
  - 256-bit AES 全輪：2^119 運算
  - 256-bit AES 10/14 輪：2 把相關金鑰、2^45 運算
- 依本章定義，AES 在理論上已「被攻破」（弱點在 key schedule）；**128-bit AES 目前沒有已知攻擊**。

結論：AES 作為標準仍是合理選擇，但**系統設計要保留更換加密器的彈性**。

### 6.3 其他 AES 決選者

| 加密器 | 特色 | 輪數 / 最佳攻擊 | 速度 |
|---|---|---|---|
| **Serpent** | 「像坦克一樣堅固」；4-bit S-box，用 bitslice 實作 | 32 輪 / 攻到 12 輪 | 約 AES 的 1/3 |
| **Twofish**（作者參與） | Feistel；g 函式含**金鑰相依 S-box** + MDS 矩陣；PHT；whitening | 16 輪 / 攻到 8 輪 | 快，但換金鑰成本高 |
| **RC6** | 使用 32-bit 乘法 | 20 輪 / 攻到 17 輪 | 依平台而異 |
| **MARS** | 非均勻結構（不同輪不同設計） | — | 複雜 |

### 6.4 該選哪一個？⭐

> **「沒有人會因為選了 AES 而被開除。」**

1. **預設用 AES**。
2. **3DES** 只在相容舊系統，或被綁死在 64-bit 區塊時才用。
3. 若對 AES 不放心：
   - **雙重加密**：先 AES、再 Serpent 或 Twofish，**兩把獨立金鑰**；或
   - **增加輪數**：AES-128/192/256 分別用 16 / 20 / 28 輪。
4. 跟隨 NIST 或密碼學社群的共識。
5. 實作要注意**時序側通道**——使用常數時間（constant-time）實作，避免查表時間洩漏金鑰。

### 6.5 金鑰大小 ⭐

- 要達到 **n bits 安全**，系統中所有值都應該至少 **2n bits**——因為**碰撞攻擊**（生日攻擊）只需 2^(n/2)。
- 因此 **128-bit 區塊大小是一個真實限制**（第 4 章會看到 CBC/CTR 的資訊洩漏）。
- 建議：**使用 256-bit 金鑰**，設計強度定為 **128 bits**（系統其他部分以 128 bits 為準）。
- 本書全書都使用 **AES-256**，儘管它的 key schedule 有前述相關金鑰攻擊結果。

## 7. 設計觀念整理

| 觀念 | 說明 |
|---|---|
| 理想元件 + 嚴格定義 | 定義越嚴，上層越能把它當黑盒子使用 |
| 先列超集合再剔除 | 安全分析不能只列「想得到的攻擊」 |
| 能力過剩的元件 | 介面簡單、不要求使用者遵守隱性規則 |
| 安全餘裕 | 看「最佳攻擊能打到幾輪」 vs. 總輪數 |
| 可替換性 | 標準可能被攻破，系統要留後路 |
| 2n 原則 | 要 n-bit 安全，數值至少 2n bits |

## 10. 本章重點整理

1. 區塊加密器 = 以金鑰為索引的**置換**；不可直接使用，要搭配模式。
2. 安全定義：與**理想（偶置換）加密器**不可用非泛用方法區分，且成本低於窮舉。
3. 嚴格的定義帶來**模組化**：上層可以假設它是理想的。
4. DES 有弱金鑰、互補性質、金鑰過短；3DES 只是延命。
5. AES 是標準，但安全餘裕不大、key schedule 有理論攻擊——要保留替換彈性。
6. 預設 **AES-256**，設計強度 128 bits；注意常數時間實作。

> **一句話**：區塊加密器是一張用金鑰模擬的巨大隨機置換表——選 AES-256、別直接用它，並且永遠留一條換掉它的後路。
