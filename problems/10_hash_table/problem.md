# 10. 自己做一個雜湊表 (Hash Table)

> 主題：雜湊表　難度：★★☆　時間限制：2 秒　相關教學：`lessons/06_hash_table.md`

## 題目

請 **不要使用 `std::map` / `std::unordered_map` / `std::set`**，
自己實作一個 key、value 都是 `long long` 的雜湊表（建議用 separate chaining：每個桶子是一條串列 / vector）。

| 指令 | 說明 | 輸出 |
|---|---|---|
| `put k v` | 設定 `key = k` 的值為 `v`（已存在就覆蓋） | 無 |
| `get k` | 查詢 | 值；不存在輸出 `not found` |
| `erase k` | 刪除 | 成功 `ok`；不存在 `not found` |
| `size` | 目前有幾個 key | 整數 |

## 輸入

第一行 `Q`，接下來 `Q` 行指令。

## 輸出

依照上表。

## 限制

- `1 ≤ Q ≤ 2×10^5`
- `-10^18 ≤ k, v ≤ 10^18`（**key 可能是負數**）

## 範例

輸入
```
8
put 5 100
put -3 7
get 5
put 5 1
get 5
erase 4
erase -3
size
```
輸出
```
100
1
not found
ok
1
```

## 測資裡藏了什麼陷阱？

- C++ 的 `%` 對負數會得到 **負數**：`-3 % 10 == -3`。直接拿去當陣列索引會越界！
- 有些測資的 key 全都是 `2^20` 的倍數，或是某個常見質數的倍數。如果你的雜湊函數只是 `k % 1024`，
  所有 key 都會擠在同一個桶子裡，雜湊表退化成串列 → **TLE**。
  想想看：桶子數量選什麼好？要不要把 key 先「打亂」（例如乘上一個大奇數、做 xor-shift）？
- `put` 已經存在的 key 時，`size` 不能增加。
